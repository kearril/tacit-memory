# TacitMemory 决策记录

本文档记录当前有效的设计决定：定了什么、为什么这样选、没选什么。决定被推翻时就地改写，不保留取代链。系统具体行为见 [`design.md`](design.md)。

## 记忆组织

### 文件是唯一真相源

- **决定**：所有记忆都是 Markdown 文件，放在独立的 Git 仓库里。检索索引只是派生缓存，可随时删除重建；换嵌入模型、换索引引擎或改表结构时一律重建，不做迁移。
- **理由**：用户必须能直接读、直接改自己的记忆，并用 Git 追溯历史，记忆系统不能是黑盒。
- **没选**：以数据库为主存储、文件只作导出（如 Mem0、Hindsight）——用户无法直接编辑，历史锁在数据库里。

### 按生命周期组织：捕获、整理、供给

- **决定**：记忆工作流分为三段，每段有唯一负责方。捕获：主会话在对话中写入活动、细节页与画像候选。整理：用户触发 `tacit-consolidate`，主会话依据服务备料写入汇总、重写主线近况并起草提案。供给：服务按确定性规则将记忆交给主会话（常驻区块、服务端说明、`recall`）。
- **理由**：写入求快，整理求准；对话中允许粗糙写入，质量由整理兜底。
- **没选**：按内容类型分层且每层各自决定注入方式——类型与进入上下文的时机耦合，容易产生边界问题。

### 主线是唯一的聚合单位

- **决定**：主线（`workstream`）指「一件持续进行、由多个会话围绕它聚合而成的事务」，不分类型，不要求关联代码仓库。每条主线包含背景说明（基本不变）与近期摘要（仅在整理时更新）。主线仅在整理阶段经用户确认后成立：提示词要求写入时只用已成立的主线名，无法匹配时细节页放进专题（slug 以事项名开头），活动不标注主线；整理阶段将同前缀专题页提议为新主线。服务不拦截未成立的新名称，但不放入常驻区块。一条活动只属于一条主线。
- **理由**：服务器运维这类没有代码仓库的长期事务，在「项目」模型下只能散落在专题中，而细分类型只会导致类别膨胀。由于主线进入每个会话的常驻区块，模型临时构造的名称不应直接占据该位置；服务端硬拦截又会打断记录，因此仅在提示词层约束。
- **没选**：项目加「近期主线」两个概念（容易演变为流水账）；英文用 `mainline`（在代码语境中易与主干分支混淆）；允许细节页用未成立主线名建目录再靠整理合并（分叉率高）。

### 画像分作用域，以会话内即时确认晋升

- **决定**：画像条目分为三种作用域：全局（进入常驻区块）、`workstream:<名>`（进入主线简报）、`domain:<标签>`（常驻区块只放一行索引，正文按需读取）。一条规则至少在两类不同情境下成立才归入全局。晋升有两个入口：用户纠正 Agent 或明确提出协作做法时，Agent 问一次是否记为长期规则，同意后直接写入；其余观察记为候选，在整理时归纳成提案一次批量确认。
- **理由**：约半数候选仅在特定情境下成立，全部常驻会带来上下文噪声。依赖「出现天数」自动晋升在实践中容易失效——Agent 遵循度提高后，用户不再重复纠偏，候选反而达不到天数门槛。
- **没选**：为每个领域生成独立 skill（链接管理复杂，触发可靠性并不更高）。

### 机器身份与写明适用条件，而非按机器或客户端分片

- **决定**：每台机器在 `config.yaml` 中有名称与可选说明（缺省由主机名规整而来），常驻区块开头输出机器行；记忆规则要求环境相关条目在正文中写明机器名，机器清单记入画像「档案」；服务不按机器或客户端分别渲染常驻区块，检索也不按机器过滤。
- **理由**：多机共用一份记忆库时，关键在于把适用条件写清，而非在存储或常驻区块里叠加 `machine:` / `client:` 标签；常驻区块给出本机身份后，Agent 结合上下文即可判断适用性。
- **没选**：引入 `client:` / `machine:` 作用域标签；按绑定分别渲染常驻区块；强制按机器过滤检索结果。

### 细节页分四种类型

- **决定**：细节页必填 `type`：`incident`（排错）、`decision`（决定）、`entity`（实体）、`work`（工作单元），页头支持可选的 `supersedes` 声明演进替代关系。服务只校验取值与无环引用，不校验小节名；仅按英文名识别三个约定小节：`work` 页的 `Leftovers` 汇总为主线未决事项，`decision` 页的 `Overturned` 非空或被另一页 `supersedes` 取代时不算有效决定，`incident` 页的 `Lesson` 在整理报告中引用。
- **理由**：主线简报需要按类型分组，让 Agent 在开局快速区分有效决定、排错记录与未决事项；小节结构由内容决定，强制校验会让写入僵化。
- **没选**：只有三种类型（「一段工作的完整记录」无处安放）。

### 条目用内容哈希短码引用

- **决定**：服务返回条目时附带内容哈希前 6 位短码，后续调用凭短码引用；短码不写入文件。内容一改短码即失效，兼作乐观并发控制。
- **理由**：条目级引用都是短时的（一次往返或一次整理）；长期引用只发生在细节页之间，已由页面标识解决。
- **没选**：文件内写永久编号（手改维护成本高）、按原文匹配（转述易失配）、按行号（插入即错位）。

### 不设写入上限，整理时提示篇幅

- **决定**：画像、领域、活动、标题与别名均不设长度与条数硬上限。简洁由提示词引导，过长条目与常驻区块由整理报告提示，由用户决定是否精简。仅保留结构性约束（活动与触发描述限一行）、主线简报上限与别名最少个数。
- **理由**：写入时拒绝的代价落在记录当下，模型为挤进上限反复改写甚至放弃记录，而固定上限数字本身缺乏数据支撑。

## 写入与整理

### 不用钩子，不做后台补抽

- **决定**：写入只有三个入口：记忆规则（对话中当场写）、用户触发的 `tacit-remember`、整理 `tacit-consolidate`。不使用客户端钩子，也不在会话结束后读聊天记录补抽。
- **理由**：主会话是唯一掌握完整情境的一方，知道哪句是拍板、哪次是纠正；事后补抽脱离情境，噪声大。钩子覆盖不了自动压缩与突然退出，且每家客户端各一套适配成本高；只依赖 MCP 与 skill 才能跨客户端通用。
- **代价**：主会话未遵守规则且用户未触发 `tacit-remember` 就结束会话时，该段内容不会被记住。

### 服务不调用生成模型

- **决定**：服务不调用任何生成式对话模型，包括后台汇总、抽取与反思。所有需要理解与生成的工作由主会话完成，服务只做存储、校验、判断与检索。
- **理由**：主会话掌握完整上下文且能力更强，服务没有自己的「大脑」，行为可预测、可测试。
- **没选**：服务内置 LLM 做抽取、合并或重要性打分（如 Mem0、Hindsight、Generative Agents）。

### 决策模型只做判断，凭据检测留在本地

- **决定**：决策模型只回答结构化选择题（重复页、同主题、同一偏好、画像冲突），返回概率并按双阈值分「确定 / 不确定 / 否定」三档，不确定项留待整理复核。凭据检测不交给外部模型，只用本地正则。
- **理由**：判断可预测、可测试。把凭据检测交给外部模型会在真含凭据时将其外泄，与安全目标相悖，且每次写入额外增加延迟。
- **实测**：基于 TypeSafe `jev-latest` 以中文真实样本标定的默认阈值为确定 ≥ 0.85、否定 ≤ 0.25：重复页正样本最低 0.90、负样本最高 0.19、误拒为 0。更换其他决策模型后须自行核对调整。
- **代价**：口述式的裸密码缺乏格式特征，无法靠正则拦截，依赖工具说明中的规则约束。

### 整理按变化增量检查并限时

- **决定**：整理先自动完成格式修正、候选去重、周/月汇总与主线近况更新；再将需决策的提案编成编号清单交用户一次回复确认；最后执行并提交。依赖决策模型的检查只看上次整理以来变过的内容，判断概率按提问内容缓存，单次整理限时 20 秒。
- **理由**：把用户确认成本压到一次回复；调用量与增量成正比而非仓库总量；避免部分客户端 30 秒 MCP 请求超时导致整份报告被丢弃。
- **没选**：全量检查加手动维护的「已判定不重复」名单；空闲时后台补抽。

### 只有完整整理推进基准

- **决定**：只有基于完整报告（判断在预算内算完且无类别截断；未配置的模型不影响）且用户未限定范围的整理以 `consolidate:` 提交并推进基准；其余以 `consolidate(partial):` 提交，基准不动。基准以来的增量类别全部列出、不截断。
- **理由**：局部整理或限时中断时若推进基准，尚未检查的变更之后将不再出现；增量不截断则是为了防止基准未推进时每次只露出同样的前 20 项。
- **没选**：单独维护每个类别的进度状态文件；不完整整理也推进基准。

### 记忆指令做成手动 skill，整理报告经 MCP 资源提供

- **决定**：`tacit-remember` 与 `tacit-consolidate` 是只能由用户触发的 skill；整理报告需现场计算，经 MCP 资源 `tacit://consolidation-report` 提供。
- **理由**：部分客户端对 MCP prompt 参数解析受限，附加文字易被丢弃；手动 skill 能原样送达用户附加要求。资源不占工具列表，也不会被模型擅自调用。
- **没选**：保留 MCP prompt；新增返回报告的 MCP 工具；让 Agent 经 shell 调 CLI。

### 整理提醒只提供布尔信号

- **决定**：`GET /api/consolidation` 与 `tacit consolidation` 仅现场计算并返回「是否该整理」，不附原因与计数，由客户端自己的定时机制决定何时询问与后续动作。
- **理由**：整理提示只在连接时下发一次，长会话容易错过；定时任务只需要一个触发信号，细节在整理时由报告给出。
- **没选**：服务定时缓存；内置 webhook 或系统通知；MCP 通知（多数客户端不展示）。

## 注入与语言

### 常驻区块与服务端说明按变化频率分路

- **决定**：低频变化的内容（全局画像、领域索引、主线）写入客户端上下文文件的常驻区块；高频变化的内容（核心规则、值得记标准、最近 7 天活动、状态与整理提示）在连接时动态生成为服务端说明（总长上限 4000 字符）。
- **理由**：主流客户端对服务端说明约有 4000 字符上限，装不下完整画像；全部写进上下文文件又会导致每天改写用户的全局文件。核心规则放在服务端说明，服务停止时规则随工具一同消失。

### 提示词分层，策略文字外置

- **决定**：触发时机（何时检索、何时写）放在开局可见的服务端说明；详细写法放在按需读取的记忆 skill；调用格式放在工具说明与拒绝回复。策略文字外置为 `TACIT_HOME/prompts/` 下四份文档，支持自定义覆盖（`skill.md` 仅追加）。
- **理由**：避免写法细节挤占服务端说明容量，同时保持用户可定制性而不破坏工具契约与触发描述。

### 面向 Agent 的文字与文件结构词固定英文

- **决定**：工具说明、服务端说明、skill、工具回复、整理报告、判断问题以及记忆文件的结构词固定英文；`language` 仅控制记忆内容与面向人的界面/CLI/日志语言。
- **理由**：长提示词只维护一份，避免双语漂移，且英文指令遵循更稳定；文件格式与 `language` 解耦，不同语言设置的机器之间可直接共享记忆仓库。
- **没选**：界面语言与记忆语言拆成两个开关；要求细节页所有自由小节名也用英文。

## 存储、备份与同步

### 索引用 SQLite：FTS5 加 C# 余弦计算

- **决定**：派生索引使用 SQLite：全文用 FTS5（中文在 C# 侧切为相邻二字并保留末尾单字），向量以 float32 BLOB 存于普通表，检索时先用 SQL 筛选再在 C# 中通过零拷贝流式扫描 + SIMD 逐条计算余弦距离，同时维护由页头显式 `related` / `supersedes` 派生的页面关系表。
- **理由**：个人记忆规模在数百至数千单元，零拷贝流式 SIMD 计算耗时远低于数毫秒，无需近似索引；移除原生扩展 `sqlite-vec` 省去了多平台原生二进制分发与校验。基于显式页头链接的轻量派生页图保持 100% 确定性与可重建性，无需后台 LLM 抽取三元组。
- **没选**：继续捆绑 `sqlite-vec`；引入第三方向量计算包；正则扫描正文提取隐式链接；引入独立图数据库或后台 LLM 抽实体三元组。
- **检索门控与调分**：`minRerankScore` 默认 `0.20` 拦截明显无关噪声，并配合相对最佳分截断（`0.30 × best`）与通用搜索活动槽位上限动态收缩 `topK`；对已推翻/被取代页面温和降权（`× 0.70`），并在通用搜索下对活动施加类型先验与 90 天半衰期温和衰减（细节页零时间衰减，显式 `kind=activities` 不受影响）。所有参数白盒可见于检索追踪，且支持通过 `retrieval.minRerankScore` 按实际重排模型微调。

### 云端备份用 WebDAV，密钥用固定环境变量名

- **决定**：云端备份经通用 WebDAV 上传整份 zip 快照，远端仅存一份，先 `PUT` `.part` 再 `MOVE` 原子替换。每个密钥有固定环境变量名（`TACIT_*_API_KEY`、`TACIT_WEBDAV_PASSWORD`），非空时优先于配置文件。
- **理由**：各类网盘、NAS 与自建服务普遍支持 WebDAV；整份快照带走配置与提示词，恢复路径与本地一致；固定变量名便于报错与 `status` 精确提示。
- **没选**：用 `git push` 替代备份（会丢失配置与提示词）；配置文件 `${VAR}` 插值；系统钥匙串（后台服务跨平台兼容性差）。

### 多机同步直接用 Git，线性 rebase 加定向 union 合并

- **决定**：多台机器各自运行常驻服务，记忆仓库经 `sync.remote` 自动拉取与推送；配置、提示词、绑定与备份留在各自机器。两边都有新提交时采用 `rebase` 保持线性历史；仅对只追加的 `recent/*.md` 与 `candidates.md` 启用 `merge=union`，并在 `.git/info/attributes` 中强制 LF 换行；冲突、历史不相关或恢复备份后自动暂停同步，交由人工解决或 `--use-local / --use-remote` 选边。
- **理由**：记忆仓库本身就是 Git 仓库，天然支持离线提交与合并；线性历史便于定位整理基准；只追加文件用 `union` 可避免同日双机记录冲突，而覆盖类文件遇冲突暂停可防止静默丢数据。
- **没选**：导出/导入工具；单一远程常驻服务（断网不可用且暴露 MCP）；合并提交（历史分叉）；冲突时自动取一边。

## 辅助模型、服务与 Web 界面

### 辅助模型按通用协议接入且全部可选

- **决定**：嵌入（OpenAI Embeddings）、reranker（Cohere/Jina Rerank）、决策模型（System One）按通用协议接入，填写完整请求 URL（不自动拼接路径），另内置 Cloudflare Workers AI 适配；三者与密钥均可省略。
- **理由**：开源项目不能假设用户自行部署模型，Cloudflare 免费额度提供零自部署的完整体验，全部可选则保证了零配置即可开箱试用。
- **没选**：为每家厂商写适配；引入 Python 子服务做模型代理。

### 单一常驻 HTTP 服务，绑定不代写 MCP 配置

- **决定**：仅提供单一常驻 HTTP 服务，不提供 `stdio` 传输；客户端绑定只维护上下文文件常驻区块与 skill 链接，不读写任何客户端的 MCP 配置文件。
- **理由**：`stdio` 会导致多客户端并发启动多个进程同时写文件与 `git commit`，引发竞态与锁冲突；各客户端的 MCP 配置文件路径与格式各不相同，打印端点由用户自行配置最稳妥。

### CLI 面向脚本与 Agent，Web 界面由同一进程托管

- **决定**：CLI 保持非交互、退出码分明、无 TUI；Web 界面构建为静态单页应用由 `tacit serve` 在 `/ui` 托管，只调用管理 API，配置保存后在进程内重建运行时生效。
- **理由**：单进程部署、托管与排障最简单；管理 API 与 CLI 共用同一套规则；后台服务无法从其他设备重启，进程内重建运行时解决了远程改配置的问题。
- **代价**：通过设置页保存 `config.yaml` 会整份重写并去掉手写注释。

### 按连接来源鉴权，外观偏好留在浏览器

- **决定**：仅依据 TCP 对端地址区分本机（免登录、可访问 `/mcp`）与其他设备（须访问密码登录、禁止 `/mcp`），不内置 HTTPS；明暗与调色盘仅存浏览器 `localStorage`，经 `<meta name="color-scheme">` 与 `light-dark()` 生效。
- **理由**：本机用户本就能直接读写 `TACIT_HOME`，本机鉴权无安全收益；单用户个人工具不需要账号权限体系；外观偏好属于设备与环境光线选择，不应跨设备串扰或触发服务重载。

## 代码组织与发布

- **一处声明，处处派生**：配置键表 `ConfigKeys`、工具取值 `ToolValues`、前端路由 `routes.ts` 均单一声明，避免多处抄写漂移。
- **不嵌 libgit2、不引 Markdown AST 库**：统一调用命令行 `git` 以与主会话整理行为一致；按行定点修改 Markdown 以保留用户手改字节。
- **单文件裁剪发行包**：采用自包含、单文件、压缩并仅裁剪框架（`TrimMode=partial`），SQLite 原生库放同目录，JSON 全面源码生成，以 `build/smoke.sh` 作为裁剪安全网；不做 Native AOT（受限于 Dapper 动态代码生成）。
- **三平台原生打包与 Apache-2.0**：支持 `win-x64`、`osx-arm64`、`linux-x64`（glibc），macOS 需原生构建以完成 ad-hoc 签名；版本号由 MinVer 从 `v*` tag 推导；采用 Apache-2.0 许可兼顾宽松使用与专利授权。
