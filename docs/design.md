# TacitMemory 设计

本文档定义系统**做什么**：记忆如何分层、如何存储、何时写入、如何检索与注入，描述的是 v1 的目标行为。对外接口与可配置项的逐项说明见 `docs/reference/`（`mcp.md`、`cli.md`、`configuration.md`），运维做法见 `docs/operations.md`，代码如何组织与各模块的实现状况见 `docs/architecture.md`，术语见 `GLOSSARY.md`。

## 1. 目标

让 Agent 像一个可靠的老朋友：记得用户的偏好与习惯，记得用户最近在做什么，提起具体的事时能想起细节；不记得时直说，不编造。

| 场景 | 用户说 | 期望的反应 | 依靠 |
| :--- | :--- | :--- | :--- |
| 新开会话 | "帮我写个脚本" | 直接按用户习惯的语言和方式回应，不用重新交代 | 画像（全局条目与领域索引，常驻区块） |
| 随口聊 | "最近有点累" | 能联想到用户最近在忙的事，但不复述近况 | 主线（常驻区块）；最近 7 天的活动（服务端说明） |
| 提起一件事 | "上次数据库升级那个坑" | 先检索，再按记忆回答现象、根因和解法 | 细节页 |
| 提起没记过的事 | "上次部署那个问题" | 说没有这方面的记忆，再问细节 | 记忆规则 |
| 没提起 | 聊别的 | 不主动翻旧账 | 细节页不常驻 |
| 纠正后确认 | 用户纠正 Agent，或明确说出一条做法 | 问一次"要记成长期规则吗"，并说明理由；同意后才写入画像 | 会话内即时确认（记忆规则） |
| 主线开局 | "我们来看 my-app 的发版" | 先 `recall workstream=my-app` 读主线简报，再行动 | 主线简报 |
| 命中领域 | "帮我看下代理为什么慢" | 任务命中领域索引中某个领域的触发描述时，先用 `recall kind=rules domain=<标签>` 取该领域的规则 | 领域索引与 `kind=rules` |
| 临时问答 | "Python 里 `zip` 怎么用？" | 直接回答，不写入任何记忆 | 值得记标准（"不记"） |
| 顺口提到的偏好 | 与当前任务无关的一句偏好 | 不当场提交为候选，不打断当前任务 | 值得记标准；整理时才归纳 |

## 2. 原则

1. **只存环境里拿不到的信息**：记忆只保存 Agent 无法从代码、仓库文档、配置、客户端会话历史中获得，且会改变其行为的信息。
2. **按进入上下文的方式分层**：常驻内容在会话开始时就在上下文中，一定被看到；按需内容由 Agent 主动检索，前提是它知道去取。
3. **常驻只能依据开局信号**：会话开始时只知道工作目录、客户端和时间。只在特定话题下才相关的内容一律按需检索。
4. **文件是唯一真相源**：所有记忆都是人类可读、可直接编辑的 Markdown 文件，存放在独立的 Git 仓库中；派生索引随时可删除重建。
5. **理解与生成交给主模型，判断交给辅助模型**：写什么、怎么写、如何改写由主会话完成；常驻服务借助辅助模型做召回、排序和结构化判断，自身不调用生成式对话模型。
6. **实时写入求快，批量清理靠整理**：对话中的写入可以不完美；合并重复、精简画像、确认候选等工作在整理中完成。
7. **画像只是记忆**：常驻内容是可能过时的背景，优先级低于主线上下文文件与当前对话中的用户指令。

## 3. 三层记忆

| 层 | 内容 | 进入方式 |
| :--- | :--- | :--- |
| **画像** | 红线、协作规则、偏好、档案四节，每条带作用域（全局、主线、领域） | 全局条目与领域索引常驻：写入常驻区块；领域正文按需（`kind=rules`）；主线条目进入主线简报 |
| **近期活动** | 主线文件、按月存放的活动记录与汇总 | 主线的背景说明与近期摘要常驻：写入常驻区块；最近 7 天的活动常驻：写入服务端说明；活动记录按需 |
| **细节页** | 一件事或一个主题一页，按小节组织 | 按需：被提起时检索 |

## 4. 辅助模型

| 模型 | 职责 |
| :--- | :--- |
| 嵌入模型 | 生成向量，用于检索召回与判断前的近邻筛选 |
| reranker | 对检索候选精排，并按分数阈值过滤 |
| 决策模型 | 回答选择题，返回各选项概率 |

三者均可不配置：某个模型的映射缺失即为未配置，服务照常启动并按降级工作（见下文「降级」）。已配置的模型每个配置 `url`（完整请求地址，程序原样请求，不追加路径）、`model`，以及可选的 `apiKey`（有密钥时以 `Authorization: Bearer` 发送，没有则不发送任何认证头）。三个模型各按一种通用协议请求：嵌入模型为 OpenAI Embeddings，reranker 为 Cohere/Jina Rerank，决策模型为 System One（TypeSafe 的原生决策接口即其一个服务）。决策模型接口与具体模型无关，只包含选择题。发给决策模型的问题一律使用英文，被判断的内容保持原文。

每个模型可配置 `provider`，省略即为通用协议；写 `cloudflare`（不区分大小写）则按 Cloudflare Workers AI 的格式收发，这是目前唯一的提供方适配。差异只有两处：reranker 发送 `query` 与 `contexts[].text`，不发送模型名（`model` 仍必填，只用于显示），按 `result.response[].id` 与 `score` 对回每段文档的分数；决策模型的请求与 System One 相同，响应先取 `result` 再按 System One 读取。嵌入模型接受 `provider: cloudflare`，按通用协议处理。Cloudflare 响应的 `success` 不为真或缺少 `result`，与其他格式错误一样视为格式不对、不重试。reranker 的每段文档都须得到且只得到一个分数，缺漏、重复或越界的序号同样是格式不对。重试、退避、单次超时、总时限与冷却由同一个模型客户端负责，两种提供方不分支；判断阈值与 `minRerankScore` 的默认值不随提供方或模型变化，换模型后的判断质量由使用者自行核对。

配置项的写法与校验见 `docs/reference/configuration.md`「`models`」。

### 判断

| 判断 | 题型 | 确定时 | 拿不准时 |
| :--- | :--- | :--- | :--- |
| 新画像候选与已有候选或拒绝列表中的某条是否同一偏好 | 选择 | 并入该候选；命中拒绝列表则不记录并告知 | 新建候选 |
| 新建细节页与同主线已有页是否同一件事 | 选择 | 拒绝新建，列出该页 | 允许新建，留待整理 |
| 新活动与当天已有活动是否同主题 | 选择 | 退回已有活动，要求合并 | 单独记录 |
| 新写入的画像条目是否与已有条目冲突、重复或取代它 | 选择 | 拒绝写入，返回冲突条目的节、原文与短码，与用户确认后改用 `replace` 改写它 | 写入，留待整理 |

- 选择题最多 10 个选项（含"都不是"），候选按判断而定：重复页判断取同一所属主线内的嵌入近邻，同主线没有其他页时不提问；同主题判断取当天全部活动（不分主线）中最新的 9 条，当天没有活动时不提问；同一偏好判断取候选、拒绝列表与画像三处合并的嵌入近邻至多 9 条（不分作用域），选项标明来源、归属节与作用域，三处都为空时不提问；画像冲突判断取全局条目与同作用域条目（作用域为所写条目的作用域，`replace` 为被替换条目的作用域）中嵌入最相近的至多 9 条，`replace` 时排除被替换的那一条，没有其他可比较条目时不提问。题意为"新条目是否与某条已有条目冲突、重复或取代它"，被判断的内容保持原文，选项附所在节。
- 服务只使用模型返回的概率，自行计算：选择题取最高概率。
- 每个判断在配置中设上下两个阈值，划出"确定 / 拿不准 / 否定"三档；未配置时用内置默认值（以真实中文样本测定）。选择题："都不是"的概率不低于其余任一选项时为否定；否则最高的选项不低于上阈值为确定，不高于下阈值为否定，其间为拿不准。实测中最高概率与第二名之差不改变任何结果，因此不参与划分。拿不准的情况不自动处理，由整理重新发现。
- 凭据检测不交给决策模型，只用内置正则，写入内容不会为了检测而离开本机。正则匹配以下常见格式，命中即拒绝：`sk-` 开头的密钥、`ghp_` 等 GitHub 令牌、`AKIA` 与 `ASIA` 开头的 AWS 访问密钥；Slack、GitLab、Google、阿里云、SendGrid、Docker Hub、Notion、Stripe live 等服务令牌；JWT、私钥块、URL 中的 `user:pass@`、`Bearer` 令牌、`password=`；键名以 pass、pwd、token、secret、api key、access key、session 结尾，用 `=` 或 `:` 赋值，且值不少于 6 个字符并含数字；40 字符以上且同时含大小写字母与数字的 base64。值为 `<…>`、`${…}`、`***` 等占位符或 `xxxx`、`your…` 时不算。没有格式特征的裸值（如口述的"密码是 …"）正则拦不住，靠三个写入工具说明中"禁止写入凭据"的要求约束。被拒绝时指出可疑片段的位置与开头 6 个字符，不回显整个片段；主会话确认无凭据后可带 `confirm_no_secret` 重新提交，此时跳过正则。检测范围是本次写入的标题、别名、小节名与正文；`delete_section` 不写入新内容，不检测。

### 降级

辅助模型不可用时不拒绝写入：

| 不可用 | 写入 | 检索 |
| :--- | :--- | :--- |
| 嵌入模型 | 照常写文件并提交；判断因无法取近邻而跳过，按拿不准处理；向量在模型恢复后按文件哈希补齐 | 只走全文 |
| reranker | 不受影响 | 按合并顺序返回，不精排 |
| 决策模型 | 所有判断按"拿不准"处理 | 不受影响 |

未配置与不可用是两回事。未配置的模型从不被调用，不发请求、不进入冷却；它不在写入与检索的返回末尾注明，不进入服务端说明的状态提示；整理报告中依赖它的类别标为"未检查（未配置）"，`tacit status` 中显示"未配置"且不上色。不可用的模型是已配置、请求最终失败、正在冷却的模型，照常在返回末尾注明并进入服务端说明。去掉嵌入模型的配置时，派生索引中已存的向量保留，之后加回同一模型名不需要重新嵌入；换成另一个模型名时才丢弃向量并补齐。

降级时返回结果末尾注明（未配置的模型不注明）；启动时连不上任一已配置的模型不阻止启动，但在服务端说明与 `tacit status` 中提示。嵌入模型不可用时，沿用索引中记录的向量维度，恢复后再校验。没有嵌入模型时，`tacit reindex` 只重建全文并注明未配置嵌入模型。

辅助模型的每次请求先在请求内重试，偶发错误不直接降级：

- 重试：网络错误、单次超时、HTTP 429 与 5xx，一次请求最多尝试 5 次。HTTP 401/403、400/404/422 及其他 4xx，以及响应格式不对（无法解析、向量长度不一致、概率缺项等），不重试，直接算失败。
- 退避：两次尝试之间依次等 0.5、1、2、4 秒；429 带 `Retry-After` 时按其等待。
- 总时限：一次请求从第一次尝试起最多 20 秒，含各次尝试与退避。每次尝试有 5 秒单次超时，但被总时限截断。时限用完即算失败，不再发起新尝试，也不等待超出时限的退避。
- 冷却：只有请求最终失败（5 次用尽、遇到不重试的失败或用完总时限）才记一次失败，该模型冷却 30 秒，冷却期间不调用，状态提示列出它。冷却结束后的下一次请求照常尝试，成功一次即恢复可用。重试过程中的失败不改变健康状态。

次数、退避与总时限不做成配置项。代价已接受：模型挂起时，一次实时写入最多等 20 秒才判定失败并降级，期间写入锁被占用；进入冷却后才恢复为立即跳过。

画像冲突判断在决策模型或嵌入模型不可用时照常写入，并在回复末尾注明判断被跳过。

### 探测

`tacit probe [embedding|reranker|decision]` 由 CLI 直接读取 `config.yaml`，对配置中的模型各发一次真实请求。它不经常驻服务，因此服务未运行时也能用，也不要求记忆仓库已初始化；它不经模型客户端的重试与冷却，不改变任何模型的健康状态，不写服务日志。请求的构建与响应的读取与正式使用相同，格式不对（含 Cloudflare 的 `success` 为假）同样算失败。

请求体只含内置的固定英文文本：嵌入模型一句英文，reranker 一条英文查询与两段英文文档，决策模型一道两个选项的英文选择题。探测不读取、也不发送任何记忆内容。

探测只发一次请求、不重试，单次时限 20 秒。成功只说成功；失败给出 HTTP 状态码、响应体前 500 个字符与耗时，网络错误与超时给出错误类别与耗时。输出与报错不含任何密钥值：响应体中出现的密钥以 `***` 代替。输出开头写明探测的是 `config.yaml` 中的配置。不带参数时依次探测三个模型，未配置的模型显示"未配置，跳过"且不算失败；明确指定却未配置的，退出码为 1。

## 5. 存储

```text
<记忆仓库>/
├── .gitignore              # 只含 .cache/
├── persona.md              # 画像
├── candidates.md           # 画像候选与拒绝列表
├── workstreams.md          # 主线：已成立的主线的背景说明与近期摘要
├── recent/YYYY-MM.md       # 活动记录（按月），末尾可有 ## 汇总 节
├── pages/
│   ├── <主线>/<slug>.md    # 细节页，目录名即所属主线
│   └── _topics/<slug>.md   # 专题
└── .cache/                 # 派生索引，不进 Git
```

### 通用写法

- 新建文件为 UTF-8 无 BOM、换行 LF，文件以换行结尾；修改已有文件时保留其原有的 BOM 与换行风格（含 CRLF）。列表项以 `- ` 开头，缩进两个空格。
- 日期一律 `YYYY-MM-DD`，按常驻服务所在机器的本地日期。
- 文件不写一级标题，从 `##` 开始分节；细节页标题只在 YAML 头的 `title` 中出现。
- 来源写在条目下一行的缩进 HTML 注释里：`<!-- 2026-10-25 原话「怎么又搜不到中文了」 -->`，原话可省略。活动记录的注释只含原话，日期由所在的日标题给出。
- 结构词（节名、`归属：`、`原话` 等）按记忆语言写入；解析时所有支持语言的结构词都识别。
- 所属主线名转为小写，只允许 `[a-z0-9._-]`；以下划线开头的名字保留给系统（如 `_topics`），以点开头的目录不算主线。

### 条目与短码

| 文件 | 一条 |
| :--- | :--- |
| `persona.md` | 一个顶层列表项 |
| `workstreams.md` | 一个 `## 主线` 节，每条主线一个三级标题及其背景说明、近期摘要两行；不设短码，由整理直接编辑 |
| `recent/YYYY-MM.md` | 日期标题下的一个列表项；`## 汇总` 节中的一行汇总（不带短码） |
| `candidates.md` | 一个三级标题及其出现记录 |
| 细节页 | 一个小节，以"页面标识 + 小节名"指代 |

服务返回条目时附带短码（规范化文本哈希的前 6 位，例如 `a3f9c2`），后续调用凭短码引用；短码不写进文件。内容完全相同的条目按出现顺序加后缀（`a3f9c2-2`）。条目内容一改，旧短码即失效：拿旧短码替换或删除会被拒绝并返回最新内容。

### 画像 `persona.md`

```markdown
## 红线
- 不要自行发布版本或推送到公开仓库；改为先请用户确认（理由：影响外部，无法撤回）
  <!-- 2026-10-25 原话「发布前必须问我」 -->

## 协作规则
- 需求不清时 → 先连续追问，确认后再给出完整方案
  <!-- 2026-10-20 原话「先问清楚再动手」 -->

## 偏好
- 沟通：先要结论，再看依据；反感客套和铺垫

## 档案
- 系统：Windows 11 x64，Shell 为 PowerShell 7
```

| 节 | 句式 |
| :--- | :--- |
| 红线 | `不要 <行为>；改为 <替代做法>`，可加一句理由；英文记忆中"改为"的结构词为 `instead`，写作 `Don't <behaviour>; instead <alternative>` |
| 协作规则 | `<情境>时 → <做法>`，只用肯定句，理由可选 |
| 偏好 | `<维度>：<描述>`，描述句，可写"不喜欢……" |
| 档案 | `<字段>：<事实>`，不写行为要求 |

- 每条一行，一条只写一个情境和一个做法；不使用大写强调词。简洁靠句式与好坏对照引导，写入不设字数与条数上限，过长的条目由整理报告的篇幅提示列出，由用户决定是否精简。
- 修改逐条进行，不整篇重写；被取代的条目直接替换，历史由 Git 保留。

#### 作用域

前四节只放全局条目。领域与主线条目放在其后的作用域块中，每个作用域一个二级标题，块内按四节分三级标题，句式与上限相同：

```markdown
## 领域：network-proxy
触发：改代理、分流或测速时
### 协作规则
- 性能/节点比较 → 不拿单次测速当日常结论
  <!-- 2026-11-06 原话「……」 -->

## 主线：my-app
### 协作规则
- 发版 → 先跑全量测试
```

- 结构词随记忆语言：中文为 `## 领域：<标签>`、`触发：<一行>`、`## 主线：<名>`，英文为 `## Domain: <label>`、`Trigger: <line>`、`## Workstream: <name>`；解析时两种都识别。
- 领域标签与主线名同一套命名规则（`[a-z0-9._-]`，不以 `.` 或 `_` 开头）；触发描述为一行，不设长度上限。
- 块的顺序：全局四节之后，领域块在前、主线块在后，各自按名称排序。写入新块时按此顺序放置；块缺失时补回，块内缺少的节按四节标准顺序补回块内。
- 领域的规则可以来自用户偏好，也可以来自排错教训，只要它只在该情境下成立。

### 画像候选 `candidates.md`

```markdown
## 候选

### 沟通：先要结论，再看依据
归属：偏好
- 2026-10-28 原话「先说结论」
- 2026-10-30 原话「别铺垫，直接说结果」

## 拒绝列表

### 每次提交前都运行全量测试
归属：协作规则
- 2026-10-27 原话「跑一下全部测试」
- 2026-10-29 拒绝 原话「不用，只跑相关的」
```

- 三级标题即确认后写进画像的条目原文；出现天数按不同日期计数，只作整理时的参考。
- 归属行之后可有一行 `作用域：domain:<标签>` 或 `作用域：workstream:<名>`（英文为 `Scope: …`），缺省为全局；拒绝列表的条目同样。作用域行的值不合规时记为格式问题，该候选按全局处理。
- 候选全部作为整理时的证据，没有出现天数门槛；确认后移入 `persona.md`，作用域随之进入对应的作用域块。
- 拒绝列表永久有效；用户改主意时可直接要求写入画像。
- 提议写入候选时的标题补回与出现记录追加规则见第 6 节。

### 主线 `workstreams.md`

```markdown
## 主线
### mac-mini
背景：家里的常驻服务器，跑代理分流和自用服务。
近况：服务栈搭完后在收敛，砍掉不常用的。
```

每条主线一个三级标题（名字即主线名，规则同上），其后两行：背景说明（必填，写这件事是什么，基本不变）与近期摘要（可缺，写近期处在什么阶段、往哪走，不罗列做了哪些）。英文记忆的结构词为 `Workstream`、`Background:`、`Recent:`。文件中有条目的名字才是已成立的主线；由用户确认后由整理直接编辑该文件，数量不设上限。活动比近期摘要新，两者不一致时以活动为准。

### 活动记录 `recent/YYYY-MM.md`

```markdown
## 2026-10-31
- [tacit-memory] 决策模型定为只做判断，去重与修正交给整理
  <!-- 原话「其实可以直接把记忆库当成主线」 -->
- 想清楚了画像里缺的是人的倾向，而不只是规范
```

每天一个二级标题，按写入顺序排列；属于主线的活动以 `[主线名]` 开头。长度与写法见第 6 节。

月文件末尾可有一节 `## 汇总`（英文 `## Summary`），由整理时的主会话直接编辑写入，每行一条汇总：

```markdown
## 汇总
- 2026-W45：本周整理了画像与记忆结构
- 2026-11：十一月主要在做记忆重设计
```

- 周汇总形如 `- 2026-W45：<一行>`，周按 ISO 周计（周一至周日），写在该周周四所在月份的文件里；月汇总形如 `- 2026-11：<一行>`，按自然月计，写在该月的文件里。
- 汇总节不是活动：其中的行不在日期标题下，不取短码，不参与同主题判断与"最近 7 天"的活动列表，也不能被 `replaces` 指向。
- 新活动仍写在当天的日期标题下；当天还没有标题时，标题写在汇总节之前，汇总节保持在文件末尾。
- 无法识别的行、不存在的周号或月份、写错文件的周或月，列入整理报告的格式问题，服务照常读取其余内容。

### 细节页

```markdown
---
title: 数据库升级后扩展丢失
aliases: [全文检索插件失效, 升级后搜索不到中文]
dates: { first: 2026-10-21, last: 2026-10-25 }
related: [my-app/backup-script, _topics/pgroonga]
type: incident
---

## 现象
……

## 根因
……
```

| 字段 | 规则 | 由谁写 |
| :--- | :--- | :--- |
| `title` | 必填，最多 50 字 | 主会话 |
| `aliases` | 至少 2 个，每个最多 30 字；覆盖口语说法、中英文名与别称 | 主会话；可追加 |
| `dates` | 首次与最近一次经服务写入的日期 | 服务 |
| `related` | 其他页的页面标识；指向不存在的页时经服务写入被拒绝 | 主会话 |
| `type` | 必填，取值 `incident`（排错）、`decision`（决定）、`entity`（实体）、`work`（工作单元）之一；经服务新建时必须给出，`update_header` 可改 | 主会话 |

- 页面标识为 `<所属主线>/<slug>`，slug 匹配 `^[a-z0-9]+(-[a-z0-9]+)*$`，在主线内唯一，创建后不可改名。
- 正文按 `##` 小节组织，小节名由主会话决定，页内不得重名。服务按记忆语言的结构词识别两个约定的小节：`work` 页的「遗留」（英文 Leftovers），`decision` 页的「推翻记录」（英文 Overturned）。
- 每种类型的推荐小节与示例写在记忆 skill 中，服务不校验小节名。

### Git

- 首次初始化：`git init`，写入 `.gitignore`、各文件的节标题骨架与 `recent/`、`pages/` 下的 `.gitkeep`，提交 `init: create memory repo`。目录非空且不是 Git 仓库时拒绝初始化。
- 再次执行 `init` 不覆盖任何已有文件：记忆目录已是 Git 仓库时只补缺失的骨架文件，不提交，并列出已存在的文件。传入的 `--language` 或 `--memory` 与已有 `config.yaml` 不一致时拒绝执行。
- 每次经服务的写入自动提交一次，只提交本次写入的文件，作者固定为 `tacit <tacit@localhost>`。提交信息为 `<区域>: <动作> <对象>`，区域为 `persona`、`candidates`、`recent`、`pages` 之一，例如 `pages: create tacit-memory/db-upgrade`。
- 要写的文件含有用户未提交的修改时，连同修改一起提交，并在提交信息末尾注明。
- 整理的提交由主会话完成，提交信息以 `consolidate:` 开头；服务据此识别上次整理的时间。

### 生成整理报告时当场解析

服务修改文件时只定位并改动要改的那几行，其余内容原样保留。格式不符合约定时照常解析；问题不在写入或索引同步时记录，而是生成整理报告时把全部记忆文件重新解析一遍当场得出（见第 9 节），修正后下次生成报告即消失。下表是各类情况的解析处理，问题本身的检查项见第 9 节：

| 情况 | 处理 |
| :--- | :--- |
| 细节页 YAML 头无法解析 | 照样建索引，`title` 取文件名 |
| 协作规则缺 `→`、红线缺"改为"、无法识别的节或内容 | 照样计数与渲染 |
| 某节条目过多或过长 | 照样全部渲染与写入，不设上限；整理报告的篇幅提示列出过长的条目 |
| 细节页缺少 `type` 或取值无效 | 照样建索引、检索与读取；整理报告的格式问题中列出，不受整理基准限制 |
| 日期格式错误 | 该条不参与基于日期的计算 |
| 文件不是 UTF-8 | 跳过该文件，在服务端说明中提示 |
| 活动记录中不在日期标题下的条目、无法识别的日期标题 | 不建索引、不计入最近 7 天的活动，其余活动照常 |
| 混用不同语言的结构词 | 照常解析 |
| 画像、候选文件、活动记录与主线文件的格式问题 | 照常解析与渲染，问题只在整理报告中列出，写入路径与索引不使用；主线文件中有问题的条目不算已成立的主线 |

## 6. 写入

### 入口

写入有三个入口，不使用客户端钩子，也不做会话结束后的后台补抽：

1. **记忆规则**：写在服务端说明中，主会话在对话中当场执行，包括用户纠正后的即时确认（见本节「画像」）；
2. **记忆指令** `tacit-remember`（skill）：用户在压缩上下文、退出前或认为重要时触发；
3. **整理** `tacit-consolidate`（skill）：用户定期触发，主会话依据整理报告写汇总与主线、起草画像提案与页面重组（见第 9 节）。

主会话未遵守规则、用户也未执行指令就结束会话时，该段内容不会被记住。这是明确接受的代价。

### 值得记标准

`prompts/rules.md` 分"值得记"与"不记"两节（条数上限见 `docs/reference/configuration.md`「提示词文档」），原样写入服务端说明。初始化时生成默认模板；文件被删除后，下次加载配置时（启动服务、绑定、解绑）按记忆语言重新生成。旧位置 `TACIT_HOME/rules.md` 不再读取。

默认值得记：用户纠正或打断 Agent；方案拍板（保留用户原话）；查明根因的排错（含试过但无效的做法）；新的环境事实；用户明确要求记下。默认不记：常规的写代码、改错字、看日志；能从代码、仓库文档、配置中查到的内容；临时问答、一次性查询和闲聊，没有结论时。

### 通用规则

- **先检索再写**：命中已有页则更新该页，未命中才新建；一件事只对应一页。
- **读取不修改**：检索与读取不改动任何文件。
- **保留来源**：写入内容附带日期，必要时附用户原话。
- **不写凭据**：见第 4 节。

### 细节页

- 新建时提交整页，必须给出 `type`；服务先用决策模型判断是否与已有页重复。
- 更新以小节为单位：新增或替换一个小节、删除一个小节、修改页头（追加别名、改标题、`related` 或 `type`）。替换与删除须带原小节的短码。
- `section` 填的是本页某小节的短码（忽略大小写与首尾空白，且本页没有同名小节）时，`upsert_section` 与 `delete_section` 拒绝并给出该小节的标题；下一步：`section` 填小节名，`hash` 填该短码。不论 `hash` 是否已填都拒绝，不写入也不提交。像短码但不属于本页的值照常按小节名处理。
- 不提供整页重写；大幅调整在整理中直接改文件。

### 近期活动

- 写入时机：一件主事有了结论（定了决定、查明根因、阶段目标完成）时写一条；每个会话至多一条，之后有进展用 `replaces` 改写。
- 一条活动写"人在做什么、想通了什么"，不写"改了哪些文件"。
- 写入 `recent/YYYY-MM.md`，按本地日期定位当日标题；缺标题时追加到文件末尾。写入只改动新增的条目与来源注释，文件其余字节不变。
- 文本限一行，不设长度上限，不以 `[` 开头；原话同样限一行，且不含 `-->`；主线名小写并校验，允许新主线。
- 写入成功时，回复只有一行：新短码（改写时为改写后的短码）。回复不附近期主线与活动列表。
- 与当天已有活动同主题时（按第 4 节的选择题与三档，阈值为 `sameTopic`），服务不写入，以普通回复（非错误）退回该活动及其短码；主会话写出合并后的一句，带 `replaces` 重新提交。决策模型不可用时照常写入，回复中注明未检查；带 `replaces` 时不做同主题判断。
- `replaces` 只指向当天的活动：短码须是当天某条的短码。其他日期、已过期（条目改写后旧短码即失效）或不存在的短码都被拒绝，拒绝时列出当天的活动及其短码。改写在原位替换条目正文与主线标签；带 `source` 时替换来源注释，否则保留原注释。改写与新增经同样的参数校验与凭据检测，不做同主题判断，返回新短码，提交信息为 `recent: replace <短码>`。
- "每个会话最多一条"只写在记忆规则中，服务不强制。
- 主线不经 `write_recent` 写入：`write_recent` 没有 `op`、`items`、`hash` 参数，传入即按未知参数拒绝，下一步说明主线由 `tacit-consolidate` 维护。主线由整理时主会话直接编辑 `workstreams.md` 维护（见第 9 节）；`workstream` 参数不要求主线已成立，未成立的名字照常写入与检索。

### 画像

| 操作 | 允许的条件 |
| :--- | :--- |
| 新增协作规则、偏好或档案 | 用户明确要求记住；或用户纠正、打断 Agent，或明确说出一条做法，且 Agent 问过一次并得到同意 |
| 新增红线 | 只能由用户明确提出 |
| 替换、删除 | 用户明确要求修改或删除某一条 |
| 观察到的偏好或规则 | 只能提交为画像候选，并标明归属节 |

这些条件写在记忆规则中。服务对新写入的条目做冲突判断，见第 4 节。

`add` 的校验与写入：
- 句式只校验红线与协作规则：红线须含"改为"（英文记忆为 `instead`，两种写法都识别），协作规则须含 `→`；偏好与档案不校验句式。
- `text` 与 `source` 各限一行：不含 `\r`、`\n`、U+2028、U+2029、U+0085，即编辑器会显示为换行的字符；`source` 不含 `-->`；`text` 不设长度上限。
- `scope` 缺省为 `global`，可取 `workstream:<名>` 或 `domain:<标签>`，名称不合规时拒绝。`trigger` 只在第一次写入一个新领域时必填（缺少则拒绝，下一步要求补上），须为一行；已有领域与其他作用域忽略它。新领域块的触发行与首条写在一起。
- 条数不设上限：全局四节、一个领域的条目与领域个数都不限，`add` 不因数量被拒。写入后回复写明所在节或领域的当前条数。过长或条目过多由整理报告的篇幅提示与领域卫生列出，由用户决定是否精简。
- `add` 写入对应作用域块的对应节末尾；块或节缺失时按上面的顺序补回。一次写入只提交 `persona.md`。
- 追加在该节末尾，下一行写 `<!-- 当天日期 原话「…」 -->`；节标题缺失时按四节标准顺序补回：补在前面最近的已有节之后，前面都没有时补在后面最近的已有节之前，四节都没有时补在文件末尾；与写入同一次提交。
- `replace` 凭短码原位替换条目及其原话注释：条目留在原节，按原节校验句式与长度，并做画像冲突判断（排除被替换的条目）；新注释为当天日期与新原话，原条目没有注释时新增一行。提交信息为 `persona: replace <新短码>`；结果与原条目完全相同时不写入、不提交。
- `delete` 凭短码删除条目及其续行与原话注释，不需要原话；回复被删除的条目原文。提交信息为 `persona: delete <短码>`。
- `replace` 与 `delete` 凭短码在任一作用域中定位；`replace` 保持条目原作用域，`delete` 删除后其所在的领域或主线块保留标题与触发行，即使已无条目。
- `propose` 的校验与写入：归属节为红线时拒绝，"下一步"为先问用户、明确同意后再 `add`；句式与单行校验同 `add`（按归属节）；`scope` 的校验同 `add`，`trigger` 不适用（候选不创建领域），传入即按未知参数拒绝；凭据检测覆盖原文与原话；不设条数上限。
- `propose` 追加在"候选"一节末尾，写成三级标题（原文）、`归属：<节名>` 与一条出现记录；"候选"标题缺失时补回拒绝列表之前，没有拒绝列表时补在文件末尾，与写入同一次提交。只提交 `candidates.md`，不重新渲染常驻区块；回复写明新建的候选及其作用域（全局时为 `scope: global`），不报告出现天数，不返回短码。
- `propose` 先做同一偏好判断（第 4 节）：命中候选则并入，保留该候选原有的作用域（回复写明它），在其出现记录末尾追加当天的原话，同日已有出现记录时不写入、不提交；命中拒绝列表或画像则不写入，告知拒绝时的日期与原话或画像中的短码。三处都为空时不提问，直接新建候选。

## 7. 检索

| 参数 | 必填 | 说明 |
| :--- | :--- | :--- |
| `query` | 与 `page` 二选一 | 自然语言查询，用记忆语言书写；`kind` 为 `persona` 或 `rules` 时忽略 |
| `page` | 与 `query` 二选一 | 页面标识：读取整页；不能与 `kind` 为 `persona` 或 `rules` 同用 |
| `workstream` | 否 | 只在该主线中检索；与 `query`、`page` 都不给时，返回该主线的主线简报（见下）；不能与 `kind` 为 `persona` 或 `rules` 同用 |
| `from`、`to` | 否 | 日期范围，由主会话把"上周"之类换算成日期；不能与 `kind` 为 `persona` 或 `rules` 同用 |
| `kind` | 否 | `pages`、`activities`（省略时两者都检索）、`rules`（领域规则）或 `persona`（整份画像）；后两者不检索 |
| `domain` | 否 | 领域标签，只与 `kind=rules` 搭配；省略时返回全部领域的规则 |

流程：

1. 筛选：页面按所属主线与页面日期区间（与查询区间重叠即保留），活动按主线标签与所在日期；指定 `workstream` 时，未标注主线的活动不出现；
2. 全文检索（FTS5，BM25）与向量检索（余弦）各取前 30 条。全文检索中，中文切成相邻两字一组；英文与文件名按 `unicode61` 规则在标点处切分，查询以短语匹配，`env.ps1`、`UTF-8` 这类写法仍可命中；单字查询退回子串匹配。向量单位为：每个小节、每页的 `title + aliases`、每条活动（连同主线标签）；
3. 用倒数排名融合（RRF）合并，取前 30 条交 reranker；
4. 丢弃低于分数阈值的结果，返回前 5 条（均可配置）；一条不剩时明确返回英文 `No relevant memory.`。

每条汇总是一个活动检索单元：按其所在周或月的首末日期筛选（与查询区间重叠即保留），没有主线标签，结果标明是汇总及其为周或月（`summary, week starting 2026-11-02`）。结果以小节和单条活动为单位，每条结果标明是页面还是活动。同一页命中的多个小节合为一条结果，每个小节返回全文及短码，并列出该页其他小节的名字；页面级命中按开头几个小节呈现。每条活动单独一条结果，显示日期、短码与所属主线（无主线则省略），随后是活动正文。

画像与候选不进入检索结果，无论 `kind` 为何；它们的向量只供两项判断取嵌入近邻。

`kind=persona` 与 `kind=rules` 不检索，直接读取画像：

- `persona` 返回整份画像：全局四节（各附条数），然后是领域块（按标签排序，标题附条数与触发描述），再是主线块（按名称排序）；
- `rules` 返回领域规则：给 `domain` 时只返回该领域的触发描述与全部条目，不给时按标签排序返回全部领域。`domain` 不是画像中的领域时拒绝，并列出已有的标签。

两者的每条都附短码，即 `write_persona` 的 `replace`、`delete` 接受的短码；原话注释不输出。没有任何条目时返回 `No relevant memory.`。两者不计入使用统计。`domain` 只能与 `kind=rules` 搭配；`kind=persona` 与 `page` 同时出现，或与 `domain` 同时出现，`kind=persona` 或 `kind=rules` 与 `page`、`workstream`、`from`、`to` 同时出现，都按参数错误拒绝，下一步说明怎样调用。

小节日期：每个小节标题后附最后修改日期（检索结果与整页读取都是）。派生索引为每个小节记录内容哈希与最后变化日期：同步时内容哈希（去掉末尾空白后）变化的小节更新为当天，其余保持不变；全量重建时取该文件最近一次提交的日期，未提交的新文件取当天。

使用统计：`recall` 返回的每个检索单元计数加一并记录当天为最近返回日期，整页读取时该页每个小节各加一。统计只存在派生索引中，`reindex` 与恢复清空；页面或月文件被编辑后重新同步时，已有计数按小节名、短码或汇总周期带回，不清零；检索排序完全不读取它，主线简报与整理报告用它排序。

主线简报：只给 `workstream`（不给 `query` 与 `page`）时返回该主线的简报，依次为：

1. 主线名；已成立时其后为背景说明与近期摘要两行（`Background:`、`Recent:`，近期摘要缺省则略去），未成立的名字不列出这两行；
2. 主线约定：主线作用域的画像条目（连同其续行）；
3. 未决事项：各 `work` 页「遗留」小节的非空行，附页面标识；
4. 页目录：按类型分组，依次为有效决定、已知坑、工作、实体、未分类（缺少类型的页）。`decision` 页的「推翻记录」非空时不列入有效决定，归入一行「已推翻」，只列标识。每页一行：标识、标题、别名、最近修改日期。组内按小节日期中最新者倒序，同日按使用次数倒序；没有页的组整组省略；
5. 最近 3 条活动：该主线标注的活动，新到旧；
6. 最近一次周汇总：该主线活动所在的周中，最近一个有汇总的那一周。

`from`、`to` 与 `workstream` 合用时，限定页面（按页头日期区间，与检索筛选相同）与活动的日期区间；与 `kind` 同给时按参数错误拒绝。主线既无页面也无活动时返回英文 `No relevant memory.`。

简报总长不超过 `limits.brief`。超出时只从最旧的页目录条目起截断，并注明省略了多少条；页目录全部省略后仍超出（约定、未决事项、活动与汇总本身超长）时，按上限截断末尾并注明。简报是读取：不改文件，列出的每个页（页目录、已推翻的决定与未决事项中的页）计一次使用统计。

## 8. 注入

常驻内容按变化频率分两路：

| 通道 | 内容 | 何时更新 |
| :--- | :--- | :--- |
| 常驻区块 | 全局画像、领域索引、主线 | 绑定时；画像、主线文件或活动记录变化时；`prompts/resident.md` 变化时；本地日期变化时 |
| 服务端说明 | 核心规则、通用规则、语言规范、值得记标准、最近 7 天活动、状态提示、整理提示 | 所依据的记忆、`prompts/` 下的提示词文档或状态变化后重新生成，客户端连接时下发 |

两者都在下一次会话生效，正在进行的会话不会重新加载。

### 常驻区块

- 由 `<!-- tacit:begin … -->` 与 `<!-- tacit:end -->` 界定，内部以 `<user_memory>` 包裹；起止标记不完整或不唯一时拒绝改写；结果未变不写文件；区块外的内容从不改动。
- 外壳两段与四节引导语来自 `prompts/resident.md`，整份替换内置默认；文件缺失时用内置默认（即现有文字）。起止标记、`<user_memory>` 标签、节标题与画像条目仍由服务生成。格式与校验见 `docs/reference/configuration.md`「提示词文档」。
- 组成依次为：外壳；全局四节；`situational_rules`（每个领域一行：标签、触发描述、条数，全部领域都列出；领域与主线条目的正文不进入常驻区块）；`workstreams`（只列已成立的主线：活跃的一行"名字：背景说明 近况：近期摘要"，安静的一行"名字：背景说明"；活跃的在前，按最近一次活动的日期由新到旧，安静的在后，按名称排序；活跃指最近 28 天内（本地日期，含当天）有标注该主线的活动，28 天为代码常量；没有已成立的主线时整节省略）。无内容的节整节省略；两个生成节的引导语可由 `resident.md` 给出。常驻区块不设长度上限。
- 计算所用的日期是服务的本地日期。服务在每个本地午夜重新渲染，窗口才会随日期前移。
- `resident.md`、`persona.md`、`workstreams.md`、活动记录（`recent/`）或主线目录（`pages/` 下一层）变化后，去抖重渲染所有已绑定文件中的常驻区块；本地日期变化时同样重渲染。渲染彼此串行，失败只提示。连接时使用当前的 `resident.md`。
- 渲染时去掉来源注释；节标题使用英文，条目保持记忆语言。
- 每次渲染都重新读取 `bindings.json`，因此运行中的服务能感知新的绑定；`connect` 在绑定时立即渲染一次。

### 服务端说明

- 组成：开场、核心规则（`prompts/instructions.md`，缺失时为内置默认）、通用规则（代码提供，始终在核心规则之后）、语言规范与值得记标准是固定部分；其后是最近 7 天活动、状态提示与整理提示。提示词文档的文件校验与运行中保存的处理见 `docs/reference/configuration.md`「提示词文档」。
- 固定部分合计不超过 2500 字符。启动时超出则拒绝启动，报告超出的字符数，并列出可精简的文件（`rules.md`；存在 `instructions.md` 时一并列出）。
- 服务端说明总长不超过 4000 字符。生成时超出则依次截断最早的活动；固定部分、状态提示与整理提示不截断。
- 记忆规则各条的内容与职责见 `docs/prompts.md` 第 4 节。
- 语言规范：记忆内容与检索语句使用记忆语言；用户原话、代码、路径、命令与专有名词保持原样。
- 值得记标准：`prompts/rules.md` 两节的条目原样写入；修改 `prompts/rules.md` 后，下一个会话生效。
- 状态提示：列出冷却中的辅助模型（请求重试后仍失败才进入冷却，见第 4 节）与因不是 UTF-8 而被跳过的页面文件、活动记录文件、画像与候选文件；无问题时省略。服务不为探测而调用模型。
- 最近 7 天活动：活动记录中最近 7 天的全部条目（新的在前；超出总长时仍从最早的活动截起），每条前补日期与主线标签，包在 `<recent_activity days="7">` 标签中作为数据；活动中不附短码。主线在常驻区块中，不在这里。
- 整理提示：有以下任一情况时出现，位于服务端说明末尾，各自独立生效：距上次整理达到 `consolidation.remindAfterDays` 天（默认 7；两个提交都没有时视为到期）；存在未汇总的已完成周；候选达到 `consolidation.remindCandidates`（默认 5）；主线为空。内容：距上次整理的天数（以最近的 `consolidate:` 提交为准，没有则以 `init:` 提交为准；两者都没有时写明从未整理过）、未汇总的周数、候选数、格式问题数、主线是否为空，以及一句说明用户可以运行 `tacit-consolidate` skill 开始整理。只有格式问题时不出现。生成时不调用任何模型，不显示重复页与冲突条目的数量；`tacit status` 的待处理问题与此共用同一份计算。它属于动态部分，不计入固定部分的长度上限，计入总长，与状态提示一样不截断。

## 9. 整理

用户在任意目录通过 `tacit-consolidate` skill 开始整理（omp 中的触发方式见 `README.md`，附加要求可省略）。该 skill 的正文只取决于代码与记忆语言，不读记忆仓库，依次包含：开场（现在开始整理；先读取资源 `tacit://consolidation-report`，读不到就停下请用户运行 `tacit serve`；记忆仓库的绝对路径；直接用绝对路径改文件，并在该目录中执行 git，不要求当前目录是记忆仓库）、六个步骤、当前记忆语言的结构词对照表，以及作用域块、候选块、拒绝列表条目与汇总行的示例。用户附在命令后的文字可限定本次的范围，如“只做汇总”（只写汇总，不出提案）；“只处理主线”或“只处理主线 名字”（只做主线材料与主线提案，其余类别不动）用于直接指定一条主线。整理报告不在正文中，由该资源现场返回（见 `docs/reference/mcp.md` 第 4 节）。主会话依据报告直接修改记忆仓库中的文件，最后在记忆仓库中提交，提交信息以 `consolidate:` 开头。

整理步骤（英文，按顺序）：

1. A 部分（`A. Automatic`）直接处理、不问用户：修正标为直接修正的格式问题，删除待清理的画像候选，按材料写周汇总与月汇总行，依据主线材料只重写各条已成立主线的近况（背景说明不改）；此步不改画像、作用域块与页面；
2. 按需读取 B 部分各项提到的页面与材料，此步不改动任何内容；
3. 起草全部提案，编成一张编号清单，一次交给用户：主线提案（新建主线及其背景说明、近况与迁入的页，把未成立的名字并入已有主线或去掉标签，拆分与合并）、画像提案（含作用域与泛化检验：至少两类不同情境成立才算全局）、领域规则提案（来自用户偏好与"教训"）、页面重组（补类型、拆分实体页、把复述环境的内容改为指针、合并重复页）、冲突条目、领域卫生与篇幅提示；清单末尾写明回复写法，如"1 2 4 确认，3 拒绝，5 暂缓，6 改成主线作用域"，回复未提及的项视为暂缓；
4. 按回复逐项执行，画像、作用域块与页面的改动只在用户确认之后：确认 → 写入画像或作用域块（条目下一行为当天日期与原话的注释），改写页面，并从候选中删除；拒绝 → 候选移入拒绝列表，加一条带"拒绝"标记、当天日期的出现记录，其他项原样保留；改成 → 按用户给的版本执行，视同确认；暂缓或未答 → 原样保留，下次整理照常再报；主线提案确认后，在主线文件中增删条目，迁移细节页并修正其他页的 `related` 引用，合并时把被并主线的作用域块条目移入目标主线；历史活动的标签不改写；
5. 结尾向用户展示写下的汇总与变更过的主线条目；
6. 在记忆仓库中提交，信息以 `consolidate:` 开头；没有改动时用 `--allow-empty` 提交。

上次整理是最近一次以 `consolidate:` 开头的提交（空提交同样生效）；没有时取 `init:` 提交；两者都没有时视为从未整理。报告开头写明所用的基准提交与预算情况。

整理报告在读取资源时现场计算，不保存中间状态。报告开头写明日期、仓库路径、基准提交与预算情况（`consolidation.budgetSeconds` 与判断是否在限时内算完）。报告分两部分：`## A. Automatic` 为主会话自行处理的材料，`## B. For proposals` 为需要用户拍板的材料，各类有英文标题；每类最多列 20 项，从最旧的开始，超出的写剩余数量与"处理完后再运行 `tacit-consolidate` skill"；没有内容的类别写 None.，标题始终列出。

| :--- | :--- | :--- | :--- |

增量规则：画像证据中的候选全部列出，不受基准限制；页面、原话与教训只列自上次整理以来的变化，所以被拒绝的页面提案在那一页没再变化前不会重复出现。每类最多 20 项，超出时写明剩余数量（见上文）。

违反格式或规则按文件列出，每项标明文件、位置（行号或小节）与问题说明：画像（红线缺"改为"、协作规则缺 `→`、无法识别的节或内容；领域块缺触发行、块内无法识别的三级标题、域名不合规、同一作用域重复成块）、候选文件（候选块缺"归属"、无法识别的出现记录行）、活动记录（条目不在日期标题下、无法识别的日期标题、日期格式错误）、`workstreams.md`（名字不合规、重名、缺背景说明、无法识别的行）。这些问题都是直接修正，列在 A 部分。长度与条数不属于格式问题，由 B 部分的篇幅提示与领域卫生列出。修正后再运行 `tacit-consolidate`，问题即消失；写入与索引不使用这些问题。

判断类别的做法：

- 疑似重复的页：变过的页与上次整理提交（没有则为 `init:`，都没有则为全部页）的工作区内容比较，内容不同的页文件计入，含新增、修改与未提交的修改，删除的页不计入。每个变过的页当作新页判断：选项为同主线的嵌入近邻，问题原文、选项数与 `decision.samePage` 阈值都与实时判断一致；同主线没有其他页时不提问。"确定"与"拿不准"两档收录并标明档位，"否定"不收；同一无序页对只报一次，若两页各判断一次而档位不同，取"确定"。
- 候选清理复用实时的同一偏好判断：问题原文、选项规模（近邻至多 9 条加"都不是"）与 `decision.samePreference` 阈值都不变，选项只取画像条目与拒绝列表，不含其他候选；两处都为空时不提问。
- 三档：确定 → 列为待清理；拿不准或否定 → 都不列。候选不因此被删除，仍留在 candidates.md。
- 决策模型或嵌入模型未配置时，待清理一类标为"未检查（未配置）"并说明原因；决策模型或嵌入模型不可用时标为"未检查"并说明原因。未配置的模型不提问，工作池不为它发出判断。

判断缓存、工作池与限时：

- 判断的概率按提问内容的哈希缓存在派生索引的 `judgment_cache` 表中。键为题型、问题说明、状态文本与按键排列的全部选项文本（含"都不是"）；值为模型返回的各选项概率。三档在读取时按当前阈值计算，改阈值不使缓存失效。只有整理读写缓存，实时写入的判断不读也不写。派生索引重建时缓存一并清空。
- 工作池：同时进行的判断不超过 `consolidation.maxConcurrency`（默认 5），一个完成就补发下一个。工作池由服务共享，多次整理之间的并发合计也不超过该数。模型进入冷却后，尚未发出的判断不再发出，计为"未检查（模型不可用）"；已在进行的照常完成。
- 限时：`consolidation.budgetSeconds`（默认 20）从各类别读取仓库并提交全部判断之后开始计时。到点时，已返回的结果写入报告；未返回的计为"未检查"，报告注明"还有 N 项未检查，再运行一次 `tacit-consolidate` 接着算"；尚未取得并发槽位的判断不再发出，已取得槽位的判断照常读取缓存，缓存未命中且未到点才发出。已在进行的判断不取消，跑完后写入缓存，再运行一次 `tacit-consolidate` 即可取得。读取仓库、解析与组装报告不计入预算。

## 10. 记忆指令与记忆 skill

### 记忆指令

两个记忆指令是 skill，与 `tacit-memory` 一样由代码生成到 `TACIT_HOME/skills/`，不读取记忆仓库：

| skill | 用途 | 正文依赖 |
| :--- | :--- | :--- |
| `tacit-remember` | 让主会话把本会话写进记忆（步骤见 `docs/prompts.md` 第 7 节） | 仅代码 |
| `tacit-consolidate` | 让主会话依据整理报告整理记忆仓库（见本文第 9 节） | 代码与记忆语言；报告经资源 `tacit://consolidation-report` 读取 |

两者 frontmatter 都含 `disable-model-invocation: true`，只由用户触发（触发方式见 `README.md`）。用户附在命令后的文字是本次的重点或附加要求，Agent 须遵从。`tacit-remember` 写完后列出写了什么：页面附页面标识，活动与画像条目附短码，候选附原文；不预先征求确认，与画像矛盾时先问用户。

### 记忆 skill

- 位置：`TACIT_HOME/skills/tacit-memory/SKILL.md`，由代码生成，用户不直接修改；成品结构与各部分的措辞见 `docs/prompts.md` 第 11 节。`prompts/skill.md` 存在且非空白时，末尾接 `## User conventions` 一节。
- `prompts/skill.md` 的长度与格式规则见 `docs/reference/configuration.md`「提示词文档」。
- 生成时机：服务启动时；`prompts/` 下的文件变化时；门面的 `GenerateSkills` 操作（返回三个 skill 各自的路径与是否写入），不需要服务运行；`connect` 绑定时也调用它。内容不变时不写文件。
- 两个记忆指令与记忆 skill 同时生成。`tacit-remember` 的成品只取决于代码，`tacit-consolidate` 只取决于代码与记忆语言；两者都不读取记忆仓库，也不读 `prompts/`，没有覆盖或追加文件，个人要求在触发时附上即可。
- 不进入自动备份。系统部分正文的措辞验证方式见 `docs/testing.md` 第 4 节。

## 11. 语言

| 读者 | 内容 | 语言 |
| :--- | :--- | :--- |
| 只给 Agent 看 | 工具与参数说明、服务端说明、记忆指令、工具返回与报错、整理报告、常驻区块外壳、发给决策模型的问题 | 固定英文 |
| 人要看或要改 | 记忆仓库的结构词、`config.yaml` 与 `prompts/rules.md` 模板、CLI 输出 | 随配置 `language` |
| 记忆内容 | 画像条目、细节页、活动记录、近期主线 | 按语言规范使用记忆语言 |

`language` 取 `zh` 或 `en`，缺省时系统界面语言为中文则取 `zh`，否则取 `en`。Agent 与用户交谈所用语言由画像决定，不由 TacitMemory 规定。

用户在 `prompts/` 下写的文档（`rules.md`、`instructions.md`、`resident.md`、`skill.md`）不检查语言，可用任一语言；语言规范只约束系统提供的文字。

## 12. 运行

### 客户端绑定

| 绑定写入 | 位置 |
| :--- | :--- |
| 常驻区块 | 上下文文件中起止标记之间的内容；上下文文件不存在时由 `connect` 创建，并记为 `createdContextFile` |
| skill 链接 | skill 目录下的 `tacit-memory`、`tacit-remember`、`tacit-consolidate` 三个链接，分别指向 `TACIT_HOME/skills/` 下的同名目录 |
| 绑定记录 | `TACIT_HOME/bindings.json`，每条含 `client`、`contextFile`、`skillsFolder` 与 `createdContextFile`；三个链接的位置由 `skillsFolder` 与固定的三个 skill 名推出 |

绑定 = 客户端名称 + 上下文文件 + skill 目录。名称只是标签：只允许小写字母、数字与连字符，长度 1 到 32，大小写不同视为同一名称并以小写记录。两个路径都必填、没有默认值；开头的 `~` 展开为用户目录，记录的是绝对路径。tacit 不读写任何客户端的 MCP 配置：`connect` 打印 MCP 端点（见 `docs/reference/mcp.md` 第 1 节），由用户在客户端中自行配置。命令的用法见 `docs/reference/cli.md`。

`connect` 的检查顺序，任一步拒绝都不写任何文件：名称合规；同名记录的路径不同则拒绝，提示先 `disconnect`；上下文文件的上一级目录存在；skill 目录存在（不存在时拒绝，不创建）；三个链接位置无冲突（不存在，或已是指向 tacit 对应 skill 的链接）；严格加载配置与画像；上下文文件是 UTF-8 且标记完整。通过后依次生成三个 skill、写常驻区块、建立缺失的链接、写绑定记录；其后某一步失败时撤回本次新建的链接。同名同路径重复执行是安全的：补齐缺失的链接，常驻区块按当前画像重写。

`disconnect --client <名称>` 只需名称，路径取自记录：移除常驻区块（文件变空且 `createdContextFile` 为真时删除文件）与指向 tacit 的三个链接，别人的同名项保留并报告；文件或链接已不在时逐项报告缺失，照常删除记录，以 0 结束；名称不存在时以 1 结束。只宽松读取语言，配置无效时照常工作。

共用：多个绑定可以指向同一个上下文文件或同一个 skill 目录（如两个客户端都读取 `~/.agents/skills`）。

- 路径比较用规范化后的完整路径（去掉末尾分隔符）。Windows 上忽略大小写，其他平台区分大小写。tacit 不解析目录联接与软链接：经两个不同入口指向同一目录的，被当作两处。
- `connect` 遇到已被其他绑定引用的上下文文件：不写第二个常驻区块，文件中始终只有一个；新记录的 `createdContextFile` 继承已有记录的值；报告「已由 `<名称>` 使用」。遇到已被引用的 skill 目录：已指向 tacit 的链接视为复用，报告同样说明复用了谁的路径。
- `disconnect`：仍被其他绑定引用的上下文文件不动，报告「仍被 `<名称>` 使用，保留」；无人引用时才移除常驻区块，文件变空且 `createdContextFile` 为真则删除。skill 目录同理：仍被引用时链接全部保留，无人引用时只删指向 tacit 的链接。
- 渲染所有常驻区块时按规范化路径去重：同一文件一次渲染只写一次、只产生一个结果。
- `status` 绑定栏：每条绑定注明与之共用路径的其他绑定；共用路径只检查一次，问题挂在第一个引用它的绑定上，其余绑定只注明共用。

链接的形式：Windows 用目录联接（不需要管理员权限），其他平台用软链接。三个位置中任一被占用（同名的目录或文件，或指向别处的链接）时，`connect` 整体拒绝并指出冲突的位置：三个链接一个都不建，skill 成品与其他文件也不写，不回退为复制。链接无法建立（如 `TACIT_HOME` 位于网络盘）时同样拒绝。`disconnect` 只删除指向 tacit 的链接本身，不跟随链接删除目标，skill 成品保留。

### 备份与恢复

- 所有备份（自动、手动、保险与云端）的打包方式相同，zip 内容为：记忆仓库（含 `.git`，不含 `.cache`）、`config.yaml`、`prompts/` 目录（含 `rules.md`、`instructions.md`、`resident.md` 与 `skill.md`）、`bindings.json` 与清单（`manifest.json`：生成时间、tacit 版本、`kind`、记忆仓库 HEAD 的提交号与提交说明、文件列表）。生成的记忆 skill（`skills/`）不进入备份。配置中含明文密钥时备份时提示。
- 自动备份（`backups/auto-YYYY-MM-DD.zip`）：每天第一次写入后生成一份，在写入队列中打包（作为写入槽的后台任务，打包期间的写入排队等待），只清理 `auto-*`，保留最近 `backup.keep` 份（默认 7；`0` 只关闭自动备份）。
- 手动备份（`backups/manual-YYYY-MM-DD-HHmmss.zip`）：`tacit backup` 立即生成，在写入队列中打包，拿到某次写入之后的完整状态；`--to <目录>` 写到指定目录（不存在则创建）。不计入 `backup.keep`，永不自动清理。
- 保险备份（`backups/pre-restore-YYYY-MM-DD-HHmmss.zip`）：恢复前自动生成，不清理、不上传。
- 时间戳为本地时间；同一秒内重名时拒绝，不覆盖已有文件。
- 云端备份（`tacit backup --remote`）：现场打包（在写入队列中，拿到某次写入之后的完整状态），上传为 `backup.webdav.url` 目录下唯一的 `tacit-backup.zip`，已存在则替换。只在执行命令时上传，不自动进行；本地不留副本，本地备份也不上传。zip 原样上传，不抹掉其中的密钥。
- 替换是原子的：先把 zip `PUT` 为 `tacit-backup.zip.part`，再 `MOVE` 到 `tacit-backup.zip`（`Overwrite: T`），上传中途失败时远端旧的那份保持不变。远端目录不存在时对目录 `MKCOL`（只建最后一级）后重试一次上传。服务不支持 `MOVE`（405 或 501）时报错"该 WebDAV 服务不支持原子替换"，不回退为直接覆盖。替换失败（上传或 `MOVE` 失败，含不支持 `MOVE`）时尽力删除 `.part`，删除失败不影响报错。
- 只使用通用 WebDAV 方法与 HTTP 基本认证；`username` 省略时不发送认证。每个请求（含响应体的读取）单独计时，超过 10 分钟即失败（硬编码），请求本身不重试（父目录缺失时的 MKCOL 与重传见上文）。错误信息说明阶段（连接、认证、上传、替换、下载）与 HTTP 状态码，不含密码与 URL 中的凭据。
- 每次尝试的时间与结果（成功，或失败原因）记入 `backups/remote.json`，`tacit status` 的备份栏据此显示最近一次云端备份；该文件不进入任何备份，状态显示不访问网络。
- 恢复（`tacit restore --from <zip> [--include-config] [--yes]` 本地备份，或 `tacit restore --remote [--include-config] [--yes]` 云端备份）由常驻服务执行，先预览：备份的生成时间、tacit 版本、`kind`、记忆仓库 HEAD 的提交号与说明、文件数，以及将被替换的内容。未加 `--yes` 时等待输入 `y`，其余输入一律取消（退出码 1）；标准输入不是终端时不等待，预览后以用法错误（退出码 2）结束，不发出执行请求。
- 拒绝且什么都不改的情况：清单缺失、无法解析或与内容不符；缺少 `memory/.git/`；条目不在允许的位置（只能是 `memory/`、`prompts/` 或根下的 `config.yaml`、`bindings.json`、`manifest.json`），或含 `..`、绝对路径。
- 确认后，执行顺序：等在途的后台任务结束 → 停止两个监听、关闭派生索引 → 生成保险备份（失败即中止）→ 把备份的 `memory/` 解压到 `memory.path` 内的隐藏暂存目录 `.tacit-restore-<id>`，当前内容移到同处的隐藏目录 `.tacit-previous-<id>`，暂存内容再移入（`memory.path` 目录本身保留，`.cache/` 不动；两个隐藏目录与记忆仓库同卷，移动均为重命名，不依赖 `memory.path` 的父目录所在卷；索引重建与备份都不把它们当作内容）→ 加 `--include-config` 时先把 `config.yaml` 写到 `TACIT_HOME/restore-<id>` 下的临时位置再替换，`prompts/` 整体替换（备份中没有的文件删除），并读取恢复回来的配置以确认能否加载，不能加载时照常完成并在结果中附错误（列出键路径），提示重启 `tacit serve` 前需修正 → 全量重建索引 → 删除两个隐藏目录与 `TACIT_HOME/restore-<id>`（上述删除在重建成功之后才执行，重建失败时仍可撤销换入）→ 恢复监听 → 加 `--include-config` 时重载提示词 → 使服务端说明失效 → 重新渲染常驻区块。
- `bindings.json` 永远不恢复。记忆仓库恢复到当前配置的 `memory.path`；恢复回来的 `config.yaml` 指向另一个路径时只提示，不搬目录。运行中的服务继续使用当前加载的配置。
- 换入之后任一步失败：记忆仓库逆序撤销换入，回到恢复前的内容，监听与索引照常恢复，错误附保险备份路径。
- 结果：保险备份路径、恢复后的 HEAD、索引重建的文件数、单元数与向量数；加 `--include-config` 时附"`config.yaml` 重启 `tacit serve` 后生效"；恢复回来的 `memory.path` 不同时附"重启后会指向 X，记忆仓库已恢复到 Y"。
- 云端恢复（`--remote`）：服务先把远端的 `tacit-backup.zip` 下载到 `backups/.download/tacit-backup.zip`（覆盖已有文件），校验后预览，预览中给出下载文件的本地路径。确认后以这个路径走上面的同一条恢复流程，所以确认的与恢复的是同一个文件；恢复成功后删除该文件，失败则保留以便排查。远端没有备份时提示"远端没有云端备份"；认证、连接与下载失败沿用云端备份的阶段提示。`.download/` 不是备份：不计入 `status` 的最近本地备份，也不被清理逻辑触及。

### 服务运行

- 单一常驻 HTTP MCP 服务，只监听 `127.0.0.1`，不做鉴权：本机视为可信边界。管理 API（`/api`）另有 Origin、Host 与 POST 的 Content-Type 三道防护，拒绝外部网页、DNS 重绑定与非 JSON 的 POST 请求（防护细节见 `docs/architecture.md` 第 5 节）。记忆工具的读写、服务端说明与整理报告资源的生成、后台的索引同步与常驻区块渲染、提示词重载共用一把读写锁：写入与后台任务之间串行，读取彼此共享；维护操作（`reindex`，以及恢复）独占，期间上述操作排队等待，完成后照常执行。服务未运行时记忆工具不可用，已写入的常驻区块仍然有效。
- 启动时按文件哈希比对增量同步索引；运行时监听记忆仓库，文件变化即同步对应索引，画像变化时重新渲染常驻区块。
- 索引记录表结构版本不一致时删除并全量重建；嵌入模型名或向量维度与记录不一致时只丢弃向量，全文索引保留，向量按文件哈希补齐。
- 日志的位置、格式与记录的事件见 `docs/operations.md`「日志」；各命令的用法与退出码见 `docs/reference/cli.md`。

### 客户端能力记录

- 服务在每个 MCP 请求上读取客户端的声明：名称、版本、协议版本、能力（`elicitation`、`sampling`、`roots`，以及实验性能力的键）与 `extensions` 的扩展标识。2026-07-28 版本的每个请求都带这些信息；更早的版本只在 `initialize` 中带，之后的请求不再记录。读取点在 `Mcp` 层，交给核心的只是普通值，核心不依赖 SDK 类型。
- 按"名称 + 版本"（不分大小写）保存最近一次所见的记录，写入 `TACIT_HOME/clients.json`，含最近连接的本地日期、协议版本、能力与扩展。它是运行状态，不属于记忆，不进入任何备份；写入与记忆的写入锁无关，不阻塞记忆工具。
- 只在首次见到某个客户端，或其协议版本、能力、扩展变化时写一条日志事件。同一天的重复请求不写文件、不记日志；跨天只更新日期。
- 写入失败只记日志，不影响请求；文件无法读取时从空记录开始。声明的文字先去掉控制字符并截断到 200 字符，状态报告与日志只显示处理后的文字。
- `tacit status` 的客户端栏列出各记录，最近连接者在前；服务未运行时读取同一文件。只做观察，不因客户端声明了某个扩展而改变任何行为。

## 13. 不做的事（v1）

| 不做 | 原因或归属 |
| :--- | :--- |
| 任务交接（上次停在哪） | 由客户端负责 |
| 保存原始会话 | 由客户端负责 |
| 客户端钩子（任何客户端）、后台补抽 | 写入依靠记忆规则、记忆指令与整理 |
| 服务内调用生成模型，包括后台汇总、抽取与反思 | 汇总、主线与提案由主会话在整理中完成 |
| 人格注入 | 语气由客户端与画像中的偏好决定 |
| 主动浮现往事 | 细节只在被提起时检索 |
| 按主线的常驻内容 | 主线约定与页目录只在 `recall workstream=<名>` 的主线简报中按需给出；常驻区块只列已有主线名 |
| 遗忘式删除，即按衰减删除记忆原文 | 遗忘以分辨率衰减实现（小节日期、未汇总周的降级显示），原文保留 |
| 使用统计进入检索排序；时间新近度加权 | 使用统计只供主线简报排序与整理报告；没有数据证明问题之前，检索结果保持稳定 |
| 知识图谱与时序图谱 | 记忆以 Markdown 页面与活动为单位，结构关系由 `related` 承担 |
| 判断问题措辞的改动与阈值重新测定 | 措辞与阈值绑定，改动须重新测定（见 `docs/prompts.md` 第 8 节） |
| 兼容旧格式、旧配置、旧工具参数，以及专门的迁移工具 | 封闭开发，只有使用者本人；旧键按未知键报错并点名键路径，迁移由新版本的第一次整理完成 |
| 每个领域生成一个 skill | 链接管理复杂，可靠性不更高；领域索引与 `kind=rules` 取代它 |
| 永久的条目编号 | 条目引用都是短时的，用短码 |
| 自动校准判断阈值 | 尚无标注数据，阈值手动配置 |
| MCP Skills 扩展、MCP Apps、elicitation 与 MRTR 的会话内确认，以及 Tasks 扩展 | 等所用客户端跟进后再做；现在只记录客户端声明的能力（见第 12 节「客户端能力记录」）。即时确认只用提示词实现 |
| 资源模板、订阅与 `list_changed` 通知 | 当前只有整理报告一个资源，无需；其他资源（如今天的活动）未做 |

## 14. 扩展

扩展时遵守：

- **所有入口经常驻服务**：TUI、Web UI 等新界面只调用常驻服务，不直接读写记忆仓库或索引。
- **规则只有一份**：新能力先在核心实现，再由各入口调用。
- **文件始终可直接编辑**：界面是便利，不是必需。
- **配置向后兼容**：新增配置项必须有默认值。

已知方向：Web UI（浏览、审核候选、检索调试）、TUI、以支持 logprobs 的对话模型实现决策模型接口、更多客户端支持、更换索引引擎。
