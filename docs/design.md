# TacitMemory 设计

本文档定义系统**做什么**：记忆如何分层、如何存储、何时写入、如何检索与注入，以及用户在命令行与 Web 界面上看到的行为。全局概览见 `docs/overview.md`，做某个决定的理由见 `docs/decisions.md`，记忆文件的写法、配置项与 MCP 接口见 `docs/reference/`，术语见 `GLOSSARY.md`。

## 1. 目标

让 Agent 像一个可靠的老朋友：记得用户的偏好与习惯，记得用户最近在做什么，提起具体的事时能想起细节；不记得时直说，不编造。

| 场景 | 用户说 | 期望的反应 | 依靠 |
| :--- | :--- | :--- | :--- |
| 新开会话 | "帮我写个脚本" | 直接按用户习惯的语言和方式回应，不用重新交代 | 画像（全局条目与领域索引，常驻区块） |
| 随口聊 | "最近有点累" | 把话题与记忆中的主线、决定、事故关联；关联改变答案时说明，与话题无关的记忆不提 | 主线（常驻区块）；最近 7 天的活动（服务端说明） |
| 提起一件事 | "上次数据库升级那个坑" | 先检索，再按记忆回答现象、根因和解法 | 细节页 |
| 提起没记过的事 | "上次部署那个问题" | 说没有这方面的记忆，再问细节 | 记忆规则 |
| 没提起 | 聊别的 | 不主动翻旧账 | 细节页不常驻 |
| 纠正后确认 | 用户纠正 Agent，或明确说出一条做法 | 问一次"要记成长期规则吗"，并说明理由；同意后才写入画像 | 会话内即时确认（记忆规则） |
| 主线开局 | "我们来看 photo-sorter 的发版" | 先 `recall workstream=photo-sorter` 读主线简报，再行动 | 主线简报 |
| 命中领域 | "帮我看下代理为什么慢" | 任务命中领域索引中某个领域的触发描述时，先用 `recall kind=rules domain=<标签>` 取该领域的规则 | 领域索引与 `kind=rules` |
| 临时问答 | "Python 里 `zip` 怎么用？" | 直接回答，不写入任何记忆 | 值得记标准（"不记"） |
| 顺口提到的偏好 | 与当前任务无关的一句偏好 | 不当场提交为候选，不打断当前任务 | 值得记标准 |

## 2. 原则

1. **只存环境里拿不到的信息**：记忆只保存 Agent 无法从代码、仓库文档、配置、客户端会话历史中获得，且会改变其行为的信息。
2. **按进入上下文的方式分层**：常驻内容在会话开始时就在上下文中，一定被看到；按需内容由 Agent 主动检索，前提是它知道去取。
3. **常驻只能依据开局信号**：会话开始时只知道工作目录、客户端和时间。只在特定话题下才相关的内容一律按需检索。
4. **文件是唯一真相源**：所有记忆都是人类可读、可直接编辑的 Markdown 文件，存放在独立的 Git 仓库中；派生索引随时可删除重建。
5. **理解与生成交给主模型，判断交给辅助模型**：写什么、怎么写、如何改写由主会话完成；常驻服务借助辅助模型做召回、排序和结构化判断，自身不调用生成式对话模型。
6. **实时写入求快，批量清理靠整理**：对话中的写入可以不完美；合并重复、精简画像、确认候选等工作在整理中完成。
7. **画像只是记忆**：常驻内容是可能过时的背景，优先级低于项目上下文文件与当前对话中的用户指令。

## 3. 三层记忆

| 层 | 内容 | 进入方式 |
| :--- | :--- | :--- |
| **画像** | 红线、协作规则、偏好、档案四节，每条带作用域（全局、主线、领域） | 全局条目与领域索引常驻：写入常驻区块；领域正文按需（`kind=rules`）；主线条目进入主线简报 |
| **近期活动** | 主线文件、按月存放的活动记录与汇总 | 主线的背景说明与近期摘要常驻：写入常驻区块；最近 7 天的活动常驻：写入服务端说明；活动记录按需 |
| **细节页** | 一件事或一个主题一页，按小节组织 | 按需：被提起时检索 |

## 4. 辅助模型

| 模型 | 职责 |
| :--- | :--- |
| 嵌入模型 | 生成向量，用于检索召回与判断前的近邻筛选 |
| reranker | 对检索候选精排，并按分数阈值过滤 |
| 决策模型 | 回答选择题，返回各选项概率 |

三者均可不配置：某个模型的映射缺失即为未配置，服务照常启动并按降级工作（见下文「降级」）。已配置的模型每个配置 `url`（完整请求地址，程序原样请求，不追加路径）、`model`，以及可选的 `apiKey`（有密钥时以 `Authorization: Bearer` 发送，没有则不发送任何认证头）。三个模型各按一种通用协议请求：嵌入模型为 OpenAI Embeddings，reranker 为 Cohere/Jina Rerank，决策模型为 System One（TypeSafe 的原生决策接口即其一个服务）。决策模型接口与具体模型无关，只包含选择题。发给决策模型的问题一律使用英文，被判断的内容保持原文。

每个模型可配置 `provider`，省略即为通用协议；写 `cloudflare` 则按 Cloudflare Workers AI 的格式收发，差异只在构造请求与读取响应两处，重试与冷却不分支。判断阈值与 `minRerankScore` 的默认值不随提供方或模型变化，换模型后的判断质量由使用者自行核对。

配置项的写法与校验见 `docs/reference/configuration.md`「`models`」。

### 判断

| 判断 | 题型 | 确定时 | 拿不准时 |
| :--- | :--- | :--- | :--- |
| 新画像候选与已有候选或拒绝列表中的某条是否同一偏好 | 选择 | 并入该候选；命中拒绝列表则不记录并告知 | 新建候选 |
| 新建细节页与同主线已有页是否同一件事 | 选择 | 拒绝新建，列出该页 | 允许新建，留待整理 |
| 新活动与当天已有活动是否同主题 | 选择 | 退回已有活动，要求合并 | 单独记录 |
| 新写入的画像条目是否与已有条目冲突、重复或取代它 | 选择 | 拒绝写入，返回冲突条目的节、原文与短码，与用户确认后改用 `replace` 改写它 | 写入，留待整理 |

- 选择题最多 10 个选项（含「都不是」）。选项取嵌入近邻或当天的活动：重复页取同主线的页，同主题取当天最新的 9 条活动，同一偏好取候选、拒绝列表与画像，画像冲突取全局与同作用域的条目；没有可比较的对象时不提问。被判断的内容保持原文。
- 服务只使用模型返回的概率，自行计算：选择题取最高概率。
- 每个判断在配置中设上下两个阈值，划出"确定 / 拿不准 / 否定"三档；未配置时用内置默认值（以真实中文样本测定）。选择题："都不是"的概率不低于其余任一选项时为否定；否则最高的选项不低于上阈值为确定，不高于下阈值为否定，其间为拿不准。实测中最高概率与第二名之差不改变任何结果，因此不参与划分。拿不准的情况不自动处理，由整理重新发现。
- 凭据检测不交给决策模型，只用内置正则，写入内容不会为了检测而离开本机。正则覆盖常见的密钥、令牌、私钥块、URL 中的 `user:pass@` 与 `password=` 一类赋值，占位符不算；没有格式特征的裸值拦不住，靠工具说明中「禁止写入凭据」的要求约束。被拒绝时只指出可疑片段的位置与开头 6 个字符；主会话确认无凭据后可带 `confirm_no_secret` 重新提交。

### 降级

辅助模型不可用时不拒绝写入：

| 不可用 | 写入 | 检索 |
| :--- | :--- | :--- |
| 嵌入模型 | 照常写文件并提交；判断因无法取近邻而跳过，按拿不准处理；向量在模型恢复后按文件哈希补齐 | 只走全文 |
| reranker | 不受影响 | 按合并顺序返回，不精排 |
| 决策模型 | 所有判断按"拿不准"处理 | 不受影响 |

未配置与不可用是两回事。未配置的模型从不被调用，不发请求、不进入冷却；它不在写入与检索的返回末尾注明，不进入服务端说明的状态提示；整理报告中依赖它的类别标为"未检查（未配置）"，`tacit status` 中显示"未配置"且不上色。不可用的模型是已配置、请求最终失败、正在冷却的模型，照常在返回末尾注明并进入服务端说明。去掉嵌入模型的配置时，派生索引中已存的向量保留，之后加回同一模型名不需要重新嵌入；换成另一个模型名时才丢弃向量并补齐。

降级时返回结果末尾注明（未配置的模型不注明）；启动时连不上任一已配置的模型不阻止启动，但在服务端说明与 `tacit status` 中提示。嵌入模型不可用时，沿用索引中记录的向量维度，恢复后再校验。没有嵌入模型时，`tacit reindex` 只重建全文并注明未配置嵌入模型。

辅助模型的每次请求先在请求内重试，偶发错误不直接降级：

- 重试：网络错误、单次超时、HTTP 429 与 5xx，一次请求最多尝试 5 次。HTTP 401/403、400/404/422 及其他 4xx，以及响应格式不对（无法解析、向量长度不一致、概率缺项等），不重试，直接算失败。
- 退避：两次尝试之间依次等 0.5、1、2、4 秒；429 带 `Retry-After` 时按其等待。
- 总时限：一次请求从第一次尝试起最多 20 秒，含各次尝试与退避。每次尝试有 5 秒单次超时，但被总时限截断。时限用完即算失败，不再发起新尝试，也不等待超出时限的退避。
- 冷却：只有请求最终失败（5 次用尽、遇到不重试的失败或用完总时限）才记一次失败，该模型冷却 30 秒，冷却期间不调用，状态提示列出它。冷却结束后的下一次请求照常尝试，成功一次即恢复可用。重试过程中的失败不改变健康状态。

次数、退避与总时限不做成配置项。代价已接受：模型挂起时，一次实时写入最多等 20 秒才判定失败并降级，期间写入锁被占用；进入冷却后才恢复为立即跳过。

画像冲突判断在决策模型或嵌入模型不可用时照常写入，并在回复末尾注明判断被跳过。

### 探测

`tacit probe [embedding|reranker|decision]` 由 CLI 直接读取 `config.yaml`，对配置中的模型各发一次真实请求。它不经常驻服务，因此服务未运行时也能用，也不要求记忆仓库已初始化；它不经模型客户端的重试与冷却，不改变任何模型的健康状态，不写服务日志。请求的构建与响应的读取与正式使用相同，格式不对（含 Cloudflare 的 `success` 为假）同样算失败。

请求体只含内置的固定英文文本：嵌入模型一句英文，reranker 一条英文查询与两段英文文档，决策模型一道两个选项的英文选择题。探测不读取、也不发送任何记忆内容。

探测只发一次请求、不重试，单次时限 20 秒。成功只说成功；失败给出 HTTP 状态码、响应体前 500 个字符与耗时，网络错误与超时给出错误类别与耗时。输出与报错不含任何密钥值：响应体中出现的密钥以 `***` 代替。输出开头写明探测的是 `config.yaml` 中的配置。不带参数时依次探测三个模型，未配置的模型显示"未配置，跳过"且不算失败；明确指定却未配置的，退出码为 1。

## 5. 存储

```text
<记忆仓库>/
├── persona.md              # 画像
├── candidates.md           # 画像候选与拒绝列表
├── workstreams.md          # 主线：背景说明与近期摘要
├── recent/YYYY-MM.md       # 活动记录（按月），末尾可有汇总
├── pages/<主线>/<slug>.md  # 细节页；pages/_topics/ 为专题
└── .cache/                 # 派生索引，不进 Git
```

- 所有记忆都是可直接编辑的 Markdown，放在独立的 Git 仓库里；派生索引随时可删除重建。
- 每次经服务的写入只提交本次写入的那个文件；整理的提交由主会话完成，以 `consolidate:` 开头，服务据此识别上次整理。
- 服务改文件时只改要改的那几行，其余字节原样保留；格式不对时照常读取，问题只在整理报告里列出。
- 服务返回条目时附带短码（内容哈希的前 6 位），后续调用凭短码引用；条目一改，旧短码即失效。短码不写进文件。
- 各文件的写法、句式与示例见 `docs/reference/memory-files.md`。

## 6. 写入

### 入口

写入有三个入口，不使用客户端钩子，也不做会话结束后的后台补抽：

1. **记忆规则**：写在服务端说明中，主会话在对话中当场执行，包括用户纠正后的即时确认（见本节「画像」）；
2. **记忆指令** `tacit-remember`（skill）：用户在压缩上下文、退出前或认为重要时触发；
3. **整理** `tacit-consolidate`（skill）：用户定期触发，主会话依据整理报告写汇总与主线、起草画像提案与页面重组（见第 9 节）。

主会话未遵守规则、用户也未执行指令就结束会话时，该段内容不会被记住。这是明确接受的代价。

### 值得记标准

`prompts/rules.md` 分 `Worth recording`（值得记）与 `Not recorded`（不记）两节（条数上限见 `docs/reference/configuration.md`「提示词文档」），原样写入服务端说明。文件不存在时使用内置默认：它只给 Agent 看，所以是英文，与记忆语言无关；服务不生成该文件。旧位置 `TACIT_HOME/rules.md` 不再读取。

默认值得记（大意，原文为英文）：用户纠正或打断 Agent；方案拍板（保留用户原话）；查明根因的排错（含试过但无效的做法）；新的环境事实；用户明确要求记下。默认不记：常规的写代码、改错字、看日志；能从代码、仓库文档、配置中查到的内容；临时问答、一次性查询和闲聊，没有结论时。

### 通用规则

- **先检索再写**：命中已有页则更新该页，未命中才新建；一件事只对应一页。
- **读取不修改**：检索与读取不改动任何文件。
- **保留来源**：写入内容附带日期，必要时附用户原话。
- **标明机器与适用条件**：与环境有关的条目在正文中写明适用的机器名，不写「本机」「这里」等相对指代；机器清单记入画像「档案」节。
- **不写凭据**：见第 4 节。

### 细节页

- 页面标识的第一段用已成立的主线；对不上时放进专题，slug 以事项名开头，便于整理按前缀把同一件事的专题页提议为主线。这条只由提示词约束，服务不拦未成立的名字。
- 新建时提交整页，必须给出 `type`；服务先用决策模型判断是否与已有页重复。
- 更新以小节为单位：新增或替换一个小节、删除一个小节、修改页头（追加别名、改标题、`related` 或 `type`）。替换与删除须带原小节的短码。
- `section` 填的是本页某小节的短码（忽略大小写与首尾空白，且本页没有同名小节）时，`upsert_section` 与 `delete_section` 拒绝并给出该小节的标题；下一步：`section` 填小节名，`hash` 填该短码。不论 `hash` 是否已填都拒绝，不写入也不提交。像短码但不属于本页的值照常按小节名处理。
- 不提供整页重写；大幅调整在整理中直接改文件。

### 近期活动

- 写入时机：一件主事有了结论（定了决定、查明根因、阶段目标完成）时写一条（带所属主线）；每条主线每个会话至多一条，之后有进展用 `replaces` 改写。
- 一条活动写"人在做什么、想通了什么"，不写"改了哪些文件"。
- 写入 `recent/YYYY-MM.md`，按本地日期定位当日标题；缺标题时追加到文件末尾。写入只改动新增的条目与来源注释，文件其余字节不变。
- 服务在条目下的注释里写上本机的机器名（机器标记），`write_recent` 不接受机器参数；带原话时与原话写在同一行注释里。机器标记不参与短码。最近 7 天的活动与 `recall` 返回的活动在日期后以 `(机器名)` 标出，记忆页的活动也显示机器名；没有标记的旧活动不显示。
- 文本限一行，不设长度上限，不以 `[` 开头；原话同样限一行，且不含 `-->`；主线名小写并校验。服务不拦未成立的主线名，提示词要求只用已成立的主线，对不上时不标注。
- 写入成功时，回复只有一行：新短码（改写时为改写后的短码）。回复不附主线与活动列表。
- 与当天已有活动同主题时（按第 4 节的选择题与三档，阈值为 `sameTopic`），服务不写入，以普通回复（非错误）退回该活动及其短码；主会话写出合并后的一句，带 `replaces` 重新提交。决策模型不可用时照常写入，回复中注明未检查；带 `replaces` 时不做同主题判断。
- `replaces` 只指向当天的活动：短码须是当天某条的短码。其他日期、已过期（条目改写后旧短码即失效）或不存在的短码都被拒绝，拒绝时列出当天的活动及其短码。改写在原位替换条目正文与主线标注；机器标记换成本机；带 `source` 时替换原话，否则保留原话。改写与新增经同样的参数校验与凭据检测，不做同主题判断，返回新短码，提交信息为 `recent: replace <短码>`。
- "每条主线每个会话最多一条"只写在记忆规则中，服务不强制。
- 主线不经 `write_recent` 写入：`write_recent` 没有 `op`、`items`、`hash` 参数，传入即按未知参数拒绝，下一步说明主线由 `tacit-consolidate` 维护。主线由整理时主会话直接编辑 `workstreams.md` 维护（见第 9 节）；`workstream` 参数不要求主线已成立，未成立的名字照常写入与检索。

### 画像

| 操作 | 允许的条件 |
| :--- | :--- |
| 新增协作规则、偏好或档案 | 用户明确要求记住；或用户纠正、打断 Agent，或明确说出一条做法，且 Agent 问过一次并得到同意 |
| 新增红线 | 只能由用户明确提出 |
| 替换、删除 | 用户明确要求修改或删除某一条 |
| 观察到的偏好或规则 | 只能提交为画像候选，并标明归属节 |

这些条件写在记忆规则中。服务对新写入的条目做冲突判断，见第 4 节。

`add` 的校验与写入：
- 不校验句式：红线说明改做什么、协作规则写成"情境 → 做法"是记忆 skill 给的写作建议，写入时不拒绝，整理报告也不列出。
- `text` 与 `source` 各限一行：不含 `\r`、`\n`、U+2028、U+2029、U+0085，即编辑器会显示为换行的字符；`source` 不含 `-->`；`text` 不设长度上限。
- `scope` 缺省为 `global`，可取 `workstream:<名>` 或 `domain:<标签>`，名称不合规时拒绝。`trigger` 只在第一次写入一个新领域时必填（缺少则拒绝，下一步要求补上），须为一行；已有领域与其他作用域忽略它。新领域块的触发行与首条写在一起。
- 条数不设上限：全局四节、一个领域的条目与领域个数都不限，`add` 不因数量被拒。写入后回复写明所在节或领域的当前条数。过长或条目过多由整理报告的篇幅提示与领域卫生列出，由用户决定是否精简。
- `add` 写入对应作用域块的对应节末尾；块或节缺失时按上面的顺序补回。一次写入只提交 `persona.md`。
- 追加在该节末尾，下一行写 `<!-- 当天日期 quote「…」 -->`；节标题缺失时按四节标准顺序补回：补在前面最近的已有节之后，前面都没有时补在后面最近的已有节之前，四节都没有时补在文件末尾；与写入同一次提交。
- `replace` 凭短码原位替换条目及其原话注释：条目留在原节，按原节校验句式与长度，并做画像冲突判断（排除被替换的条目）；新注释为当天日期与新原话，原条目没有注释时新增一行。提交信息为 `persona: replace <新短码>`；结果与原条目完全相同时不写入、不提交。
- `delete` 凭短码删除条目及其续行与原话注释，不需要原话；回复被删除的条目原文。提交信息为 `persona: delete <短码>`。
- `replace` 与 `delete` 凭短码在任一作用域中定位；`replace` 保持条目原作用域，`delete` 删除后其所在的领域或主线块保留标题与触发行，即使已无条目。
- `propose` 的校验与写入：归属节为红线时拒绝，"下一步"为先问用户、明确同意后再 `add`；句式与单行校验同 `add`（按归属节）；`scope` 的校验同 `add`，`trigger` 不适用（候选不创建领域），传入即按未知参数拒绝；凭据检测覆盖原文与原话；不设条数上限。
- `propose` 追加在 `Candidates` 一节末尾，写成三级标题（原文）、`Belongs to: <画像节>` 与一条出现记录；"候选"标题缺失时补回拒绝列表之前，没有拒绝列表时补在文件末尾，与写入同一次提交。只提交 `candidates.md`，不重新渲染常驻区块；回复写明新建的候选及其作用域（全局时为 `scope: global`），不报告出现天数，不返回短码。
- `propose` 先做同一偏好判断（第 4 节）：命中候选则并入，保留该候选原有的作用域（回复写明它），在其出现记录末尾追加当天的原话，同日已有出现记录时不写入、不提交；命中拒绝列表或画像则不写入，告知拒绝时的日期与原话或画像中的短码。三处都为空时不提问，直接新建候选。

## 7. 检索

| 参数 | 必填 | 说明 |
| :--- | :--- | :--- |
| `query` | 与 `page` 二选一 | 自然语言查询，用记忆语言书写；`kind` 为 `persona` 或 `rules` 时忽略 |
| `page` | 与 `query` 二选一 | 页面标识：读取整页；不能与 `kind` 为 `persona` 或 `rules` 同用 |
| `workstream` | 否 | 只在该主线中检索；与 `query`、`page` 都不给时，返回该主线的主线简报（见下）；不能与 `kind` 为 `persona` 或 `rules` 同用 |
| `from`、`to` | 否 | 日期范围，由主会话把"上周"之类换算成日期；不能与 `kind` 为 `persona` 或 `rules` 同用 |
| `kind` | 否 | `pages`、`activities`（省略时两者都检索）、`rules`（领域规则）或 `persona`（整份画像）；后两者不检索 |
| `domain` | 否 | 领域标签，只与 `kind=rules` 搭配；省略时返回全部领域的规则 |

流程：

1. 筛选：页面按所属主线与页面日期区间（与查询区间重叠即保留），活动按主线标注与所在日期；指定 `workstream` 时，未标注主线的活动不出现；
2. 全文检索（FTS5，BM25）与向量检索（余弦）各取前 30 条。全文检索中，中文切成相邻两字一组，每段末尾的字另作一个词；英文与文件名按 `unicode61` 规则在标点处切分，查询以短语匹配，`env.ps1`、`UTF-8` 这类写法仍可命中；查询中单独的汉字（如「改 bug」中的「改」）匹配该字的任意一次出现，与其他词一样按 BM25 排序。向量单位为：每个小节、每页的 `title + aliases`、每条活动（连同主线标注）。小节送去嵌入与精排的文本前面加上页面标题（不含别名），只写了做法、没提主题的小节也能凭标题被找到；全文检索与结果显示仍只用小节本身；
3. 用倒数排名融合（RRF）合并，取前 30 条交 reranker；
4. 丢弃低于分数阈值的结果，返回前 5 条（均可配置）；某页在此刻读不出来时跳过它，由后面的结果补上；一条不剩时明确返回英文 `No relevant memory.`。

每条汇总是一个活动检索单元：按其所在周或月的首末日期筛选（与查询区间重叠即保留），没有主线标注，结果标明是汇总及其为周或月（`summary, week starting 2026-11-02`）。结果以小节和单条活动为单位，每条结果标明是页面还是活动。同一页命中的多个小节合为一条结果，每个小节返回全文及短码，并列出该页其他小节的名字；页面级命中按开头几个小节呈现。每条活动单独一条结果，显示日期、短码与所属主线（无主线则省略），随后是活动正文。

画像与候选不进入检索结果，无论 `kind` 为何；它们的向量只供两项判断取嵌入近邻。

`kind=persona` 与 `kind=rules` 不检索，直接读取画像：

- `persona` 返回整份画像：全局四节（各附条数），然后是领域块（按标签排序，标题附条数与触发描述），再是主线块（按名称排序）；
- `rules` 返回领域规则：给 `domain` 时只返回该领域的触发描述与全部条目，不给时按标签排序返回全部领域。`domain` 不是画像中的领域时拒绝，并列出已有的标签。

两者的每条都附短码，即 `write_persona` 的 `replace`、`delete` 接受的短码；原话注释不输出。没有任何条目时返回 `No relevant memory.`。两者不计入使用统计。`domain` 只能与 `kind=rules` 搭配；`kind=persona` 与 `page` 同时出现，或与 `domain` 同时出现，`kind=persona` 或 `kind=rules` 与 `page`、`workstream`、`from`、`to` 同时出现，都按参数错误拒绝，下一步说明怎样调用。

小节日期：每个小节标题后附最后修改日期（检索结果与整页读取都是）。派生索引为每个小节记录内容哈希与最后变化日期：同步时内容哈希（去掉末尾空白后）变化的小节更新为当天，其余保持不变；全量重建时取该文件最近一次提交的日期，未提交的新文件取当天。

使用统计：`recall` 返回的每个检索单元计数加一并记录当天为最近返回日期，整页读取时该页每个小节各加一。统计只存在派生索引中，`reindex` 与恢复清空；页面或月文件被编辑后重新同步时，已有计数按小节名、短码或汇总周期带回，不清零；检索排序完全不读取它，主线简报与整理报告用它排序。Web 界面的记忆浏览与检索追踪都不计数：追踪与 `recall` 走同一条检索管线，只是不记录返回。

主线简报：只给 `workstream`（不给 `query` 与 `page`）时返回该主线的简报，依次为：

1. 主线名；已成立时其后为背景说明与近期摘要两行（`Background:`、`Recent:`，近期摘要缺省则略去），未成立的名字不列出这两行；
2. 主线约定：主线作用域的画像条目（连同其续行）；
3. 未决事项：各 `work` 页 `Leftovers` 小节的非空行，附页面标识；
4. 页目录：按类型分组，依次为有效决定、已知坑、工作、实体、未分类（缺少类型的页）。`decision` 页的 `Overturned` 小节非空时不列入有效决定，归入一行「已推翻」，只列标识。每页一行：标识、标题、别名、最近修改日期。组内按小节日期中最新者倒序，同日按使用次数倒序；没有页的组整组省略；
5. 最近 3 条活动：该主线标注的活动，新到旧；
6. 最近一次周汇总：该主线活动所在的周中，最近一个有汇总的那一周。

`from`、`to` 与 `workstream` 合用时，限定页面（按页头日期区间，与检索筛选相同）与活动的日期区间；与 `kind` 同给时按参数错误拒绝。主线既无页面也无活动时返回英文 `No relevant memory.`。

简报总长不超过 `limits.brief`。超出时只从最旧的页目录条目起截断，并注明省略了多少条；页目录全部省略后仍超出（约定、未决事项、活动与汇总本身超长）时，按上限截断末尾并注明。简报是读取：不改文件，列出的每个页（页目录、已推翻的决定与未决事项中的页）计一次使用统计。

## 8. 注入

常驻内容按变化频率分两路：

| 通道 | 内容 | 何时更新 |
| :--- | :--- | :--- |
| 常驻区块 | 全局画像、领域索引、主线 | 绑定时；画像、主线文件或活动记录变化时；`prompts/resident.md` 变化时；本地日期变化时 |
| 服务端说明 | 核心规则、通用规则、语言规范、值得记标准、最近 7 天活动、状态提示、整理提示 | 所依据的记忆、`prompts/` 下的提示词文档或状态变化后重新生成，客户端连接时下发 |

两者都在下一次会话生效，正在进行的会话不会重新加载。

### 常驻区块

- 由 `<!-- tacit:begin … -->` 与 `<!-- tacit:end -->` 界定，内部以 `<user_memory>` 包裹；起止标记不完整或不唯一时拒绝改写；结果未变不写文件；区块外的内容从不改动。
- 外壳两段与四节引导语来自 `prompts/resident.md`，整份替换内置默认；文件缺失时用内置默认（即现有文字）。起止标记、`<user_memory>` 标签、开头的机器行、节标题与画像条目仍由服务生成。格式与校验见 `docs/reference/configuration.md`「提示词文档」。
- 组成依次为：机器行（`<user_memory>` 内部首行，`Machine: <name>`；配置了 `machine.description` 时为 `Machine: <name> — <description>`）；外壳；全局四节；`situational_rules`（每个领域一行：标签、触发描述、条数，全部领域都列出；领域与主线条目的正文不进入常驻区块）；`workstreams`（只列已成立的主线：活跃的一行 `- 名字: 背景说明 Recent: 近期摘要`，安静的一行 `- 名字: 背景说明`；活跃的在前，按最近一次活动的日期由新到旧，安静的在后，按名称排序；活跃指最近 28 天内（本地日期，含当天）有标注该主线的活动，28 天为代码常量；没有已成立的主线时整节省略）。无内容的节整节省略；两个生成节的引导语可由 `resident.md` 给出。常驻区块不设长度上限。
- 计算所用的日期是服务的本地日期。服务在每个本地午夜重新渲染，窗口才会随日期前移。
- `resident.md`、`persona.md`、`workstreams.md`、活动记录（`recent/`）或主线目录（`pages/` 下一层）变化后，去抖重渲染所有已绑定文件中的常驻区块；本地日期变化时同样重渲染。渲染彼此串行，失败只提示。连接时使用当前的 `resident.md`。
- 渲染时去掉来源注释；节标题使用英文，条目保持记忆语言。
- 每次渲染都重新读取 `bindings.json`，因此运行中的服务能感知新的绑定；`connect` 在绑定时立即渲染一次。

### 服务端说明

- 组成：开场、核心规则（`prompts/instructions.md`，缺失时为内置默认）、通用规则（代码提供，始终在核心规则之后）、语言规范与值得记标准是固定部分；其后是最近 7 天活动、状态提示与整理提示。提示词文档的文件校验与运行中保存的处理见 `docs/reference/configuration.md`「提示词文档」。
- 固定部分合计不超过 3000 字符。启动时超出则拒绝启动，报告超出的字符数，并列出可精简的文件（`rules.md` 与 `instructions.md` 中存在的那些）。
- 服务端说明总长不超过 4000 字符。生成时超出则依次截断最早的活动；固定部分、状态提示与整理提示不截断。
- 记忆规则各条的内容与职责见 `docs/dev/prompts.md`「服务端说明」。
- 语言规范：记忆内容与检索语句使用记忆语言；用户原话、代码、路径、命令与专有名词保持原样。
- 值得记标准：`prompts/rules.md` 两节的条目原样写入，文件不存在时使用内置默认；修改或删除 `prompts/rules.md` 后，下一个会话生效。
- 状态提示：列出冷却中的辅助模型（请求重试后仍失败才进入冷却，见第 4 节）与因不是 UTF-8 而被跳过的页面文件、活动记录文件、画像与候选文件；无问题时省略。服务不为探测而调用模型。
- 最近 7 天活动：活动记录中最近 7 天的全部条目（新的在前；超出总长时仍从最早的活动截起），每条前补日期与主线标注，包在 `<recent_activity days="7">` 标签中作为数据；活动中不附短码。主线在常驻区块中，不在这里。
- 整理提示：该整理时出现，位于服务端说明末尾。以下任一情况即该整理，各自独立生效：距上次整理达到 `consolidation.remindAfterDays` 天（默认 3；两个提交都没有时视为到期）；存在未汇总的已完成周；新候选达到 `consolidation.remindCandidates`（默认 2）；主线为空。新候选是在上次 `consolidate:` 提交那天之后有出现记录的候选，从未整理过时全部候选都算；整理时留着继续观察的候选因此不会让提示马上回来，再次出现才算。内容：距上次整理的天数（以最近的 `consolidate:` 提交为准，没有则以 `init:` 提交为准；两者都没有时写明从未整理过），仅在非零或为空时列出的未汇总周数、候选数（整理过时附新候选数）、格式问题数、主线为空，以及一句说明用户可以运行 `tacit-consolidate` skill 开始整理。只有格式问题时不出现。生成时不调用任何模型，不显示重复页与冲突条目的数量；`tacit status` 的待处理问题与此共用同一份计算。它属于动态部分，不计入固定部分的长度上限，计入总长，与状态提示一样不截断。

## 9. 整理

用户在任意目录通过 `tacit-consolidate` skill 开始整理（触发方式取决于客户端，附加要求可省略）。该 skill 的正文只取决于代码，不读记忆仓库，依次包含：开场（现在开始整理；先读取资源 `tacit://consolidation-report`，读不到就停下请用户运行 `tacit serve`；记忆仓库的绝对路径；直接用绝对路径改文件，并在该目录中执行 git，不要求当前目录是记忆仓库）、六个步骤，以及作用域块、候选块、拒绝列表条目与汇总行的示例（示例里的结构词即文件格式，一律英文）。用户附在命令后的文字可限定本次的范围，如“只做汇总”（只写汇总，不出提案）；“只处理主线”或“只处理主线 名字”（只做主线材料与主线提案，其余类别不动）用于直接指定一条主线。整理报告不在正文中，由该资源现场返回（见 `docs/reference/mcp.md`「资源」）。主会话依据报告直接修改记忆仓库中的文件，最后在记忆仓库中提交，提交信息以 `consolidate:` 开头。

是否该整理也对外提供，供客户端的定时任务询问：管理 API 的 `GET /api/consolidation` 与命令 `tacit consolidation` 只回答是否该整理，不附原因与计数；命令不论答案如何都以 0 结束。判断与整理提示完全相同，每次请求时现场计算，不调用模型。记忆仓库的历史读不出时返回错误，不答「否」。服务只给出信号：何时询问、得到答案后做什么，由客户端决定，服务不推送、不自行开始整理。

整理步骤（英文，按顺序）：

1. A 部分（`A. Automatic`）直接处理、不问用户：修正标为直接修正的格式问题，删除待清理的画像候选，按材料写周汇总与月汇总行，依据主线材料只重写各条已成立主线的近况（背景说明不改）；此步不改画像、作用域块与页面；
2. 按需读取 B 部分各项提到的页面与材料，把 B 部分视为待甄别的原始线索，此步不改动任何内容；
3. 先过滤假阳性（核对后非同一件事或不冲突的 `Uncertain`/`Unsure` 项）、健康页面与非必要微调，再起草高信噪比提案，编成一张聚焦的编号清单一次交给用户（主线提案、画像提案含作用域与跨至少两类情境的泛化检验、建议清理的一次性噪声候选、领域规则提案、页面重组、冲突条目、确有必要的领域卫生与篇幅提示；同质低风险项可打包成单条编号，每条附推荐动作与简短理由）；清单开头简要预览第 1 步已写下的周/月汇总与主线近况，注明用户可在同一条回复中一并要求调整；清单末尾写明回复写法，如"1 2 4 确认，3 拒绝，5 暂缓，6 改成主线作用域"，回复未提及的项视为暂缓；没有需要决定的项时只展示预览并说明，跳过第 4、5 步直接提交；
4. 按回复逐项执行，并应用用户对第 1 步汇总或主线近况的调整；画像、作用域块与页面的改动只在用户确认之后：确认 → 按提案写入画像或作用域块（条目下一行为当天日期与原话的注释），改写页面，并从候选中删除（若提案本身是清理噪声候选，确认则将其移入拒绝列表）；拒绝 → 候选晋升提案移入拒绝列表，加一条带"拒绝"标记、当天日期的出现记录，其余项及清理噪声候选的拒绝保持原样；改成 → 按用户给的版本执行，视同确认；暂缓或未答 → 原样保留，下次整理照常再报；主线提案确认后，在主线文件中增删条目，迁移细节页并修正其他页的 `related` 引用，合并时把被并主线的作用域块条目移入目标主线，并清理空出的旧主线目录或空作用域块；历史活动的主线标注不改写；
5. 结尾向用户确认已应用的改动，并展示第 4 步调整过的汇总与主线条目；
6. 在记忆仓库中提交，信息以 `consolidate:` 开头；没有改动时用 `--allow-empty` 提交。

上次整理是最近一次以 `consolidate:` 开头的提交（空提交同样生效）；没有时取 `init:` 提交；两者都没有时视为从未整理。报告开头写明所用的基准提交与预算情况。

整理报告在读取资源时现场计算，不保存中间状态。报告开头写明日期、仓库路径、基准提交与预算情况（`consolidation.budgetSeconds` 与判断是否在限时内算完）。报告分两部分：`## A. Automatic` 为主会话自行处理的材料，`## B. For proposals` 为需要用户拍板的材料，各类有英文标题；每类最多列 20 项，从最旧的开始，超出的写剩余数量与"处理完后再运行 `tacit-consolidate` skill"；没有内容的类别写 None.，标题始终列出。

| 类别 | 部分 | 计算方式 | 状态 |
| :--- | :--- | :--- | :--- |
| 主线提案材料 | B | 全部确定性生成，不调用模型：专题 `pages/_topics/` 中同前缀的页：按 slug 的首段分组，每组至少 3 页时列出该组仍然共有的最长整段前缀与各页标识（提示词要求专题页的 slug 以事项名开头，新主线主要从这里提议）；未成立的主线名（`pages/` 下的目录名与上次整理以来的活动的主线标注中，不在 `workstreams.md` 里的名字，各附页数与活动数；提示词不让 Agent 自造主线名，这里收的是手改或未照做的写入）；上次整理以来不标注主线的活动。只看现有目录与基准以来的活动，因此被合并掉的旧主线标注不会反复出现 | 已实现 |
| 疑似重复的页 | B | 自上次整理以来变过的页（含未提交的修改，不含删除）与同主线嵌入近邻（至多 9 页、不含自身）交决策模型判断，问题与阈值沿用实时新建页面时的重复页判断；"确定"与"拿不准"两档收录并标明档位，同一无序页对只报一次 | 已实现 |
| 互相冲突的画像条目 | B | 上次整理后新增或改写的条目（按短码，含未提交的修改），与跨四节的近邻（至多 9 条、不含自身）交决策模型判断，沿用实时画像冲突的问题与阈值；"确定"与"拿不准"两档收录并标明档位，同一对只报一次 | 已实现 |
| 画像证据 | B | 全部候选（作用域、归属、出现记录与原话，不受基准限制），以及自上次整理以来新增活动的原话（活动记录中紧随条目的注释里的 `quote「…」`，附活动短码与主线）；按日期从最旧的开始 | 已实现 |
| 教训 | B | 自上次整理以来新增或变化的 `incident` 页的 `Lesson` 小节原文，附页面标识与日期 | 已实现 |
| 变化过的页 | B | 自上次整理以来变过的页文件（含新增与未提交的修改，不含删除）；附路径、类型（缺失时写 `untyped`）、大小、各小节及其最后修改日期、`related` 与使用次数，不附正文；按最近修改日期从最旧的开始 | 已实现 |
| 领域卫生 | B | 只有 1 条的领域（确定性判定，不调用模型） | 已实现 |
| 篇幅提示 | B | 画像的全部条目与上次整理以来新增的活动超过 `consolidation.hintEntryLength` 的，附位置与长度；常驻区块总长超过 `consolidation.hintResidentLength` 时一行说明。只提示，不拒绝写入；整理 skill 第三步提议改短，用户确认后执行 | 已实现 |
| 违反格式或规则 | A | 生成报告时重新解析全部记忆文件：细节页的 YAML 头、`title`、`aliases`、`related`、文件名与小节重名；文件是否为 UTF-8；画像、候选文件、活动记录与 `workstreams.md` 的问题（见下；格式问题中已无上限项） | 已实现 |
| 待清理的画像候选 | A | 每条候选（不分出现天数）与画像、拒绝列表的嵌入近邻做同一偏好判断；"确定"者列为待清理，写明相同的画像条目（短码）或拒绝列表条目 | 已实现 |
| 待汇总的周 | A | 已结束（最后一天早于今天）、有活动但没有汇总行的 ISO 周（经 `SummaryCalendar.Unsummarized`），从最旧的开始；附该周全部活动原文，按主线分组，没有主线的归为"其他"；写明汇总行写入的月文件 | 已实现 |
| 待汇总的月 | A | 已结束、有活动但没有汇总行的自然月，附写入该月文件的周汇总 | 已实现 |
| 主线材料 | A | 每条已成立、在上次整理之后（含进行中的周）有标注活动的主线：当前的背景说明与近况，以及这些活动；没有新活动的主线不列；没有已成立的主线时写明一行说明 | 已实现 |

增量规则：画像证据中的候选全部列出，不受基准限制；页面、原话与教训只列自上次整理以来的变化，所以被拒绝的页面提案在那一页没再变化前不会重复出现。每类最多 20 项，超出时写明剩余数量（见上文）。

违反格式或规则按文件列出，每项标明文件、位置（行号或小节）与问题说明：画像（无法识别的节或内容，包括写成其他语言的节名；领域块缺触发行、块内无法识别的三级标题、域名不合规、同一作用域重复成块）、候选文件（候选块缺"归属"、无法识别的出现记录行）、活动记录（条目不在日期标题下、无法识别的日期标题、日期格式错误）、`workstreams.md`（名字不合规、重名、缺背景说明、无法识别的行）。这些问题都是直接修正，列在 A 部分。长度与条数不属于格式问题，由 B 部分的篇幅提示与领域卫生列出。修正后再运行 `tacit-consolidate`，问题即消失；写入与索引不使用这些问题。

判断类别的做法：

- 疑似重复的页：变过的页与上次整理提交（没有则为 `init:`，都没有则为全部页）的工作区内容比较，内容不同的页文件计入，含新增、修改与未提交的修改，删除的页不计入。每个变过的页当作新页判断：选项为同主线的嵌入近邻，问题原文、选项数与 `decision.samePage` 阈值都与实时判断一致；同主线没有其他页时不提问。"确定"与"拿不准"两档收录并标明档位，"否定"不收；同一无序页对只报一次，若两页各判断一次而档位不同，取"确定"。
- 候选清理复用实时的同一偏好判断：问题原文、选项规模（近邻至多 9 条加"都不是"）与 `decision.samePreference` 阈值都不变，选项只取画像条目与拒绝列表，不含其他候选；两处都为空时不提问。
- 三档：确定 → 列为待清理；拿不准或否定 → 都不列。候选不因此被删除，仍留在 candidates.md。
- 决策模型或嵌入模型未配置时，待清理一类标为"未检查（未配置）"并说明原因；决策模型或嵌入模型不可用时标为"未检查"并说明原因。未配置的模型不提问，工作池不为它发出判断。

判断缓存、工作池与限时：

- 判断的概率按提问内容的哈希缓存在派生索引里，三档在读取时按当前阈值计算，所以改阈值不使缓存失效。只有整理读写缓存，实时写入的判断不用它。
- 同时进行的判断不超过 `consolidation.maxConcurrency`（默认 5）。整理限时 `consolidation.budgetSeconds`（默认 20）：到点时未返回的判断计为「未检查」，报告注明「再运行一次 `tacit-consolidate` 接着算」；已在进行的判断不取消，跑完写入缓存，下次直接用上。

## 10. 记忆指令与记忆 skill

### 记忆指令

两个记忆指令是 skill，与 `tacit-memory` 一样由代码生成到 `TACIT_HOME/skills/`，不读取记忆仓库：

| skill | 用途 | 正文依赖 |
| :--- | :--- | :--- |
| `tacit-remember` | 让主会话把本会话写进记忆（步骤见 `docs/dev/prompts.md`「记忆指令 skill」） | 仅代码 |
| `tacit-consolidate` | 让主会话依据整理报告整理记忆仓库（见本文第 9 节） | 代码；报告经资源 `tacit://consolidation-report` 读取 |

两者 frontmatter 都含 `disable-model-invocation: true`，只由用户触发（触发方式取决于客户端）。用户附在命令后的文字是本次的重点或附加要求，Agent 须遵从。`tacit-remember` 写完后列出写了什么：页面附页面标识，活动与画像条目附短码，候选附原文；不预先征求确认，与画像矛盾时先问用户。

### 记忆 skill

- 位置：`TACIT_HOME/skills/tacit-memory/SKILL.md`，由代码生成，用户不直接修改；成品结构与各部分的措辞见 `docs/dev/prompts.md`「记忆 skill」。`prompts/skill.md` 存在且非空白时，末尾接 `## User conventions` 一节。
- `prompts/skill.md` 的长度与格式规则见 `docs/reference/configuration.md`「提示词文档」。
- 生成时机：服务启动时；`prompts/` 下的文件变化时；门面的 `GenerateSkills` 操作（返回三个 skill 各自的路径与是否写入），不需要服务运行；`connect` 绑定时也调用它。内容不变时不写文件。
- 两个记忆指令与记忆 skill 同时生成。`tacit-remember` 的成品只取决于代码，`tacit-consolidate` 也只取决于代码；两者都不读取记忆仓库，也不读 `prompts/`，没有覆盖或追加文件，个人要求在触发时附上即可。
- 不进入自动备份。系统部分正文的措辞验证方式见 `docs/dev/testing.md`「提示词的验证」。

## 11. 语言

| 层 | 内容 | 语言 |
| :--- | :--- | :--- |
| 文件格式 | 记忆文件的 21 个结构词（画像四节与作用域块、候选与拒绝列表、汇总、原话与拒绝标记、主线文件的字段、三个被识别的页面小节、`rules.md` 的两个节名）；`init` 写出的骨架 | 固定英文 |
| 只给 Agent 看 | 工具与参数说明、服务端说明、记忆指令、skill、工具返回与报错、整理报告、常驻区块外壳与其中生成的行（领域索引与主线行）、发给决策模型的问题、值得记标准的内置默认 | 固定英文 |
| 记忆内容 | 画像条目、细节页正文与自由取名的小节、活动记录、主线的背景与近况 | 按语言规范使用记忆语言 |
| 给人看的显示 | Web 界面、CLI 输出、API 错误说明、日志 | 随配置 `language` |

结构词只认英文写法（大小写不限），写成其他语言的结构词当作内容，例如 `## 教训` 只是一个普通小节。所以记忆的格式与 `language` 无关：两台语言设置不同的机器之间，记忆可以直接互导；切换 `language` 只影响此后写入的内容与界面。

`language` 取 `zh` 或 `en`，在 `init` 时定下：取 `--language`，否则沿用已有配置，已有配置却没有可读的 `language` 时拒绝（`init` 不改写已有配置，问到的答案存不下）；都没有时在终端里询问，且在其他检查都通过之后才问；标准输入不是终端时不询问，以用法错误结束，提示加 `--language`。配置文件还不存在、读不了或缺这个键时，提示与报错用英文。Agent 与用户交谈所用语言由画像决定，不由 TacitMemory 规定。

用户在 `prompts/` 下写的文档（`rules.md`、`instructions.md`、`resident.md`、`skill.md`）不检查语言，可用任一语言；语言规范只约束系统提供的文字。

## 12. 运行

### 客户端绑定

| 绑定写入 | 位置 |
| :--- | :--- |
| 常驻区块 | 上下文文件中起止标记之间的内容；上下文文件不存在时由 `connect` 创建；`disconnect` 只移除区块，文件即使变空也保留 |
| skill 链接 | skill 目录下的 `tacit-memory`、`tacit-remember`、`tacit-consolidate` 三个链接，分别指向 `TACIT_HOME/skills/` 下的同名目录 |
| 绑定记录 | `TACIT_HOME/bindings.json`，每条含 `client`、`contextFile` 与 `skillsFolder`；三个链接的位置由 `skillsFolder` 与固定的三个 skill 名推出 |

绑定 = 客户端名称 + 上下文文件 + skill 目录。名称只是标签：只允许小写字母、数字与连字符，长度 1 到 32，大小写不同视为同一名称并以小写记录。两个路径都必填、没有默认值；开头的 `~` 展开为用户目录，记录的是绝对路径。tacit 不读写任何客户端的 MCP 配置：`connect` 打印 MCP 端点（见 `docs/reference/mcp.md`），由用户在客户端中自行配置。

`connect` 的检查顺序，任一步拒绝都不写任何文件：名称合规；同名记录的路径不同则拒绝，提示先 `disconnect`；上下文文件所在的目录与 skill 目录处没有同名文件挡着（含它们的上级）；三个链接位置无冲突（不存在，或已是指向 tacit 对应 skill 的链接）；严格加载配置与画像；上下文文件是 UTF-8 且标记完整。通过后先新建不存在的上下文目录与 skill 目录，并在结果中逐个列出（Web 界面以提醒显示），让用户确认客户端读取的就是这里；再依次生成三个 skill、写常驻区块、建立缺失的链接、写绑定记录；其后某一步失败时撤回本次新建的链接。同名同路径重复执行是安全的：补齐缺失的链接，常驻区块按当前画像重写。

`disconnect --client <名称>` 只需名称，路径取自记录：移除常驻区块（文件本身保留）与指向 tacit 的三个链接，别人的同名项保留并报告；文件或链接已不在时逐项报告缺失，照常删除记录，以 0 结束；名称不存在时以 1 结束。只宽松读取语言，配置无效时照常工作。

共用：多个绑定可以指向同一个上下文文件或同一个 skill 目录（如两个客户端都读取 `~/.agents/skills`）。

- 路径比较用规范化后的完整路径（去掉末尾分隔符）。Windows 与 macOS 上忽略大小写，Linux 上区分大小写。tacit 不解析目录联接与软链接：经两个不同入口指向同一目录的，被当作两处。
- `connect` 遇到已被其他绑定引用的上下文文件：不写第二个常驻区块，文件中始终只有一个；报告「已由 `<名称>` 使用」。遇到已被引用的 skill 目录：已指向 tacit 的链接视为复用，报告同样说明复用了谁的路径。
- `disconnect`：仍被其他绑定引用的上下文文件不动，报告「仍被 `<名称>` 使用，保留」；无人引用时才移除常驻区块，文件保留。skill 目录同理：仍被引用时链接全部保留，无人引用时只删指向 tacit 的链接。
- 渲染所有常驻区块时按规范化路径去重：同一文件一次渲染只写一次、只产生一个结果。
- `status` 绑定栏：每条绑定注明与之共用路径的其他绑定；共用路径只检查一次，问题挂在第一个引用它的绑定上，其余绑定只注明共用。

链接的形式：Windows 用目录联接（不需要管理员权限），其他平台用软链接。三个位置中任一被占用（同名的目录或文件，或指向别处的链接）时，`connect` 整体拒绝并指出冲突的位置：三个链接一个都不建，skill 成品与其他文件也不写，不回退为复制。链接无法建立（如 `TACIT_HOME` 位于网络盘）时同样拒绝。`disconnect` 只删除指向 tacit 的链接本身，不跟随链接删除目标，skill 成品保留。

### 备份与恢复

- 所有备份（自动、手动、保险与云端）的打包方式相同，zip 内容为：记忆仓库（含 `.git`，不含 `.cache`）、`config.yaml`、`prompts/` 目录（含 `rules.md`、`instructions.md`、`resident.md` 与 `skill.md`）、`bindings.json` 与清单（`manifest.json`：生成时间、tacit 版本、`kind`、记忆仓库 HEAD 的提交号与提交说明、文件列表）。生成的记忆 skill（`skills/`）不进入备份。配置中含明文密钥时备份时提示。
- 自动备份（`backups/auto-YYYY-MM-DD.zip`）：每天第一次写入后生成一份，在写入队列中打包（作为写入槽的后台任务，打包期间的写入排队等待），只清理 `auto-*`，保留最近 `backup.keep` 份（默认 7；`0` 只关闭自动备份）。
- 手动备份（`backups/manual-YYYY-MM-DD-HHmmss.zip`）：`tacit backup` 立即生成，在写入队列中打包，拿到某次写入之后的完整状态；`--to <目录>` 写到指定目录（不存在则创建）。不计入 `backup.keep`，永不自动清理。
- 保险备份（`backups/pre-restore-YYYY-MM-DD-HHmmss.zip`）：恢复前自动生成，不清理、不上传。
- 时间戳为本地时间；同一秒内重名时拒绝，不覆盖已有文件。
- 云端备份（`tacit backup --remote`）：现场打包（在写入队列中，拿到某次写入之后的完整状态），上传为 `backup.webdav.url` 目录下的备份文件（`backup.webdav.file`，默认 `tacit-backup.zip`），已存在则替换。多台机器共用一个目录时各配一个文件名，互不覆盖。只在执行命令时上传，不自动进行；本地不留副本，本地备份也不上传。zip 原样上传，不抹掉其中的密钥。
- 替换是原子的：先把 zip `PUT` 为 `<文件名>.part`，再 `MOVE` 到备份文件（`Overwrite: T`），上传中途失败时远端旧的那份保持不变。远端目录不存在时对目录 `MKCOL`（只建最后一级）后重试一次上传。服务不支持 `MOVE`（405 或 501）时报错"该 WebDAV 服务不支持原子替换"，不回退为直接覆盖。替换失败（上传或 `MOVE` 失败，含不支持 `MOVE`）时尽力删除 `.part`，删除失败不影响报错。
- 只使用通用 WebDAV 方法与 HTTP 基本认证；`username` 省略时不发送认证。每个请求（含响应体的读取）单独计时，超过 10 分钟即失败（硬编码），请求本身不重试（父目录缺失时的 MKCOL 与重传见上文）。错误信息说明阶段（连接、认证、上传、替换、下载）与 HTTP 状态码，不含密码与 URL 中的凭据。
- 每次尝试的时间与结果（成功，或失败原因）记入 `backups/remote.json`，`tacit status` 的备份栏据此显示最近一次云端备份；该文件不进入任何备份，状态显示不访问网络。
- 恢复（`tacit restore --from <zip> [--include-config] [--yes]` 本地备份，或 `tacit restore --remote [--include-config] [--yes]` 云端备份）由常驻服务执行，先预览：备份的生成时间、tacit 版本、`kind`、记忆仓库 HEAD 的提交号与说明、文件数，以及将被替换的内容。未加 `--yes` 时等待输入 `y`，其余输入一律取消（退出码 1）；标准输入不是终端时不等待，预览后以用法错误（退出码 2）结束，不发出执行请求。
- 拒绝且什么都不改的情况：清单缺失、无法解析或与内容不符；缺少 `memory/.git/`；条目不在允许的位置（只能是 `memory/`、`prompts/` 或根下的 `config.yaml`、`bindings.json`、`manifest.json`），或含 `..`、绝对路径。
- 确认后先生成保险备份（失败即中止），再把备份的记忆仓库换入（当前内容移到同卷的隐藏目录，以便撤销）；加 `--include-config` 时一并替换 `config.yaml` 与 `prompts/`，恢复回来的配置能加载就按它重新加载，不能加载时照常完成并在结果中附错误。之后全量重建索引、重新渲染常驻区块。换入之后任一步失败，记忆仓库逆序撤销，回到恢复前的内容。
- `bindings.json` 永远不恢复。记忆仓库恢复到当前配置的 `memory.path`；恢复回来的 `config.yaml` 指向另一个路径时只提示，不搬目录。运行中的服务继续使用当前加载的配置。
- 结果：保险备份路径、恢复后的 HEAD、索引重建的文件数、单元数与向量数；加 `--include-config` 时附"已按恢复回来的 `config.yaml` 重新加载"（或没能加载的原因），并列出需重启才生效且与运行中不同的项（键路径、运行中的值、恢复后的值）；恢复回来的 `memory.path` 不同时附"重启后会指向 X，记忆仓库已恢复到 Y"。
- 云端恢复（`--remote`）：服务先把远端的备份文件（同样取 `backup.webdav.file`）下载到 `backups/.download/<文件名>`（覆盖已有文件），校验后预览，预览中给出下载文件的本地路径。确认后以这个路径走上面的同一条恢复流程，所以确认的与恢复的是同一个文件；恢复成功后删除该文件，失败则保留以便排查。远端没有备份时提示"远端没有云端备份"；认证、连接与下载失败沿用云端备份的阶段提示。`.download/` 不是备份：不计入 `status` 的最近本地备份，也不被清理逻辑触及。

### 服务运行

- 单一常驻 HTTP 服务，总是监听 `127.0.0.1`，`server.host` 给出的一个额外地址也监听。按连接来源区分本机与其他设备：MCP 端点只接受本机连接；管理 API 对本机免登录，其他设备要先用访问密码登录。不做 HTTPS，本机视为可信边界。访问规则见下文「访问与鉴权」。记忆工具的读写、后台的索引同步与常驻区块渲染共用一把读写锁：写入与后台任务之间串行，读取彼此共享；维护操作（重建索引、恢复、保存设置）独占，期间其他操作排队。服务未运行时记忆工具不可用，已写入的常驻区块仍然有效。
- 设置页保存配置后，服务**重新加载**：写出新的 `config.yaml` 与重新加载合为一次维护操作，在途的读写先完成，期间到达的排队，之后按新配置执行。进程不退出，监听、会话与访问密码保留；重开的是配置决定的部分（派生索引、辅助模型、记忆工具、备份与文件监听），随后重新生成 skill、重渲染各绑定的常驻区块。`server.port`、`server.host`、`memory.path`、`language` 与 `limits.page.minAliases` 不随它生效，按运行中的值继续，直到重启 `tacit serve`。新配置打不开时以原配置重开，`config.yaml` 也写回原样；连原配置也打不开时服务停止，下次启动报告原因。手动编辑 `config.yaml` 不触发重新加载，在设置页保存任何改动或重启 `tacit serve` 后才生效；带配置的恢复完成后同样重新加载（见「备份与恢复」）。
- 启动时按文件哈希比对增量同步索引；运行时监听记忆仓库与 `prompts/`，文件变化即同步对应索引，画像变化时重新渲染常驻区块。
- 后台刷新（派生索引同步、常驻区块渲染、提示词重读）在变化停止 300 ms 后执行。遇到瞬时错误（文件被其他程序占用、无权访问，或 `prompts/` 正被替换）时按同一间隔重试，最多 5 次，仍失败则提示用户一次，等下一次变化再试；派生索引的同步放弃后，下一次检索前先全量同步一遍，文件放开后的检索因此不必等下一次变化。其他错误直接提示，不重试。任何错误都不会中断服务。维护操作开始前，排着的刷新先执行完。
- 索引记录表结构版本不一致时删除并全量重建；嵌入模型名或向量维度与记录不一致时只丢弃向量，全文索引保留，向量按文件哈希补齐。
- 日志的位置与排障见 `docs/reference/operations.md`；各命令的用法与退出码见 `tacit --help`。

### 访问与鉴权

同一个端口上有三样东西：`/mcp`（MCP 端点）、`/api`（管理 API，`tacit` 命令与 Web 界面都经它访问服务）与 `/ui`（Web 界面的静态文件）。

- **按连接来源区分**：依据只是 TCP 连接的对端地址，不看任何请求头。回环地址即本机：`/api` 免登录，`/mcp` 可用。其他设备访问 `/api` 要先登录，访问 `/mcp` 一律拒绝（会话也不放行），访问 `/`、`/ui`、`/api` 之外的路径一律拒绝。经 SSH 端口转发进来的连接也算本机；不支持反向代理转发到回环地址，那样会被当作本机。
- **访问密码**只有一个，没有用户名，最短 8 个字符。它的哈希与会话签名密钥存在 `TACIT_HOME/access.json`，不在配置里，不进入备份。`server.host` 设了额外地址而没有访问密码时，服务拒绝启动。本机设置或修改密码不需要旧密码；其他设备修改要提供当前密码；清除只接受本机，且设了额外监听时不允许。
- **会话**是签名的 Cookie，有效期从登录起 30 天、不续期，服务重启后仍有效；设置、修改或清除访问密码都会让全部已有会话失效。同一地址连续输错 5 次后暂停 60 秒。
- **请求防护**（只对 `/api`）：带 `Origin` 头时须与请求自身同源；本机连接的 Host 须为 `127.0.0.1`、`localhost` 或 `[::1]`；`POST` 与 `PUT` 须为 JSON。防护先于鉴权判定。
- **错误**：错误体为 `{"error": "<错误名>", "message": "<记忆语言的说明>"}`，`message` 可直接显示；校验不通过时另带 `problems`，一次列出全部问题。客户端按错误名区分错误，不解析说明文字。端点与字段以 `/api/openapi.json` 为准。
- 不提供 HTTPS：其他设备连接上的访问密码与密钥以明文传输，只在可信网络（如 Tailscale）里打开额外监听。

### 客户端能力记录

- 服务从每个 MCP 请求里读取客户端声明的名称、协议版本、能力与扩展，按名称为每个客户端保存一条记录到 `TACIT_HOME/clients.json`（能力与扩展取历次声明的并集），供 `tacit status` 与仪表盘显示。
- 只做观察，不因客户端声明了某个扩展而改变任何行为；它是运行状态，不属于记忆，不进入备份。

## 13. Web 界面

### 定位与访问

- Web 界面由常驻服务托管在 `http://<主机>:<端口>/ui`，打开 `/` 会被带到这里；服务未运行时不可用。
- 它只调用管理 API，规则都在核心里，与 `tacit` 命令共用。它是配置、绑定、提示词文档、状态与日志的操作入口，也可以只读地浏览记忆；记忆的写入仍由主会话经 MCP 工具完成，整理仍由 `tacit-consolidate` 开启。
- 界面语言就是记忆语言，没有单独的切换。页面在手机浏览器上可用。
- 本机连接直接进入，不需要登录。从其他设备打开时先到登录页，输入访问密码后回到原本要去的地址；登录后能做的事与本机相同。访问密码、会话与限速的规则见第 12 节「访问与鉴权」。

外壳是左侧边栏，导航固定为五项：仪表盘、设置、提示词、日志、记忆。

### 仪表盘

一页看清服务是否正常、有什么要处理：

- **概览**：一句状态（「一切安好」或「有 N 件事等你处理」）和待处理清单，每条链接到能解决它的地方：辅助模型未配置、没有绑定或绑定有问题、提示词文档有误、额外监听没能启动、上一次云端备份失败。模型冷却会自己恢复，候选与格式问题留给整理，都不列为待处理。
- **记忆活动**：近一年的热力图，每天一格，整理过的日子另有标记；点有活动的一天，打开记忆页的活动视图并定位到那一天。
- **辅助模型**：三个模型各自可用、冷却中或未配置，可一键探测。
- **备份**：最新本地备份与云端备份的状态；可立即做本地或云端备份，可从已有备份恢复（先预览，可选一并恢复配置与提示词）。
- **索引与整理**：上次整理在哪天，等下次整理处理的候选、格式问题与未汇总的周；可重建索引；可复制定时提醒的配置指令（英文，交给本机 Agent，由它按自己的环境配好每天询问 `GET /api/consolidation` 的定时任务，见第 9 节「整理」）。
- **日志**：今天有几条警告与错误，链接到日志页。
- **服务与客户端**：版本、MCP 与 Web 地址、额外监听的状态；绑定与连接过的客户端，每个一枚胶囊。

状态每 30 秒刷新，命令执行后相关数据随即刷新；连不上服务时保留上次的数据并注明。

### 设置

设置页取代手写 `config.yaml`：每一项是一个控件，附解说，悬停名称可看到键路径。各节依次为模型、绑定、检索与判断、整理、备份、远程访问、高级。

- **全页统一保存**：改动后页面底部浮出提示条，写明改动数，可放弃或保存。服务一次校验整份配置并报告全部问题，不通过时文件不变；通过后写文件并在进程内重新加载，立即生效。
- 等于默认的项不写进文件，此后随默认值变化；值与默认不同时可一键恢复默认。
- 打开页面后 `config.yaml` 又被改过时，保存被拒绝，可重新载入。文件无法加载时，页面只显示出错的键与原因，服务仍按上次加载的配置运行。
- `server.port`、`server.host` 与 `limits.page.minAliases` 保存后要重启才生效，重启前标「待重启」。`memory.path` 与 `language` 只读，只能在文件里改并重启。
- **密钥**像其他设置项一样就地修改，默认以掩码显示、可切换为明文，改动随全页保存生效，清空即从文件中删除；来自环境变量的密钥只读。
- **绑定**与**访问密码**立即生效，不经全页保存。绑定以磁贴列出，可新增（常见客户端有预设路径）和解除，规则同 `tacit connect` 与 `tacit disconnect`；界面不替用户修改客户端的 MCP 配置，只给出注册所需的地址。设了额外监听却没有访问密码时，保存被拒绝。

### 提示词

四份提示词文档（核心规则、值得记标准、常驻区块、写法约定）各一页：

- 没有文件时显示内置默认（只读），点「开始自定义」以它为起点编辑；已自定义的可恢复默认。
- 输入时由服务校验并显示长度与额度（服务端说明固定部分的合计、最近活动还能用的字符数）；保存时同样校验，通过后立即生效，下一个会话采用新文本。
- 打开后文件在别处被改过时，保存不覆盖。服务运行中文件被手动改坏时，服务沿用上一版，页面、侧边栏、仪表盘与 `tacit status` 都标出原因。

### 日志

- 按天查看服务日志（保留 14 天），条目从旧到新；可按级别与关键字筛选，筛选条件写在地址里。
- 看今天时默认实时跟随，新日志每 2 秒追加；向上翻看时不自动滚动，底部提示有几条新日志。
- 只读：不提供清空、删除与下载。

### 记忆

只读地浏览记忆与执行检索追踪，都不改动任何文件，也不计入使用统计。五个视图：

- **画像**：红线、协作规则、偏好、档案四节，可按作用域（全局、某领域、某主线）筛选；画像候选与拒绝列表单独一张卡片。每条可复制短码，交给 Agent 替换或删除。
- **主线**：所有主线的卡片（近半年的活动条），点开看主线简报，内容与 Agent 用 `recall` 取到的相同，但不截断。
- **细节页**：可按关键字、主线、类型筛选的清单，以及单页阅读（小节、相关页面、来源注释）。
- **活动**：按月的时间线，月汇总与周汇总排在相应位置，可按主线筛选。
- **检索**：用与 `recall` 相同的条件检索，左边是 Agent 收到的结果，右边是每个检索单元在各阶段的名次、分数与去向（显示、超出 topK、低于阈值、在候选数之外），可临时替换检索参数、查看 Agent 收到的原文。用来回答「为什么这条没搜到」。

格式有问题的记忆文件照常显示能读的部分，问题文字与整理报告相同。

### 不做的事

| 不做 | 原因或归属 |
| :--- | :--- |

| 一键整理 | 整理由主会话完成，服务不调用生成模型 |

| 替用户修改客户端的 MCP 配置 | 绑定不代写 MCP 配置 |
| Agent 操作时间线 | 主要用途是提示词取证，代价大于收益 |

## 15. 扩展

扩展时遵守：

- **所有入口经常驻服务**：TUI、Web 界面等新界面只调用常驻服务，不直接读写记忆仓库或索引。
- **规则只有一份**：新能力先在核心实现，再由各入口调用。
- **对配置，设置页是入口，文件是兜底**：`config.yaml` 的每一项都在设置页修改，保存后经重新加载生效（需重启的项除外）；文件仍可直接编辑，在设置页保存任何改动或重启 `tacit serve` 后生效；设置页只显示不修改的 `memory.path` 与 `language` 只能这样改，且要重启。
- **记忆文件始终可直接编辑**：界面是便利，不是必需。
- **配置向后兼容**：新增配置项必须有默认值。

已知方向：Web 界面（浏览、查看候选、检索追踪；候选只看不审核，审核仍在整理中）、TUI、以支持 logprobs 的对话模型实现决策模型接口、更多客户端支持、更换索引引擎。
