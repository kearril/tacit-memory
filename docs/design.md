# TacitMemory 设计

本文档说明 TacitMemory **做什么**：记忆如何分层、如何写入与检索、如何注入与整理，以及 CLI、Web 界面与访问安全边界。设计取舍见 [`decisions.md`](decisions.md)，配置、文件格式与运维细节见 [`configuration.md`](configuration.md)、[`memory-files.md`](memory-files.md) 与 [`operations.md`](operations.md)。

## 1. 目标与原则

TacitMemory 让 Agent 在跨会话、跨客户端协作中保持连续性：延续用户的协作规则与偏好，关联近期进展，按需检索历史排错与决策；没有相关记忆时如实说明，不编造。

核心原则：

1. **只存环境里拿不到的信息**：仅记录无法从代码、仓库文档、配置或当前会话历史获取、且会影响后续行为的信息。
2. **按进入上下文的方式分层**：常驻内容在会话开始即可见，严格控制噪声；细节与历史由 Agent 按需检索。
3. **文件是唯一真相源**：全部记忆以可读、可手改的 Markdown 保存在独立 Git 仓库中，派生索引随时可删可重建。
4. **理解与生成交给主会话，判断交给辅助模型**：写什么、怎么写、汇总与整理提案由当前对话的 Agent 完成；常驻服务不调用生成式对话模型，只做存储校验、结构化判断与检索。
5. **实时写入求快，批量清理靠整理**：对话中允许粗糙写入，去重、精简、归档与提案确认交给定期整理。
6. **画像只是背景记忆**：优先级低于项目上下文文件与当前对话中的用户指令。

## 2. 记忆分层

| 层 | 内容 | 进入上下文的方式 |
| :--- | :--- | :--- |
| **画像** | 红线、协作规则、偏好、档案四节，分全局、`workstream:<名>`、`domain:<标签>` 三种作用域 | 全局条目与领域索引常驻；领域规则按 `recall kind=rules` 按需读取；主线约定随主线简报读取 |
| **近期活动** | 主线（`workstreams.md`）、按月活动记录与周/月汇总（`recent/YYYY-MM.md`） | 已成立主线的背景与近况常驻；最近 7 天活动随服务端说明下发；更早记录与汇总按需检索 |
| **细节页** | 按主题组织的 Markdown 页面（`pages/<主线>/<slug>.md` 或 `pages/_topics/<slug>.md`），分 `incident`、`decision`、`entity`、`work` 四类 | 被提起时通过 `recall` 按需检索 |

## 3. 辅助模型与降级

常驻服务可接入三类辅助模型，均通过 HTTP 调用且**全部可选**：

| 模型 | 职责 | 通用协议 |
| :--- | :--- | :--- |
| 嵌入模型 | 生成向量，用于检索召回与判断近邻筛选 | OpenAI Embeddings |
| Reranker | 对融合后的检索候选精排并按阈值过滤 | Cohere / Jina Rerank |
| 决策模型 | 回答选择题并返回各选项概率 | System One |

另内置 Cloudflare Workers AI 提供方适配（嵌入模型、reranker 与决策模型）。

### 结构化判断

服务在写入前与整理时向决策模型提出四类选择题（最多 10 个选项，含「都不是」）：

| 判断 | 确定时 | 不确定时 |
| :--- | :--- | :--- |
| 新画像候选与已有候选/拒绝列表/画像是否同一偏好 | 并入候选；命中拒绝列表或画像则不记并告知 | 新建候选 |
| 新建细节页与同主线已有页是否同一件事 | 拒绝新建并列出已有页 | 允许新建，留待整理 |
| 新活动与当天已有活动是否同主题 | 退回已有活动及短码，要求合并改写 | 单独记录 |
| 新画像条目与已有条目是否冲突、重复或取代 | 拒绝写入并给出冲突条目短码，确认后改用 `replace` | 写入，留待整理 |

- 每项判断由配置中的上下阈值（`certain` / `unlikely`）划分为**确定 / 不确定 / 否定**三档，不确定项不自动合并或丢弃，留待整理复核。
- **凭据检测**不调用决策模型，仅在本地用内置正则拦截常见密钥、令牌、私钥块与密码赋值；命中即拒绝，用户确认无凭据后可带 `confirm_no_secret` 重试。

### 降级与容错

- 服务严格区分**未配置**与**不可用**（已配置但请求失败、处于冷却期）：未配置从不发起请求，不触发告警；不可用时跳过对应步骤、不拒绝写入，并在结果与状态提示中注明。
- **嵌入模型不可用**：写入照常提交，判断按不确定处理，检索退回纯全文检索；恢复后按文件哈希补齐向量。
- **Reranker 不可用**：检索按 RRF 融合排序直接返回。
- **决策模型不可用**：所有判断按不确定处理。
- 请求失败先在单次调用内指数退避重试（网络错、超时、429、5xx，最多 5 次、总时限 20 秒；4xx 与格式错误不重试）；最终失败后该模型进入 30 秒冷却期，冷却后下一次成功即恢复。
- `tacit probe` 直接按 `config.yaml` 发出固定英文探测请求，不经过常驻服务、不发送任何记忆内容，也不影响运行中的冷却状态。

## 4. 写入

写入只有三个入口，不使用客户端钩子，也不做会话结束后的后台补抽：

1. **对话中即时写入**：Agent 按服务端说明中的记忆规则执行（用户纠正或明确提出做法时，问一次是否记为长期规则，同意后直接写入）。
2. **`tacit-remember` skill**：用户手动触发，要求 Agent 立即归纳并写入本次会话结论。
3. **`tacit-consolidate` skill**：用户定期触发整理，由 Agent 直接编辑记忆仓库并提交。

核心写入规则：

- **先检索再写页**：一件事一页；新建细节页必须指定 `type`（`incident` / `decision` / `entity` / `work`）与至少 2 个别名；后续按小节增改删或更新页头，不提供整页重写。
- **短码引用**：服务返回条目或小节时附带内容哈希前 6 位短码（不写入文件）；替换或删除须带短码，内容变化后旧短码失效，充当乐观并发控制。
- **单行与不设长度上限**：活动与画像条目不设长度和条数硬上限（避免写入被打断），过长条目由整理报告提示精简；写入与环境有关的记忆时在正文中标明机器名，不使用「本机」「这里」等相对指代。
- **活动记录**：每条主线每个会话至多一条结论，后续进展用 `replaces` 原位改写当天条目；服务自动在注释中写入本机机器标记 `on <机器名>`。主线由整理维护，不经 `write_recent` 写入。
- **画像权限边界**：红线只能由用户明确提出；替换与删除须经用户明确要求；观察到的长期习惯先经 `propose` 写入候选（仅针对单个客户端的设置、插件与故障经验不提交）。
- **单文件提交**：每次经服务的写入仅提交本次修改的文件；若该文件存在用户未提交的手动编辑，会一并纳入提交并注明。

## 5. 检索

`recall` 支持四种互斥模式：

- **按查询检索（`query`）**：自然语言查询（使用记忆语言），可按 `workstream`、`from`/`to`、`kind`（`pages` / `activities`）筛选。流程为：筛选 → FTS5 全文检索（中文按二字切分并支持单字匹配）与余弦向量检索各取候选 → RRF 融合 → Reranker 精排与阈值过滤 → 返回前 `topK` 条。汇总行作为活动检索单元参与检索；画像与候选不进入普通检索结果。
- **读取整页（`page`）**：按页面标识（`<主线>/<slug>` 或 `_topics/<slug>`）返回全文，小节附最后修改日期与短码。
- **主线简报（仅 `workstream`）**：返回该主线的全景地图，依次包含背景与近况、主线约定、各 `work` 页 `Leftovers` 汇总的未决事项、按类型分组的页目录（`decision` 页若 `Overturned` 非空则归入已推翻）、最近 3 条活动与最近一次周汇总。超出 `limits.brief` 时从最旧的页目录条目起截断。
- **直接读取画像（`kind=persona` 或 `kind=rules`）**：不走检索，直接返回整份画像或指定 `domain` 的领域规则，每条附短码供改删。

**使用统计**：`recall` 返回与整页读取会累加各检索单元的使用次数与最近返回日期，仅存于派生索引，只用于主线简报排序与整理报告，不参与检索打分。Web 界面的浏览与检索追踪不计入统计。

## 6. 注入

常驻内容按变化频率分两路下发，均在下一次会话生效：

| 通道 | 内容 | 更新时机 |
| :--- | :--- | :--- |
| **常驻区块** | 机器行、全局画像、领域索引、已成立主线（近 28 天活跃的主线附近期摘要） | 绑定时；画像、主线、活动记录或 `prompts/resident.md` 变化时；本地午夜日期变更时 |
| **服务端说明** | 核心规则、通用规则、语言规范、值得记标准、最近 7 天活动、状态提示、整理提示 | 记忆、提示词文档或模型/文件状态变化后重新生成，客户端连接时下发 |

- 常驻区块以 `<!-- tacit:begin ... -->` 与 `<!-- tacit:end -->` 写入客户端上下文文件，只改区块内内容，并声明自身为可能过时的背景记忆。
- 服务端说明的固定部分上限 3000 字符，总长上限 4000 字符；超出时仅从最早的活动起截断，不截断规则与提示。
- 当距上次整理满 `remindAfterDays` 天、存在未汇总的已完成周、新候选达到 `remindCandidates` 或主线为空时，服务端说明末尾附带整理提示。
- `tacit consolidation` 与 `GET /api/consolidation` 对外提供同一套「是否该整理」布尔信号，方便客户端自行配置定时检查。

## 7. 整理

用户通过 `tacit-consolidate` skill 开启整理，Agent 读取 MCP 资源 `tacit://consolidation-report` 获取现场生成的两段式报告，并直接编辑记忆仓库：

1. **A 部分（自动处理，不打扰用户）**：解决同步冲突（或给出选边命令）、修正格式问题、删除与画像/拒绝列表确定重复的候选、写入已结束的周/月汇总、依据新活动重写已成立主线的近期摘要（不改背景说明）。
2. **B 部分（甄别与提案）**：Agent 阅读主线提案材料、疑似重复页、冲突画像条目、画像证据、排错教训、变化过的页、领域卫生与篇幅提示，过滤假阳性后汇总为**一张编号清单**（开头附 A 部分汇总预览），由用户通过一次回复批量决定（确认 / 拒绝 / 改成 / 暂缓）。
3. **执行与提交**：按用户回复更新画像、作用域块、页面与主线文件（拒绝的候选移入拒绝列表），提交至记忆仓库并执行 `tacit sync`。

- **基准推进**：仅当报告完整（判断在 `budgetSeconds` 内算完且无类别截断；未配置的模型不影响完整性）且用户未限定整理范围时，提交信息以 `consolidate:` 开头并推进整理基准；否则以 `consolidate(partial):` 提交，基准不动。
- 整理判断结果按提问内容哈希缓存在派生索引中，改阈值不失效，限时中断后再次运行可接着算完。

## 8. 语言划分

| 层 | 内容 | 语言 |
| :--- | :--- | :--- |
| 文件结构词 | 节名、`Belongs to:`、`quote`、`on`、约定小节名（`Lesson` / `Overturned` / `Leftovers`）、`init` 骨架 | 固定英文 |
| 面向 Agent 的文字 | 工具说明、服务端说明、skill、工具回复、整理报告、判断问题 | 固定英文 |
| 记忆内容 | 画像条目、细节页正文与自由小节名、活动、主线说明 | 按配置 `language`（`zh` / `en`） |
| 面向人的显示 | Web 界面、CLI 输出、API 错误说明、服务日志 | 随配置 `language` |

用户自定义的 `prompts/` 文档不限制语言。

## 9. 运行、绑定与同步

- **单一常驻服务**：`tacit serve` 监听 `127.0.0.1:<port>`（及可选的 `server.host`）。所有读写与后台维护共用读写锁：读取共享、写入串行、维护操作（重建索引、恢复、保存设置重载、以远端为准选边）独占。
- **进程内重载**：通过 Web 设置页保存配置后，服务等待在途操作完成，在进程内重建运行时使新配置生效（失败自动回退原配置）。`server.port`、`server.host`、`limits.page.minAliases`、`memory.path`、`language` 五项需重启生效。
- **客户端绑定**：绑定由「客户端名称 + 上下文文件 + skill 目录」构成，存于 `bindings.json`。多个绑定可共用同一上下文文件或 skill 目录（解除绑定时仅在无人引用后清理）。服务只维护常驻区块与三个 skill 链接（Windows 用目录联接，其他平台用软链接），不读写客户端的 MCP 配置。
- **客户端能力记录**：服务在 `clients.json` 中记录连接过的客户端及其声明的能力并集，仅作状态观察，不改变行为，不进备份。
- **备份与恢复**：支持自动（每日首次写入后，按 `backup.keep` 清理）、手动（`tacit backup`）、保险（恢复前自动生成）与云端 WebDAV（`PUT .part` + `MOVE` 原子替换）四类备份。恢复前先预览、确认后先做保险备份再换入，失败逆序回退；默认只恢复记忆仓库，加 `--include-config` 一并恢复配置与提示词，永不恢复 `bindings.json` 与 `access.json`。
- **多机 Git 同步**：配置 `sync.remote` 后，服务在写入前拉取、写入后后台推送、定时拉取与整理前拉取，使用线性 rebase（`recent/*.md` 与 `candidates.md` 用 `union` 合并，所有文件统一 LF 签出）。断网或认证失败不阻塞本地写入；遇冲突、历史不相关或恢复备份后自动暂停同步，等待人工解决冲突或通过 `tacit sync --use-local / --use-remote` 选边。

### 访问与鉴权

同一端口承载 `/mcp`、`/api` 与 `/ui`：

- **按对端地址区分**：仅依据操作系统提供的 TCP 对端地址（不信任代理请求头）。本机回环连接免登录且可访问 `/mcp`；其他设备访问 `/api` 须先用访问密码登录，访问 `/mcp` 及非 `/`、`/ui`、`/api` 路径一律拒绝。
- **访问密码与会话**：单密码、无账号（至少 8 位），哈希与签名密钥存于 `access.json`（不进配置、不进备份）。设置 `server.host` 但未设密码时服务拒绝启动。登录签发 30 天有效 Cookie，同一地址连续输错 5 次暂停 60 秒；改密或清密使全部会话失效。
- **请求防护**：`/api` 强制校验同源 `Origin`、本机回环 `Host` 以及 `POST`/`PUT` 的 JSON `Content-Type`，防范外部网页与 DNS 重绑定。
- **传输加密**：服务不内置 HTTPS，跨设备访问请仅在可信加密网络（如虚拟专网）中启用 `server.host`；不建议通过反向代理转发至回环地址（会绕过登录鉴权）。

## 10. Web 界面

常驻服务在 `/ui` 下托管静态单页应用，只调用管理 API，支持桌面与手机浏览器。外观偏好（五套调色盘与明暗模式）仅保存在当前浏览器。

- **仪表盘**：服务健康概览与待处理清单、近一年记忆活动热力图（标出整理日）、辅助模型探测、本地/云端备份与恢复、索引重建与定时整理指令、日志统计、同步状态与客户端胶囊。
- **设置**：可视化编辑 `config.yaml`（全页统一校验保存、就地编辑密钥、一键恢复默认），以及立即生效的客户端绑定与访问密码管理。
- **提示词**：查看内置默认并在线编辑四份 `prompts/` 文档，实时校验字符额度，支持一键恢复默认。
- **日志**：按天只读查看近 14 天服务日志，支持级别与关键字筛选及当天实时跟随。
- **记忆**：只读浏览画像（含候选与短码复制）、主线与主线简报、细节页、按月活动时间线，以及逐阶段展示召回/融合/精排去向的**检索追踪**。

## 11. 不做的事

| 不做 | 原因或归属 |
| :--- | :--- |
| 任务交接、保存原始会话 | 由 Agent 客户端负责 |
| 客户端钩子、会话结束后的后台补抽 | 依赖记忆规则、`tacit-remember` 与整理，保持跨客户端通用 |
| 服务内调用生成式 LLM | 汇总、主线与提案由主会话完成，服务保持确定性 |
| 人格注入、主动浮现无关往事 | 语气由偏好决定，细节只在被提起时检索 |
| 遗忘式删除、使用统计/新近度介入检索排序 | 原文永久保留，以分辨率衰减（汇总与小节日期）表达时间；检索保持稳定 |
| 知识图谱与时序图谱 | 以 Markdown 页面与 `related` 关联表达结构 |
| 在 Web 界面直接编辑记忆、一键整理、账号分级 | 写入与整理归主会话；单用户个人部署无需权限分级 |
| 替用户改写客户端 MCP 配置 | 各客户端配置格式各异，仅输出端点由用户自行配置 |
| 1.0 前的旧格式/旧配置兼容与迁移工具 | 快速迭代期直接演进，旧键按未知键报错提示 |
| 提前实现客户端尚未普及的 MCP 扩展（Tasks、Apps、elicitation 等） | 仅记录客户端能力并集，待生态跟进后再按需实现 |
