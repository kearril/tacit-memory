# TacitMemory 设计

本文档定义系统**做什么**：记忆如何分层、如何存储、何时写入、如何检索与注入、对外暴露哪些接口，描述的是 v1 的目标行为。代码如何组织与各模块的实现状况见 `docs/architecture.md`，术语见 `GLOSSARY.md`。

## 1. 目标

让 Agent 像一个可靠的老朋友：记得用户的偏好与习惯，记得用户最近在做什么，提起具体的事时能想起细节；不记得时直说，不编造。

| 场景 | 用户说 | 期望的反应 | 依靠 |
| :--- | :--- | :--- | :--- |
| 新开会话 | "帮我写个脚本" | 直接按用户习惯的语言和方式回应，不用重新交代 | 画像 |
| 随口聊 | "最近有点累" | 能联想到用户最近在忙的事，但不复述近况 | 近期摘要 |
| 提起一件事 | "上次数据库升级那个坑" | 先检索，再按记忆回答现象、根因和解法 | 细节页 |
| 提起没记过的事 | "上次部署那个问题" | 说没有这方面的记忆，再问细节 | 记忆规则 |
| 没提起 | 聊别的 | 不主动翻旧账 | 细节页不常驻 |

## 2. 原则

1. **只存环境里拿不到的信息**：记忆只保存 Agent 无法从代码、仓库文档、配置、客户端会话历史中获得，且会改变其行为的信息。
2. **按进入上下文的方式分层**：常驻内容在会话开始时就在上下文中，一定被看到；按需内容由 Agent 主动检索，前提是它知道去取。
3. **常驻只能依据开局信号**：会话开始时只知道工作目录、客户端和时间。只在特定话题下才相关的内容一律按需检索。
4. **文件是唯一真相源**：所有记忆都是人类可读、可直接编辑的 Markdown 文件，存放在独立的 Git 仓库中；派生索引随时可删除重建。
5. **理解与生成交给主模型，判断交给辅助模型**：写什么、怎么写、如何改写由主会话完成；常驻服务借助辅助模型做召回、排序和结构化判断，自身不调用生成式对话模型。
6. **实时写入求快，批量整理靠体检**：对话中的写入可以不完美；合并重复、精简画像、确认候选等整理工作在体检中完成。
7. **画像只是记忆**：常驻内容是可能过时的背景，优先级低于项目上下文文件与当前对话中的用户指令。

## 3. 三层记忆

| 层 | 内容 | 进入方式 |
| :--- | :--- | :--- |
| **画像** | 红线、协作规则、偏好、档案四节 | 常驻：写入常驻区块 |
| **近期活动** | 近期主线 + 按月存放的活动记录 | 近期摘要常驻：写入服务端说明；活动记录按需 |
| **细节页** | 一件事或一个主题一页，按小节组织 | 按需：被提起时检索 |

## 4. 辅助模型

| 模型 | 职责 |
| :--- | :--- |
| 嵌入模型 | 生成向量，用于检索召回与判断前的近邻筛选 |
| reranker | 对检索候选精排，并按分数阈值过滤 |
| 决策模型 | 回答选择题，返回各选项概率 |

三者均为必需配置，每个模型配置 `url`（完整请求地址，程序原样请求，不追加路径）、`model`，以及可选的 `apiKey`（有密钥时以 `Authorization: Bearer` 发送，没有则不发送任何认证头）。三个模型各按一种通用协议请求：嵌入模型为 OpenAI Embeddings，reranker 为 Cohere/Jina Rerank，决策模型为 System One（TypeSafe 的原生决策接口即其一个服务）。决策模型接口与具体模型无关，只包含选择题。发给决策模型的问题一律使用英文，被判断的内容保持原文。

每个模型可配置 `provider`，省略即为通用协议；写 `cloudflare`（不区分大小写）则按 Cloudflare Workers AI 的格式收发，这是目前唯一的提供方适配。差异只有两处：reranker 发送 `query` 与 `contexts[].text`，不发送模型名（`model` 仍必填，只用于显示），按 `result.response[].id` 与 `score` 对回每段文档的分数；决策模型的请求与 System One 相同，响应先取 `result` 再按 System One 读取。嵌入模型接受 `provider: cloudflare`，按通用协议处理。Cloudflare 响应的 `success` 不为真或缺少 `result`，与其他格式错误一样视为格式不对、不重试。reranker 的每段文档都须得到且只得到一个分数，缺漏、重复或越界的序号同样是格式不对。重试、退避、单次超时、总时限与冷却由同一个模型客户端负责，两种提供方不分支；判断阈值与 `minRerankScore` 的默认值不随提供方或模型变化，换模型后的判断质量由使用者自行核对。

### 判断

| 判断 | 题型 | 确定时 | 拿不准时 |
| :--- | :--- | :--- | :--- |
| 新画像候选与已有候选或拒绝列表中的某条是否同一偏好 | 选择 | 并入该候选；命中拒绝列表则不记录并告知 | 新建候选 |
| 新建细节页与同项目已有页是否同一件事 | 选择 | 拒绝新建，列出该页 | 允许新建，留待体检 |
| 新活动与当天已有活动是否同主题 | 选择 | 退回已有活动，要求合并 | 单独记录 |
| 新写入的画像条目是否与已有条目冲突、重复或取代它 | 选择 | 拒绝写入，返回冲突条目的节、原文与短码，与用户确认后改用 `replace` 改写它 | 写入，留待体检 |

- 选择题最多 10 个选项（含"都不是"），候选按判断而定：重复页判断取同一所属项目内的嵌入近邻，同项目没有其他页时不提问；同主题判断取当天全部活动（不分项目）中最新的 9 条，当天没有活动时不提问；同一偏好判断取候选、拒绝列表与画像三处合并的嵌入近邻至多 9 条，选项标明来源与归属节，三处都为空时不提问；画像冲突判断取整份画像（跨四节）中嵌入最相近的至多 9 条，`replace` 时排除被替换的那一条，画像中没有其他条目时不提问。题意为"新条目是否与某条已有条目冲突、重复或取代它"，被判断的内容保持原文，选项附所在节。
- 服务只使用模型返回的概率，自行计算：选择题取最高概率。
- 每个判断在配置中设上下两个阈值，划出"确定 / 拿不准 / 否定"三档；未配置时用内置默认值（以真实中文样本测定）。选择题："都不是"的概率不低于其余任一选项时为否定；否则最高的选项不低于上阈值为确定，不高于下阈值为否定，其间为拿不准。实测中最高概率与第二名之差不改变任何结果，因此不参与划分。拿不准的情况不自动处理，由体检重新发现。
- 凭据检测不交给决策模型，只用内置正则，写入内容不会为了检测而离开本机。正则匹配以下常见格式，命中即拒绝：`sk-` 开头的密钥、`ghp_` 等 GitHub 令牌、`AKIA` 与 `ASIA` 开头的 AWS 访问密钥；Slack、GitLab、Google、阿里云、SendGrid、Docker Hub、Notion、Stripe live 等服务令牌；JWT、私钥块、URL 中的 `user:pass@`、`Bearer` 令牌、`password=`；键名以 pass、pwd、token、secret、api key、access key、session 结尾，用 `=` 或 `:` 赋值，且值不少于 6 个字符并含数字；40 字符以上且同时含大小写字母与数字的 base64。值为 `<…>`、`${…}`、`***` 等占位符或 `xxxx`、`your…` 时不算。没有格式特征的裸值（如口述的"密码是 …"）正则拦不住，靠三个写入工具说明中"禁止写入凭据"的要求约束。被拒绝时指出可疑片段的位置与开头 6 个字符，不回显整个片段；主会话确认无凭据后可带 `confirm_no_secret` 重新提交，此时跳过正则。检测范围是本次写入的标题、别名、小节名与正文；`delete_section` 不写入新内容，不检测。

### 降级

辅助模型不可用时不拒绝写入：

| 不可用 | 写入 | 检索 |
| :--- | :--- | :--- |
| 嵌入模型 | 照常写文件并提交；判断因无法取近邻而跳过，按拿不准处理；向量在模型恢复后按文件哈希补齐 | 只走全文 |
| reranker | 不受影响 | 按合并顺序返回，不精排 |
| 决策模型 | 所有判断按"拿不准"处理 | 不受影响 |

降级时返回结果末尾注明；启动时连不上任一模型不阻止启动，但在服务端说明与 `tacit status` 中提示。嵌入模型不可用时，沿用索引中记录的向量维度，恢复后再校验。

辅助模型的每次请求先在请求内重试，偶发错误不直接降级：

- 重试：网络错误、单次超时、HTTP 429 与 5xx，一次请求最多尝试 5 次。HTTP 401/403、400/404/422 及其他 4xx，以及响应格式不对（无法解析、向量长度不一致、概率缺项等），不重试，直接算失败。
- 退避：两次尝试之间依次等 0.5、1、2、4 秒；429 带 `Retry-After` 时按其等待。
- 总时限：一次请求从第一次尝试起最多 20 秒，含各次尝试与退避。每次尝试有 5 秒单次超时，但被总时限截断。时限用完即算失败，不再发起新尝试，也不等待超出时限的退避。
- 冷却：只有请求最终失败（5 次用尽、遇到不重试的失败或用完总时限）才记一次失败，该模型冷却 30 秒，冷却期间不调用，状态提示列出它。冷却结束后的下一次请求照常尝试，成功一次即恢复可用。重试过程中的失败不改变健康状态。

次数、退避与总时限不做成配置项。代价已接受：模型挂起时，一次实时写入最多等 20 秒才判定失败并降级，期间写入锁被占用；进入冷却后才恢复为立即跳过。

画像冲突判断在决策模型或嵌入模型不可用时照常写入，并在回复末尾注明判断被跳过。

## 5. 存储

```text
<记忆仓库>/
├── .gitignore              # 只含 .cache/
├── persona.md              # 画像
├── candidates.md           # 画像候选与拒绝列表
├── recent.md               # 近期主线
├── recent/YYYY-MM.md       # 活动记录（按月）
├── pages/
│   ├── <项目>/<slug>.md    # 细节页，目录名即所属项目
│   └── _topics/<slug>.md   # 专题
└── .cache/                 # 派生索引，不进 Git
```

### 通用写法

- 新建文件为 UTF-8 无 BOM、换行 LF，文件以换行结尾；修改已有文件时保留其原有的 BOM 与换行风格（含 CRLF）。列表项以 `- ` 开头，缩进两个空格。
- 日期一律 `YYYY-MM-DD`，按常驻服务所在机器的本地日期。
- 文件不写一级标题，从 `##` 开始分节；细节页标题只在 YAML 头的 `title` 中出现。
- 来源写在条目下一行的缩进 HTML 注释里：`<!-- 2026-10-25 原话「怎么又搜不到中文了」 -->`，原话可省略。活动记录的注释只含原话，日期由所在的日标题给出。
- 结构词（节名、`归属：`、`原话` 等）按记忆语言写入；解析时所有支持语言的结构词都识别。
- 所属项目名转为小写，只允许 `[a-z0-9._-]`；以下划线开头的名字保留给系统（如 `_topics`），以点开头的目录不算项目。

### 条目与短码

| 文件 | 一条 |
| :--- | :--- |
| `persona.md` | 一个顶层列表项 |
| `recent.md` | 一个顶层列表项；近期主线整体另有一个版本短码，用于整体改写 |
| `recent/YYYY-MM.md` | 日期标题下的一个列表项 |
| `candidates.md` | 一个三级标题及其出现记录 |
| 细节页 | 一个小节，以"页面标识 + 小节名"指代 |

服务返回条目时附带短码（规范化文本哈希的前 6 位，例如 `a3f9c2`），后续调用凭短码引用；短码不写进文件。内容完全相同的条目按出现顺序加后缀（`a3f9c2-2`）。条目内容一改，旧短码即失效：拿旧短码替换或删除会被拒绝并返回最新内容。

### 画像 `persona.md`

```markdown
## 红线
- 不要自行发布版本或推送到公开仓库；改为先请用户确认（理由：影响外部，无法撤回）
  <!-- 2026-10-25 原话「发布前必须问我」 -->

## 协作规则
- 需求不清时 → 先连续追问，确认后再给出完整方案
  <!-- 2026-10-20 原话「先问清楚再动手」 -->

## 偏好
- 沟通：先要结论，再看依据；反感客套和铺垫

## 档案
- 系统：Windows 11 x64，Shell 为 PowerShell 7
```

| 节 | 句式 | 上限（可配置） |
| :--- | :--- | :--- |
| 红线 | `不要 <行为>；改为 <替代做法>`，可加一句理由；英文记忆中"改为"的结构词为 `instead`，写作 `Don't <behaviour>; instead <alternative>` | 5 条 |
| 协作规则 | `<情境>时 → <做法>`，只用肯定句，理由可选 | 20 条 |
| 偏好 | `<维度>：<描述>`，描述句，可写"不喜欢……" | 15 条 |
| 档案 | `<字段>：<事实>`，不写行为要求 | 10 条 |

- 每条不含注释最多 200 字，一条只写一个情境和一个做法；不使用大写强调词。
- 修改逐条进行，不整篇重写；被取代的条目直接替换，历史由 Git 保留。

### 画像候选 `candidates.md`

```markdown
## 候选

### 沟通：先要结论，再看依据
归属：偏好
- 2026-10-28 原话「先说结论」
- 2026-10-30 原话「别铺垫，直接说结果」

## 拒绝列表

### 每次提交前都运行全量测试
归属：协作规则
- 2026-10-27 原话「跑一下全部测试」
- 2026-10-29 拒绝 原话「不用，只跑相关的」
```

- 三级标题即确认后写进画像的条目原文；出现天数按不同日期计数。
- 在不同日期出现满 2 天（可配置）可确认；确认后移入 `persona.md`。
- 拒绝列表永久有效；用户改主意时可直接要求写入画像。
- 提议写入候选时的标题补回与出现记录追加规则见第 6 节。

### 近期主线 `recent.md`

```markdown
## 近期主线
- TacitMemory 设计：从 Hindsight 转向自建，确定三个辅助模型配合与定期体检
```

最多 5 条（可配置），不要求日期。

### 活动记录 `recent/YYYY-MM.md`

```markdown
## 2026-10-31
- [tacit-memory] 决策模型定为只做判断，整理交给体检
  <!-- 原话「其实可以直接把记忆库当成项目」 -->
- 想清楚了画像里缺的是人的倾向，而不只是规范
```

每天一个二级标题，按写入顺序排列；属于项目的活动以 `[项目名]` 开头。长度与写法见第 6 节。

### 细节页

```markdown
---
title: 数据库升级后扩展丢失
aliases: [全文检索插件失效, 升级后搜索不到中文]
dates: { first: 2026-10-21, last: 2026-10-25 }
related: [my-app/backup-script, _topics/pgroonga]
---

## 现象
……

## 根因
……
```

| 字段 | 规则 | 由谁写 |
| :--- | :--- | :--- |
| `title` | 必填，最多 50 字 | 主会话 |
| `aliases` | 至少 2 个，每个最多 30 字；覆盖口语说法、中英文名与别称 | 主会话；可追加 |
| `dates` | 首次与最近一次经服务写入的日期 | 服务 |
| `related` | 其他页的页面标识；指向不存在的页时经服务写入被拒绝 | 主会话 |

- 页面标识为 `<所属项目>/<slug>`，slug 匹配 `^[a-z0-9]+(-[a-z0-9]+)*$`，在项目内唯一，创建后不可改名。
- 正文按 `##` 小节组织，小节名由主会话决定，页内不得重名。

### Git

- 首次初始化：`git init`，写入 `.gitignore`、各文件的节标题骨架与 `recent/`、`pages/` 下的 `.gitkeep`，提交 `init: create memory repo`。目录非空且不是 Git 仓库时拒绝初始化。
- 再次执行 `init` 不覆盖任何已有文件：记忆目录已是 Git 仓库时只补缺失的骨架文件，不提交，并列出已存在的文件。传入的 `--language` 或 `--memory` 与已有 `config.yaml` 不一致时拒绝执行。
- 每次经服务的写入自动提交一次，只提交本次写入的文件，作者固定为 `tacit <tacit@localhost>`。提交信息为 `<区域>: <动作> <对象>`，区域为 `persona`、`candidates`、`recent`、`pages` 之一，例如 `pages: create tacit-memory/db-upgrade`。
- 要写的文件含有用户未提交的修改时，连同修改一起提交，并在提交信息末尾注明。
- 体检的提交由主会话完成，提交信息以 `checkup:` 开头；服务据此识别上次体检的时间。

### 生成体检报告时当场解析

服务修改文件时只定位并改动要改的那几行，其余内容原样保留。格式不符合约定时照常解析；问题不在写入或索引同步时记录，而是生成体检报告时把全部记忆文件重新解析一遍当场得出（见第 9 节），修正后下次生成报告即消失。下表是各类情况的解析处理，问题本身的检查项见第 9 节：

| 情况 | 处理 |
| :--- | :--- |
| 细节页 YAML 头无法解析 | 照样建索引，`title` 取文件名 |
| 协作规则缺 `→`、红线缺"改为"、无法识别的节或内容 | 照样计数与渲染 |
| 某节超出上限 | 照样全部渲染；之后经服务写入该节被拒绝，直到删减到上限以内 |
| 日期格式错误 | 该条不参与基于日期的计算 |
| 文件不是 UTF-8 | 跳过该文件，在服务端说明中提示 |
| 活动记录中不在日期标题下的条目、无法识别的日期标题 | 不建索引、不进近期摘要，其余活动照常 |
| 混用不同语言的结构词 | 照常解析 |
| 画像、候选文件、活动记录与近期主线的格式问题 | 照常解析与渲染，问题只在体检报告中列出，写入路径与索引不使用 |

## 6. 写入

### 入口

写入只有两个入口，不使用客户端钩子，也不做会话结束后的后台补抽：

1. **记忆规则**：写在服务端说明中，主会话在对话中当场执行；
2. **记忆指令** `tacit-remember`（skill）：用户在压缩上下文、退出前或认为重要时触发。

主会话未遵守规则、用户也未执行指令就结束会话时，该段内容不会被记住。这是明确接受的代价。

### 值得记标准

`prompts/rules.md` 分"值得记"与"不记"两节（条数上限见第 12 节），原样写入服务端说明。初始化时生成默认模板；文件被删除后，下次加载配置时（启动服务、绑定、解绑）按记忆语言重新生成。旧位置 `TACIT_HOME/rules.md` 不再读取。

默认值得记：用户纠正或打断 Agent；方案拍板（保留用户原话）；查明根因的排错（含试过但无效的做法）；新的环境事实；用户明确要求记下。默认不记：常规的写代码、改错字、看日志；能从代码、仓库文档、配置中查到的内容。

### 通用规则

- **先检索再写**：命中已有页则更新该页，未命中才新建；一件事只对应一页。
- **读取不修改**：检索与读取不改动任何文件。
- **保留来源**：写入内容附带日期，必要时附用户原话。
- **不写凭据**：见第 4 节。

### 细节页

- 新建时提交整页；服务先用决策模型判断是否与已有页重复。
- 更新以小节为单位：新增或替换一个小节、删除一个小节、修改页头（追加别名、改标题或 `related`）。替换与删除须带原小节的短码。
- `section` 填的是本页某小节的短码（忽略大小写与首尾空白，且本页没有同名小节）时，`upsert_section` 与 `delete_section` 拒绝并给出该小节的标题；下一步：`section` 填小节名，`hash` 填该短码。不论 `hash` 是否已填都拒绝，不写入也不提交。像短码但不属于本页的值照常按小节名处理。
- 不提供整页重写；大幅调整在体检中直接改文件。

### 近期活动

- 写入时机：一件主事有了结论（定了决定、查明根因、阶段目标完成）时写一条；每个会话至多一条，之后有进展用 `replaces` 改写。
- 一条活动写"人在做什么、想通了什么"，不写"改了哪些文件"。
- 写入 `recent/YYYY-MM.md`，按本地日期定位当日标题；缺标题时追加到文件末尾。写入只改动新增的条目与来源注释，文件其余字节不变。
- 文本限一行，不超过 `limits.itemLength`（默认 200 字符，不计项目标签与来源注释），不以 `[` 开头；原话同样限一行，且不含 `-->`；项目名小写并校验，允许新项目。
- 写入后，服务返回当前近期主线（附版本短码）与自上次提交 `recent.md` 之日起的活动（新的在前，最多列 10 条，其余注明条数）；上次提交为 `init:` 或尚无提交时列出全部活动。主会话据此决定是否改写主线。
- 与当天已有活动同主题时（按第 4 节的选择题与三档，阈值为 `sameTopic`），服务不写入，以普通回复（非错误）退回该活动及其短码，不附主线与活动列表；主会话写出合并后的一句，带 `replaces` 重新提交。决策模型不可用时照常写入，回复中注明未检查；带 `replaces` 时不做同主题判断。
- `replaces` 只指向当天的活动：短码须是当天某条的短码。其他日期、已过期（条目改写后旧短码即失效）或不存在的短码都被拒绝，拒绝时列出当天的活动及其短码。改写在原位替换条目正文与项目标签；带 `source` 时替换来源注释，否则保留原注释。改写与新增经同样的参数校验与凭据检测，不做同主题判断，返回新短码，提交信息为 `recent: replace <短码>`。
- "每个会话最多一条"只写在记忆规则中，服务不强制。
- 近期主线：`update_mainline` 以版本短码整体改写，0 至 `limits.mainline`（默认 5）条，空列表即清空；`hash` 缺失或与当前版本不符时拒绝并返回当前主线与版本短码；内容未变时不写入也不提交。

### 画像

| 操作 | 允许的条件 |
| :--- | :--- |
| 新增协作规则、偏好或档案 | 用户明确要求记住 |
| 新增红线 | 只能由用户明确提出 |
| 替换、删除 | 用户明确要求修改或删除某一条 |
| 观察到的偏好或规则 | 只能提交为画像候选，并标明归属节 |

这些条件写在记忆规则中。服务对新写入的条目做冲突判断，见第 4 节。

`add` 的校验与写入：
- 句式只校验红线与协作规则：红线须含"改为"（英文记忆为 `instead`，两种写法都识别），协作规则须含 `→`；偏好与档案不校验句式。
- `text` 与 `source` 各限一行：不含 `\r`、`\n`、U+2028、U+2029、U+0085，即编辑器会显示为换行的字符；`source` 不含 `-->`；`text` 不计注释不超过 `limits.itemLength`。
- 条数上限（`limits.persona`）只约束 `add`：该节条目已达上限时拒绝，返回该节全部条目及短码；手动编辑超限后 `add` 被拒，`replace` 与 `delete` 不受上限约束。
- 追加在该节末尾，下一行写 `<!-- 当天日期 原话「…」 -->`；节标题缺失时按四节标准顺序补回：补在前面最近的已有节之后，前面都没有时补在后面最近的已有节之前，四节都没有时补在文件末尾；与写入同一次提交。
- `replace` 凭短码原位替换条目及其原话注释：条目留在原节，按原节校验句式与长度，并做画像冲突判断（排除被替换的条目）；新注释为当天日期与新原话，原条目没有注释时新增一行。提交信息为 `persona: replace <新短码>`；结果与原条目完全相同时不写入、不提交。
- `delete` 凭短码删除条目及其续行与原话注释，不需要原话；回复被删除的条目原文。提交信息为 `persona: delete <短码>`。
- `replace` 与 `delete` 不受条数上限约束，手动超限的节可经服务减下来。
- `propose` 的校验与写入：归属节为红线时拒绝，"下一步"为先问用户、明确同意后再 `add`；句式、长度与单行校验同 `add`（按归属节）；凭据检测覆盖原文与原话；不设条数上限。
- `propose` 追加在"候选"一节末尾，写成三级标题（原文）、`归属：<节名>` 与一条出现记录；"候选"标题缺失时补回拒绝列表之前，没有拒绝列表时补在文件末尾，与写入同一次提交。只提交 `candidates.md`，不重新渲染常驻区块；回复出现天数与门槛，不返回短码。
- `propose` 先做同一偏好判断（第 4 节）：命中候选则并入，在其出现记录末尾追加当天的原话，同日已有出现记录时不写入、不提交；命中拒绝列表或画像则不写入，告知拒绝时的日期与原话或画像中的短码。三处都为空时不提问，直接新建候选。

## 7. 检索

| 参数 | 必填 | 说明 |
| :--- | :--- | :--- |
| `query` | 与 `page` 二选一 | 自然语言查询，用记忆语言书写 |
| `page` | 与 `query` 二选一 | 页面标识：读取整页 |
| `project` | 否 | 只在该项目中检索 |
| `from`、`to` | 否 | 日期范围，由主会话把"上周"之类换算成日期 |
| `kind` | 否 | `pages` 或 `activities`；省略时两者都检索 |

流程：

1. 筛选：页面按所属项目与页面日期区间（与查询区间重叠即保留），活动按项目标签与所在日期；指定 `project` 时，未标注项目的活动不出现；
2. 全文检索（FTS5，BM25）与向量检索（余弦）各取前 30 条。全文检索中，中文切成相邻两字一组；英文与文件名按 `unicode61` 规则在标点处切分，查询以短语匹配，`env.ps1`、`UTF-8` 这类写法仍可命中；单字查询退回子串匹配。向量单位为：每个小节、每页的 `title + aliases`、每条活动（连同项目标签）；
3. 用倒数排名融合（RRF）合并，取前 30 条交 reranker；
4. 丢弃低于分数阈值的结果，返回前 5 条（均可配置）；一条不剩时明确返回英文 `No relevant memory.`。

结果以小节和单条活动为单位，每条结果标明是页面还是活动。同一页命中的多个小节合为一条结果，每个小节返回全文及短码，并列出该页其他小节的名字；页面级命中按开头几个小节呈现。每条活动单独一条结果，显示日期、短码与所属项目（无项目则省略），随后是活动正文。

画像与候选不进入检索结果，无论 `kind` 为何；它们的向量只供两项判断取嵌入近邻。

## 8. 注入

常驻内容按变化频率分两路：

| 通道 | 内容 | 何时更新 |
| :--- | :--- | :--- |
| 常驻区块 | 画像 | 服务启动时；绑定时；画像变化时；`prompts/resident.md` 变化时 |
| 服务端说明 | 核心规则、通用规则、语言规范、值得记标准、近期摘要、状态提示、已有项目、体检提示 | 所依据的记忆、`prompts/` 下的提示词文档或状态变化后重新生成，客户端连接时下发 |

两者都在下一次会话生效，正在进行的会话不会重新加载。

### 常驻区块

- 由 `<!-- tacit:begin … -->` 与 `<!-- tacit:end -->` 界定，内部以 `<user_memory>` 包裹；起止标记不完整或不唯一时拒绝改写；结果未变不写文件；区块外的内容从不改动。
- 外壳两段与四节引导语来自 `prompts/resident.md`，整份替换内置默认；文件缺失时用内置默认（即现有文字）。起止标记、`<user_memory>` 标签、节标题与画像条目仍由服务生成。格式与校验见第 12 节。
- `resident.md` 或 `persona.md` 变化后，去抖重渲染所有已绑定文件中的常驻区块；渲染彼此串行，失败只提示。连接时使用当前的 `resident.md`。
- 渲染时去掉来源注释；节标题使用英文，条目保持记忆语言。
- 每次渲染都重新读取 `bindings.json`，因此运行中的服务能感知新的绑定；`connect` 在绑定时立即渲染一次。

### 服务端说明

- 组成：开场、核心规则（`prompts/instructions.md`，缺失时为内置默认）、通用规则（代码提供，始终在核心规则之后）、语言规范与值得记标准是固定部分。长度上限、截断顺序、文件校验与运行中保存的处理见第 12 节。
- 记忆规则各条的内容与职责见 `docs/prompts.md` 第 4 节。
- 语言规范：记忆内容与检索语句使用记忆语言；用户原话、代码、路径、命令与专有名词保持原样。
- 值得记标准：`prompts/rules.md` 两节的条目原样写入；修改 `prompts/rules.md` 后，下一个会话生效。
- 状态提示：列出冷却中的辅助模型（请求重试后仍失败才进入冷却，见第 4 节）与因不是 UTF-8 而被跳过的页面文件、活动记录文件、画像与候选文件；无问题时省略。服务不为探测而调用模型。
- 近期摘要：近期主线 + 活动记录中最近 7 天的条目（超过 7 条取最新 7 条，新的在前），每条前补日期与项目标签；摘要中不附短码，主线也不带版本码。
- 已有项目：`pages/` 下不以 `_` 或 `.` 开头的目录，与所有活动记录中出现过的项目标签取并集，去重后按名称排序。
- 体检提示：距上次体检达到 `checkup.remindAfterDays` 天（默认 7），或有可确认的候选（按出现天数计，不做候选清理）时出现，位于服务端说明末尾、已有项目之后。内容：距上次体检的天数（以最近的 `checkup:` 提交为准，没有则以 `init:` 提交为准；两者都没有时写明从未体检过，视为到期）、可确认的候选数、格式问题数、主线是否过期，以及一句说明用户可以运行 `tacit-checkup` skill 开始体检。只有格式问题时不出现。生成时不调用任何模型，不显示重复页与冲突条目的数量。它属于动态部分，不计入固定部分的长度上限，计入总长，与状态提示一样不截断。

## 9. 体检

用户在任意目录通过 `tacit-checkup` skill 开始体检（omp 中的触发方式见 `README.md`，附加要求可省略）。该 skill 的正文只取决于代码与记忆语言，不读记忆仓库，依次包含：开场（现在开始体检；先读取资源 `tacit://checkup-report`，读不到就停下请用户运行 `tacit serve`；记忆仓库的绝对路径；直接用绝对路径改文件，并在该目录中执行 git，不要求当前目录是记忆仓库）、体检步骤、当前记忆语言的结构词对照表与候选块、拒绝列表条目的示例。体检报告不在正文中，由该资源现场返回（见第 10 节）。主会话依据报告直接修改记忆仓库中的文件，最后在记忆仓库中提交，提交信息以 `checkup:` 开头。

体检步骤（英文，按顺序）：

1. 直接修正标为"直接修正"的格式问题，不问用户；
2. 直接删除待清理的候选，不问用户；
3. 可确认的候选逐条问用户，可答"确认"、"拒绝"或"暂缓"：确认 → 移入画像对应节（原文为条目，下一行为当天日期与原话的注释），并从候选中删除；拒绝 → 移入拒绝列表，加一条带"拒绝"标记、当天日期的出现记录；暂缓 → 原样保留，下次体检照常再报；
4. 疑似重复的页、互相冲突的画像条目与超限的节逐项问用户，同意后再合并或改写；
5. 主线过期或超限时，依据最近一个月的活动记录重写 `recent.md` 的主线；
6. 整体审视画像：去重、合并措辞相近的条目，每处修改经用户确认；
7. 在记忆仓库中提交，信息以 `checkup:` 开头；没有改动时用 `--allow-empty` 提交。

上次体检是最近一次以 `checkup:` 开头的提交（空提交同样生效）；没有时取 `init:` 提交；两者都没有时视为从未体检。报告开头写明所用的基准提交。

体检报告在读取资源时现场计算，不保存中间状态。报告分六类，每类有英文标题；每类最多列 20 项，超出的写剩余数量与"处理完后再运行 `tacit-checkup` skill"；没有问题的类别写 None.，六类标题始终列出，不因全部无问题而省略。

| 类别 | 计算方式 | 状态 |
| :--- | :--- | :--- |
| 疑似重复的页 | 自上次体检以来变过的页（含未提交的修改，不含删除）与同项目嵌入近邻（至多 9 页、不含自身）交决策模型判断，问题与阈值沿用实时新建页面时的重复页判断；"确定"与"拿不准"两档收录并标明档位，同一无序页对只报一次 | 已实现 |
| 互相冲突的画像条目 | 上次体检后新增或改写的条目（按短码，含未提交的修改），与跨四节的近邻（至多 9 条、不含自身）交决策模型判断，沿用实时画像冲突的问题与阈值；"确定"与"拿不准"两档收录并标明档位，同一对只报一次 | 已实现 |
| 可确认的画像候选 | 出现天数（不同日期）达到 `candidates.minDays`，且不是确定与画像或拒绝列表中某条同一偏好的候选；拿不准的附"可能与某条相同"的提示 | 已实现 |
| 待清理的画像候选 | 每条候选（不分出现天数）与画像、拒绝列表的嵌入近邻做同一偏好判断；"确定"者列为待清理，写明相同的画像条目（短码）或拒绝列表条目 | 已实现 |
| 违反格式或规则 | 生成报告时重新解析全部记忆文件：细节页的 YAML 头、`title`、`aliases`、`related`、文件名与小节重名；文件是否为 UTF-8；混用不同语言结构词（仅提示；小节标题、归属行、原话或拒绝标记、列表项中的改为与 instead）；画像、候选文件、活动记录与近期主线的问题（见下） | 已实现 |
| 过期的近期主线 | `recent.md` 最近一次提交距今超过 `checkup.mainlineStaleDays` 天，附该提交日期 | 已实现 |

违反格式或规则按文件列出，每项标明文件、位置（行号或小节）与问题说明：画像（某节超出 `limits.persona` 条数、红线缺"改为"、协作规则缺 `→`、条目超过 `limits.itemLength`、无法识别的节或内容）、候选文件（候选块缺"归属"、无法识别的出现记录行）、活动记录（条目不在日期标题下、无法识别的日期标题、日期格式错误）、近期主线（超过 `limits.mainline` 条）。"某节超出上限"与"主线超出条数"标为问用户，其余为直接修正。修正后再运行 `tacit-checkup`，问题即消失；写入与索引不使用这些问题。

判断类别的做法：

- 疑似重复的页：变过的页与上次体检提交（没有则为 `init:`，都没有则为全部页）的工作区内容比较，内容不同的页文件计入，含新增、修改与未提交的修改，删除的页不计入。每个变过的页当作新页判断：选项为同项目的嵌入近邻，问题原文、选项数与 `decision.samePage` 阈值都与实时判断一致；同项目没有其他页时不提问。"确定"与"拿不准"两档收录并标明档位，"否定"不收；同一无序页对只报一次，若两页各判断一次而档位不同，取"确定"。
- 候选清理复用实时的同一偏好判断：问题原文、选项规模（近邻至多 9 条加"都不是"）与 `decision.samePreference` 阈值都不变，选项只取画像条目与拒绝列表，不含其他候选；两处都为空时不提问。
- 三档：确定 → 列为待清理，且不再列为可确认；拿不准 → 不列为待清理，达到门槛时在可确认条目上附"可能与某条相同"的提示；否定 → 两者都不列。
- 决策模型或嵌入模型不可用时，待清理一类标为"未检查"并说明原因；可确认的候选照常列出，并提醒主会话自行对照画像。限时到点使某候选的判断未完成时，同样附此提醒。

判断缓存、工作池与限时：

- 判断的概率按提问内容的哈希缓存在派生索引的 `judgment_cache` 表中。键为题型、问题说明、状态文本与按键排列的全部选项文本（含"都不是"）；值为模型返回的各选项概率。三档在读取时按当前阈值计算，改阈值不使缓存失效。只有体检读写缓存，实时写入的判断不读也不写。派生索引重建时缓存一并清空。
- 工作池：同时进行的判断不超过 `checkup.maxConcurrency`（默认 5），一个完成就补发下一个。工作池由服务共享，多次体检之间的并发合计也不超过该数。模型进入冷却后，尚未发出的判断不再发出，计为"未检查（模型不可用）"；已在进行的照常完成。
- 限时：`checkup.budgetSeconds`（默认 20）从各类别读取仓库并提交全部判断之后开始计时。到点时，已返回的结果写入报告；未返回的计为"未检查"，报告注明"还有 N 项未检查，再运行一次 `tacit-checkup` 接着算"；尚未取得并发槽位的判断不再发出，已取得槽位的判断照常读取缓存，缓存未命中且未到点才发出。已在进行的判断不取消，跑完后写入缓存，再运行一次 `tacit-checkup` 即可取得。读取仓库、解析与组装报告不计入预算。

## 10. 工具、资源与服务端说明

常驻服务以无状态方式提供三种 MCP 机制：工具、资源与服务端说明。资源只有一个，`tacit://checkup-report`（名为 `checkup-report`，`text/markdown`，描述写明只在运行 `tacit-checkup` skill时读取），读取时现场返回体检报告（`MemoryService.CheckupReportAsync`）；不使用资源模板、订阅与 `list_changed` 通知。不提供 prompt：`prompts/list` 恒答空列表，`prompts/get` 一律报错，因为 omp 不看能力声明、每次都请求 prompt 列表，请求失败就丢弃服务器。不使用 completions、elicitation、sampling、roots 与 logging。

### 工具

| 工具 | `op` | 必填参数 |
| :--- | :--- | :--- |
| `recall` | — | `query` 或 `page`；可选 `project`、`from`、`to`、`kind` |
| `write_page` | `create` | `page`、`title`、`aliases`、`sections`；可选 `related` |
| | `upsert_section` | `page`、`section`、`body`；替换时加 `hash` |
| | `delete_section` | `page`、`section`、`hash` |
| | `update_header` | `page`；`title`、`add_aliases`、`related` 至少一项 |
| `write_recent` | `add_activity` | `text`；可选 `project`、`source`、`replaces` |
| | `update_mainline` | `items`、`hash`（近期主线的版本短码） |
| `write_persona` | `add` | `persona_section`、`text`、`source`；可选 `confirm_no_secret` |
| | `replace` | `hash`、`text`、`source`；可选 `confirm_no_secret` |
| | `delete` | `hash` |
| | `propose` | `persona_section`、`text`、`source` |

- `persona_section` 取值为 `red_lines`、`working_rules`、`preferences`、`profile`；`write_page` 的 `section` 为小节名。写入凭据检测未通过时（`write_page`、`write_recent`、`write_persona`），可加 `confirm_no_secret` 重新提交。`update_mainline` 的规则见第 6 节。
- 参数结构扁平，由服务按 `op` 校验。
- `replace`、`delete` 缺短码或短码与任何画像条目都不符时，不按缺参数处理，而是拒绝并返回整份画像：按节列出，每节标明条数与上限，每条附短码；`delete` 不接受 `text`、`source`、`confirm_no_secret`，`replace` 不接受 `persona_section`。
- 标注：`recall` 只读、幂等、不访问外部世界，并请求客户端首轮即加载；三个写入工具非只读、有破坏性、非幂等、不访问外部世界。
- 返回 Markdown 风格的纯文本，不返回结构化数据。
- 参数缺失、短码过期、超出上限或违反规则时标记错误，按"拒绝 / 下一步 / 相关内容"三段返回，"下一步"是主会话可直接执行的动作。同主题活动被退回、候选并入已有候选、提议命中拒绝列表或画像属于正常分支，不标记错误。
- 参数名不在工具 schema 中的（未知参数）一律拒绝，每个未知参数一条 `Unknown parameter <名>.`，排在最前；同一次调用中缺 `op`、`op` 无效、放错 `op` 的已知参数一并列出，只拒绝一次。判断不看值：键在、名字不在 schema 中即为未知，值为 `null` 或空串也算；已知参数值为 `null` 仍按放错 `op` 的规则视为未给出。下一步：`op` 有效时列出该 op 的参数（`write_page` 另列 `page`）；`op` 缺失或无效时列出 `op` 的取值与工具的全部参数；`recall` 列出全部参数。拒绝不写文件、不提交，经调用记录路径记入日志，日志不含参数值。

### 记忆指令

两个记忆指令是 skill，与 `tacit-memory` 一样由代码生成到 `TACIT_HOME/skills/`，不读取记忆仓库：

| skill | 用途 | 正文依赖 |
| :--- | :--- | :--- |
| `tacit-remember` | 让主会话把本会话写进记忆（步骤见 `docs/prompts.md` 第 7 节） | 仅代码 |
| `tacit-checkup` | 让主会话依据体检报告整理记忆仓库（见本文第 9 节） | 代码与记忆语言；报告经资源 `tacit://checkup-report` 读取 |

两者 frontmatter 都含 `disable-model-invocation: true`，只由用户触发（触发方式见 `README.md`）。用户附在命令后的文字是本次的重点或附加要求，Agent 须遵从。`tacit-remember` 写完后列出写了什么：页面附页面标识，活动与画像条目附短码，候选附原文；不预先征求确认，与画像矛盾时先问用户。

## 12. 客户端、备份与运行

### 客户端与绑定

| 绑定写入 | 位置 |
| :--- | :--- |
| 常驻区块 | 上下文文件中起止标记之间的内容；上下文文件不存在时由 `connect` 创建，并记为 `createdContextFile` |
| skill 链接 | skill 目录下的 `tacit-memory`、`tacit-remember`、`tacit-checkup` 三个链接，分别指向 `TACIT_HOME/skills/` 下的同名目录 |
| 绑定记录 | `TACIT_HOME/bindings.json`，每条含 `client`、`contextFile`、`skillsFolder` 与 `createdContextFile`；三个链接的位置由 `skillsFolder` 与固定的三个 skill 名推出 |

绑定 = 客户端名称 + 上下文文件 + skill 目录。名称只是标签：只允许小写字母、数字与连字符，长度 1 到 32，大小写不同视为同一名称并以小写记录。两个路径都必填、没有默认值；开头的 `~` 展开为用户目录，记录的是绝对路径。tacit 不读写任何客户端的 MCP 配置：`connect` 打印 MCP 端点（`http://127.0.0.1:<port>/mcp`，传输方式 Streamable HTTP，建议的服务名 `tacit`），由用户在客户端中自行配置；改了 `server.port` 也须自行更新客户端中的配置。

`connect` 的检查顺序，任一步拒绝都不写任何文件：名称合规；同名记录的路径不同则拒绝，提示先 `disconnect`；上下文文件的上一级目录存在；skill 目录存在（不存在时拒绝，不创建）；三个链接位置无冲突（不存在，或已是指向 tacit 对应 skill 的链接）；严格加载配置与画像；上下文文件是 UTF-8 且标记完整。通过后依次生成三个 skill、写常驻区块、建立缺失的链接、写绑定记录；其后某一步失败时撤回本次新建的链接。同名同路径重复执行是安全的：补齐缺失的链接，常驻区块按当前画像重写。

`disconnect --client <名称>` 只需名称，路径取自记录：移除常驻区块（文件变空且 `createdContextFile` 为真时删除文件）与指向 tacit 的三个链接，别人的同名项保留并报告；文件或链接已不在时逐项报告缺失，照常删除记录，以 0 结束；名称不存在时以 1 结束。只宽松读取语言，配置无效时照常工作。

共用：多个绑定可以指向同一个上下文文件或同一个 skill 目录（如两个客户端都读取 `~/.agents/skills`）。

- 路径比较用规范化后的完整路径（去掉末尾分隔符）。Windows 上忽略大小写，其他平台区分大小写。tacit 不解析目录联接与软链接：经两个不同入口指向同一目录的，被当作两处。
- `connect` 遇到已被其他绑定引用的上下文文件：不写第二个常驻区块，文件中始终只有一个；新记录的 `createdContextFile` 继承已有记录的值；报告「已由 `<名称>` 使用」。遇到已被引用的 skill 目录：已指向 tacit 的链接视为复用，报告同样说明复用了谁的路径。
- `disconnect`：仍被其他绑定引用的上下文文件不动，报告「仍被 `<名称>` 使用，保留」；无人引用时才移除常驻区块，文件变空且 `createdContextFile` 为真则删除。skill 目录同理：仍被引用时链接全部保留，无人引用时只删指向 tacit 的链接。
- 渲染所有常驻区块时按规范化路径去重：同一文件一次渲染只写一次、只产生一个结果。
- `status` 绑定栏：每条绑定注明与之共用路径的其他绑定；共用路径只检查一次，问题挂在第一个引用它的绑定上，其余绑定只注明共用。

链接的形式：Windows 用目录联接（不需要管理员权限），其他平台用软链接。三个位置中任一被占用（同名的目录或文件，或指向别处的链接）时，`connect` 整体拒绝并指出冲突的位置：三个链接一个都不建，skill 成品与其他文件也不写，不回退为复制。链接无法建立（如 `TACIT_HOME` 位于网络盘）时同样拒绝。`disconnect` 只删除指向 tacit 的链接本身，不跟随链接删除目标，skill 成品保留。

### 记忆 skill

- 位置：`TACIT_HOME/skills/tacit-memory/SKILL.md`，由代码生成，用户不直接修改；成品结构与各部分的措辞见 `docs/prompts.md` 第 11 节。`prompts/skill.md` 存在且非空白时，末尾接 `## User conventions` 一节。
- `prompts/skill.md` 的长度与格式规则见下文「提示词文档」。
- 生成时机：服务启动时；`prompts/` 下的文件变化时；门面的 `GenerateSkills` 操作（返回三个 skill 各自的路径与是否写入），不需要服务运行；`connect` 绑定时也调用它。内容不变时不写文件。
- 两个记忆指令与记忆 skill 同时生成。`tacit-remember` 的成品只取决于代码，`tacit-checkup` 只取决于代码与记忆语言；两者都不读取记忆仓库，也不读 `prompts/`，没有覆盖或追加文件，个人要求在触发时附上即可。
- 不进入自动备份。系统部分正文的措辞验证方式见 `docs/testing.md` 第 4 节。

### 备份与恢复

- 所有备份（自动、手动、保险与云端）的打包方式相同，zip 内容为：记忆仓库（含 `.git`，不含 `.cache`）、`config.yaml`、`prompts/` 目录（含 `rules.md`、`instructions.md`、`resident.md` 与 `skill.md`）、`bindings.json` 与清单（`manifest.json`：生成时间、tacit 版本、`kind`、记忆仓库 HEAD 的提交号与提交说明、文件列表）。生成的记忆 skill（`skills/`）不进入备份。配置中含明文密钥时备份时提示。
- 自动备份（`backups/auto-YYYY-MM-DD.zip`）：每天第一次写入后生成一份，只清理 `auto-*`，保留最近 `backup.keep` 份（默认 7；`0` 只关闭自动备份）。
- 手动备份（`backups/manual-YYYY-MM-DD-HHmmss.zip`）：`tacit backup` 立即生成，在写入队列中打包，拿到某次写入之后的完整状态；`--to <目录>` 写到指定目录（不存在则创建）。不计入 `backup.keep`，永不自动清理。
- 保险备份（`backups/pre-restore-YYYY-MM-DD-HHmmss.zip`）：恢复前自动生成，不清理、不上传。
- 时间戳为本地时间；同一秒内重名时拒绝，不覆盖已有文件。
- 云端备份（`tacit backup --remote`）：现场打包（在写入队列中，拿到某次写入之后的完整状态），上传为 `backup.webdav.url` 目录下唯一的 `tacit-backup.zip`，已存在则替换。只在执行命令时上传，不自动进行；本地不留副本，本地备份也不上传。zip 原样上传，不抹掉其中的密钥。
- 替换是原子的：先把 zip `PUT` 为 `tacit-backup.zip.part`，再 `MOVE` 到 `tacit-backup.zip`（`Overwrite: T`），上传中途失败时远端旧的那份保持不变。远端目录不存在时对目录 `MKCOL`（只建最后一级）后重试一次上传。服务不支持 `MOVE`（405 或 501）时报错"该 WebDAV 服务不支持原子替换"，不回退为直接覆盖。替换失败（上传或 `MOVE` 失败，含不支持 `MOVE`）时尽力删除 `.part`，删除失败不影响报错。
- 只使用通用 WebDAV 方法与 HTTP 基本认证；`username` 省略时不发送认证。每个请求（含响应体的读取）单独计时，超过 10 分钟即失败（硬编码），请求本身不重试（父目录缺失时的 MKCOL 与重传见上文）。错误信息说明阶段（连接、认证、上传、替换、下载）与 HTTP 状态码，不含密码与 URL 中的凭据。
- 每次尝试的时间与结果（成功，或失败原因）记入 `backups/remote.json`，`tacit status` 的备份栏据此显示最近一次云端备份；该文件不进入任何备份，状态显示不访问网络。
- 恢复（`tacit restore --from <zip> [--include-config] [--yes]` 本地备份，或 `tacit restore --remote [--include-config] [--yes]` 云端备份）由常驻服务执行，先预览：备份的生成时间、tacit 版本、`kind`、记忆仓库 HEAD 的提交号与说明、文件数，以及将被替换的内容。未加 `--yes` 时等待输入 `y`，其余输入一律取消（退出码 1）；标准输入不是终端时不等待，预览后以用法错误（退出码 2）结束，不发出执行请求。
- 拒绝且什么都不改的情况：清单缺失、无法解析或与内容不符；缺少 `memory/.git/`；条目不在允许的位置（只能是 `memory/`、`prompts/` 或根下的 `config.yaml`、`bindings.json`、`manifest.json`），或含 `..`、绝对路径。
- 确认后，执行顺序：等在途的后台任务结束 → 停止两个监听、关闭派生索引 → 生成保险备份（失败即中止）→ 把备份的 `memory/` 解压到 `memory.path` 内的隐藏暂存目录 `.tacit-restore-<id>`，当前内容移到同处的隐藏目录 `.tacit-previous-<id>`，暂存内容再移入（`memory.path` 目录本身保留，`.cache/` 不动；两个隐藏目录与记忆仓库同卷，移动均为重命名，不依赖 `memory.path` 的父目录所在卷；索引重建与备份都不把它们当作内容）→ 加 `--include-config` 时先把 `config.yaml` 写到 `TACIT_HOME/restore-<id>` 下的临时位置再替换，`prompts/` 整体替换（备份中没有的文件删除），并读取恢复回来的配置以确认能否加载，不能加载时照常完成并在结果中附错误（列出键路径），提示重启 `tacit serve` 前需修正 → 全量重建索引 → 删除两个隐藏目录与 `TACIT_HOME/restore-<id>`（上述删除在重建成功之后才执行，重建失败时仍可撤销换入）→ 恢复监听 → 加 `--include-config` 时重载提示词 → 使服务端说明失效 → 重新渲染常驻区块。
- `bindings.json` 永远不恢复。记忆仓库恢复到当前配置的 `memory.path`；恢复回来的 `config.yaml` 指向另一个路径时只提示，不搬目录。运行中的服务继续使用当前加载的配置。
- 换入之后任一步失败：记忆仓库逆序撤销换入，回到恢复前的内容，监听与索引照常恢复，错误附保险备份路径。
- 结果：保险备份路径、恢复后的 HEAD、索引重建的文件数、单元数与向量数；加 `--include-config` 时附"`config.yaml` 重启 `tacit serve` 后生效"；恢复回来的 `memory.path` 不同时附"重启后会指向 X，记忆仓库已恢复到 Y"。
- 云端恢复（`--remote`）：服务先把远端的 `tacit-backup.zip` 下载到 `backups/.download/tacit-backup.zip`（覆盖已有文件），校验后预览，预览中给出下载文件的本地路径。确认后以这个路径走上面的同一条恢复流程，所以确认的与恢复的是同一个文件；恢复成功后删除该文件，失败则保留以便排查。远端没有备份时提示"远端没有云端备份"；认证、连接与下载失败沿用云端备份的阶段提示。`.download/` 不是备份：不计入 `status` 的最近本地备份，也不被清理逻辑触及。

### 配置

配置目录为 `TACIT_HOME`（默认 `~/.tacit`），包含 `config.yaml`、`prompts/`（提示词文档）、`skills/`（生成的记忆 skill）、`bindings.json`、`backups/` 与 `logs/`。环境变量只用于指定 `TACIT_HOME`、提供密钥与关闭终端美化：`TACIT_EMBEDDING_API_KEY`、`TACIT_RERANKER_API_KEY`、`TACIT_DECISION_API_KEY`（三个模型的密钥）与 `TACIT_WEBDAV_PASSWORD`（WebDAV 密码）两处都有时以环境变量为准；`NO_COLOR` 的规则见下文「运行」。

```yaml
server:
  port: 18888
memory:
  path: ~/.tacit/memory       # 默认为 $TACIT_HOME/memory
language: zh

models:                       # 必填，无默认值
  embedding: { url: …, model: …, apiKey: … }   # url 为完整请求地址，原样请求，不追加路径；apiKey 可省略，改设环境变量 TACIT_EMBEDDING_API_KEY
  reranker:  { url: …, model: …, apiKey: … }   # url 为完整请求地址；apiKey 可省略，改设环境变量 TACIT_RERANKER_API_KEY
  decision:  { url: …, model: …, apiKey: … }   # url 为完整请求地址；apiKey 可省略，改设环境变量 TACIT_DECISION_API_KEY

limits:
  persona: { redLines: 5, workingRules: 20, preferences: 15, profile: 10 }
  itemLength: 200
  mainline: 5
  page: { titleLength: 50, aliasLength: 30, minAliases: 2 }
candidates: { minDays: 2 }
checkup: { remindAfterDays: 7, mainlineStaleDays: 14, budgetSeconds: 20, maxConcurrency: 5 }   # budgetSeconds：一次体检最多等模型的秒数；maxConcurrency：同时进行的模型判断数
decision:                     # 各判断的上下阈值
  samePreference: { certain: …, unlikely: … }
  samePage:       { certain: …, unlikely: … }
  sameTopic:      { certain: …, unlikely: … }
  ruleConflict:   { certain: …, unlikely: … }
retrieval: { candidates: 30, topK: 5, minRerankScore: … }
backup: { keep: 7, webdav: { url: …, username: …, password: … } }   # 云端备份（WebDAV）；password 可省略，改设 TACIT_WEBDAV_PASSWORD
```

- 除 `models` 外各项均有默认值；判断阈值与 `minRerankScore` 的默认值内置。向量维度在启动时由嵌入模型的返回确定。
- `models.<模型>.provider` 可省略（即通用协议），写 `cloudflare`（不区分大小写）选用 Cloudflare 适配；其他值按配置错误报告，并列出可用取值。三个模型的 `model` 都必填，包括 Cloudflare 的 reranker（它的模型名在 URL 中，`model` 只用于显示）。
- 密钥：`models.embedding.apiKey`（`TACIT_EMBEDDING_API_KEY`）、`models.reranker.apiKey`（`TACIT_RERANKER_API_KEY`）、`models.decision.apiKey`（`TACIT_DECISION_API_KEY`）与 `backup.webdav.password`（`TACIT_WEBDAV_PASSWORD`）各有固定的环境变量名；环境变量非空时优先，否则用配置中的值，两处都没有即为未设置。辅助模型没有密钥不是错误，请求不带认证头；WebDAV 只有写了 `username` 时密码必填，两处都没有时加载配置报错，指出键路径与变量名。`models.<模型>` 的 `url` 与 `model` 必填，`url` 须为 http 或 https 绝对地址，原样保存，不补也不删末尾的 `/`；映射中只认 `provider`、`url`、`model`、`apiKey`，`endpoint` 等其他键按未知键报错。`backup.webdav.url` 必填，须为 http 或 https 地址，末尾补 `/`。`apiKeyEnv` 与 `backup.remote` 已删除，按未知键报错。

### 提示词文档

`TACIT_HOME/prompts/` 下的文档在启动与运行中保存时按以下规则检查；长度上限均以字符计。

- **固定部分**（开场、核心规则、通用规则、语言规范与值得记标准）合计不超过 2500 字符。启动时超出则拒绝启动，报告超出的字符数，并列出可精简的文件（`rules.md`；存在 `instructions.md` 时一并列出）。
- **服务端说明**总长不超过 4000 字符。生成时超出则依次截断近期摘要中最早的活动，再从末尾起截断已有项目列表，列表无法容纳时整段省略；固定部分、状态提示与体检提示不截断。
- **核心规则**（`instructions.md`）中独占一行的 HTML 注释（`<!-- -->`）下发前删去，不计入长度；与文字同行的注释原样下发。
- **值得记标准**（`rules.md`）：「值得记」与「不记」两节各最多 10 条，条目为顶层 `- ` 列表项。缺失时按记忆语言重新生成。
- **常驻区块**（`resident.md`）全文不超过 1500 字符，换行按 LF 计，末尾空行也计入。开头为外壳正文，之后以 `## red_lines`、`## working_rules`、`## preferences`、`## profile` 分节，小节标题须与名称完全一致。出现其他小节标题或同一小节出现两次时拒绝启动，并指出文件与行号。缺少某一节时，该节只显示条目，不显示引导语。
- **记忆 skill**（`skill.md`）不超过 3000 字符，不能以 frontmatter（开头的 `---` 部分）起始。
- 以上文档均不检查语言。
- 运行中保存时逐个文件检查：某文件出错则只它沿用上一版并提示，其余文件照常生效。`rules.md` 与 `instructions.md` 合计超过固定部分上限时两者都沿用上一版。

### 运行

- 单一常驻 HTTP MCP 服务，只监听 `127.0.0.1`，不做鉴权：本机视为可信边界。管理 API（`/api`）另有 Origin、Host 与 POST 的 Content-Type 三道防护，拒绝外部网页、DNS 重绑定与非 JSON 的 POST 请求（防护细节见 `docs/architecture.md` 第 5 节）。记忆工具的读写、服务端说明与体检报告资源的生成、后台的索引同步与常驻区块渲染、提示词重载共用一把读写锁：写入与后台任务之间串行，读取彼此共享；维护操作（`reindex`，以及恢复）独占，期间上述操作排队等待，完成后照常执行。服务未运行时记忆工具不可用，已写入的常驻区块仍然有效。
- 启动时按文件哈希比对增量同步索引；运行时监听记忆仓库，文件变化即同步对应索引，画像变化时重新渲染常驻区块。
- 索引记录表结构版本不一致时删除并全量重建；嵌入模型名或向量维度与记录不一致时只丢弃向量，全文索引保留，向量按文件哈希补齐。
- 日志写入 `TACIT_HOME/logs/tacit-YYYYMMDD.log`，只有 `serve` 写入：按天一份，保留最近 14 份，级别从 Information 起，格式为「时间 级别 消息」；ASP.NET Core 与 MCP SDK 的日志只写警告。记录的事件：启动（版本、端口、记忆仓库路径）、监听地址、端口被占用、常驻区块渲染结果、提示词重载、索引同步失败、辅助模型最终失败与冷却、管理 API 每次调用（方法、路由、状态码、耗时）、记忆工具每次调用（工具、`op`、页面标识或短码、结果、耗时）；维护操作的开始、结束与失败（耗时）；索引重建的结果（文件、单元、向量、跳过的非 UTF-8 文件）与向量待补；自动、手动与保险备份的写入与失败，明文密钥提示；云端备份的上传、下载与失败，以及 `remote.json` 写入失败；恢复的开始、完成、回退与回退失败，以及临时目录未能删除。消息语言随记忆语言。不记录记忆正文、原话、查询文本、提示词内容、密钥与 WebDAV 密码。

| 命令 | 作用 | 需要服务运行 |
| :--- | :--- | :--- |
| `tacit init [--language zh\|en] [--memory <路径>]` | 生成配置模板并创建记忆仓库 | 否 |
| `tacit serve` | 启动常驻服务；未初始化时报错 | — |
| `tacit connect` / `tacit disconnect` | `connect --client <名称> --context <文件> --skills <目录>`（三个选项都必填）；`disconnect --client <名称>`，路径取自绑定记录 | 否 |
| `tacit show instructions\|resident\|skill [--default]`、`tacit show tools\|remember\|checkup` | 查看 Agent 收到的内容，标明每一部分的来源（代码、内置默认或用户文件）与长度；`--default` 输出内置默认文本（`skill` 只输出系统部分）。`tools` 先严格加载配置，再由 CLI 经 `TacitMemory.Mcp` 读取，说明中的上限取自该配置；`remember` 与 `checkup` 输出对应 skill 的成品（不含体检报告）。`remember`、`checkup` 与 `tools` 不接受 `--default` | 否 |
| `tacit status` | 服务（地址、版本、运行时长）、辅助模型的可用与冷却（含剩余秒数）、绑定（上下文文件是否存在且为 UTF-8、起止标记完整且唯一、三个 skill 链接是否都指向 tacit，缺哪个就指出哪个）、上次体检（日期与距今天数，从未体检时写明）、待处理问题（可确认的候选、格式问题、主线是否过期，口径与体检提示相同）、最近本地备份（三种前缀中最新的一份）、云端备份（`backups/remote.json` 记录的最近一次结果，不访问网络）、日志位置、密钥来源（环境变量或配置文件，不显示值）。服务未运行时写明"服务未运行"，服务栏始终给出 MCP 端点（`http://127.0.0.1:<端口>/mcp`），省略服务运行时数据与辅助模型，其余各栏照常（退出码 4）。`config.yaml` 无法加载时（有错误、文件不存在或记忆仓库未初始化）列出原因，有错误时列出全部错误的键路径；此时仍宽松读取 `server.port`（读不出、文件不存在或 YAML 无法解析时为 18888）与 `language`（读不出时取系统界面语言）探测服务：服务在运行则并入它的各栏，未运行或端口被他人占用则在服务栏注明，退出码均为 3。配置有效时退出码只看服务：应答并给出报告为 0；服务拒绝给出报告，或离线报告读取遇到 IO 或权限错误，为 1（原因写入 stderr）；无应答或端口被他人占用为 4；不因模型冷却或待处理问题而变化。不访问网络，不调用模型 | 否 |
| `tacit reindex` | 全量重建派生索引（全文、向量、判断缓存）：删除并重建索引文件，按文件重新同步，等待向量补齐后输出文件数、单元数、已有向量的单元数、跳过的非 UTF-8 文件与耗时；嵌入模型不可用时只重建全文并注明向量待补。维护操作，期间记忆工具排队等待 | 是 |
| `tacit backup [--to <目录>] [--remote]` | 立即生成手动备份（不给选项时写到 `TACIT_HOME/backups/`，`--to` 写到指定目录）；`--remote` 上传云端备份，远端只保留一份；两者不能同时使用 | 是 |
| `tacit restore --from <文件>\|--remote [--include-config] [--yes]` | 从本地备份或云端备份恢复：先显示预览，输入 `y` 后执行（`--yes`，短写 `-y`，跳过确认）；`--from` 与 `--remote` 恰好给一个；`--include-config` 一并恢复 `config.yaml` 与 `prompts/`；`--remote` 先下载云端备份，确认的即恢复的文件 | 是 |

退出码（所有命令一致；`status` 的取值见表后）：

| 码 | 含义 |
| :--- | :--- |
| 0 | 成功；`status` 中表示服务在运行 |
| 1 | 运行失败：服务拒绝、IO 或权限错误、`serve` 端口被占、`restore` 未确认 |
| 2 | 用法错误：未知命令或选项、缺参数、参数值非法、互斥选项冲突、非终端下 `restore` 未带 `--yes` |
| 3 | 配置无效：`config.yaml` 缺失或有错、记忆仓库未初始化、提示词文档违反限制。只有严格加载配置的命令会返回：`serve`、`connect`、`status`、`reindex`、`backup`、`restore`，以及不带 `--default` 的 `show instructions`、`show resident`、`show skill`、`show remember`、`show checkup`、`show tools`；`init`、`disconnect` 与带 `--default` 的 `show` 不会返回 |
| 4 | 服务未运行，含端口被其他程序占用 |

结果写 stdout；错误与确认提示写 stderr。`restore` 在标准输入不是终端且未带 `--yes` 时以 2 结束，不挂起等待。
`status` 的取值：配置无效为 3（即使服务拒绝报告，拒绝原因也只写入 stderr）；配置有效时，服务应答并给出报告为 0；服务拒绝给出报告，或离线报告读取遇到 IO 或权限错误，为 1，原因写入 stderr，stdout 不输出报告；无应答或端口被其他程序占用为 4。多余参数为用法错误 2。

输出美化只在终端中进行，且每一路（stdout、stderr）各自判断：该路是终端且未设置环境变量 `NO_COLOR` 时美化，否则输出与美化前逐字相同的纯文本，不含任何控制字符。美化只改变排版与颜色，不新增任何文字，中英两种记忆语言下的内容一致。范围与颜色规则如下：
- `status`：每栏的标题与行放进面板。颜色由各栏已有的结构化字段决定：服务正常为绿色、未运行为黄色；模型可用为绿色、冷却中为黄色；绑定无问题为绿色、有问题为红色；待处理的计数均为零且主线未过期为绿色，有计数或主线过期为黄色，无法读取为红色；云端备份最近一次成功为绿色、失败为红色；配置栏总是红色。
- `restore` 预览：`Report` 放进面板，将被替换的条目高亮。
- 等待转圈：`reindex`、`backup --remote` 与 `restore` 的执行阶段，stderr 为终端时显示转圈与已用时间，不显示百分比，结束即清除。
- `connect`：端点三行（端点、传输方式、建议的服务名）放进面板，其余照常。

- `init` 在服务首次启动前创建记忆仓库，是唯一不经常驻服务写入记忆仓库的入口；`connect` 写客户端文件、客户端 skill 目录中的链接、`bindings.json` 与三个 skill 成品，`disconnect` 写客户端文件、链接与 `bindings.json`；两者加载配置时都会按上文补写缺失的 `rules.md`，只有 `connect` 生成 skill。
- `show` 与 `init`、`connect` 一样直接调用门面，不读写常驻服务的状态；输出不含运行时状态（调用失败的辅助模型、非 UTF-8 文件）。
- 上表为 v1 的目标命令；各命令的实现状况见 `docs/architecture.md`。

## 13. 不做的事（v1）

| 不做 | 原因或归属 |
| :--- | :--- |
| 任务交接（上次停在哪） | 由客户端负责 |
| 保存原始会话 | 由客户端负责 |
| 客户端钩子、后台补抽 | 写入只依靠记忆规则与记忆指令 |
| 服务内调用生成式对话模型 | 生成与改写由主模型完成，整理由体检完成 |
| 人格注入 | 语气由客户端与画像中的偏好决定 |
| 主动浮现往事 | 细节只在被提起时检索 |
| 按项目的常驻内容 | 项目约定应写在项目自己的仓库文档中 |
| 统计页面命中、清理久未命中的页 | 旧页不干扰检索，统计需额外状态 |
| 永久的条目编号 | 条目引用都是短时的，用短码 |
| 自动校准判断阈值 | 尚无标注数据，阈值手动配置 |
| elicitation、sampling 等 MCP 机制 | 客户端支持不足或规范已弃用 |
| 资源模板、订阅与 `list_changed` 通知 | 当前只有体检报告一个资源，无需；其他资源（如今天的活动）未做 |

## 14. 扩展

扩展时遵守：

- **所有入口经常驻服务**：TUI、Web UI 等新界面只调用常驻服务，不直接读写记忆仓库或索引。
- **规则只有一份**：新能力先在核心实现，再由各入口调用。
- **文件始终可直接编辑**：界面是便利，不是必需。
- **配置向后兼容**：新增配置项必须有默认值。

已知方向：Web UI（浏览、审核候选、检索调试）、TUI、以支持 logprobs 的对话模型实现决策模型接口、更多客户端适配、按项目的常驻内容、更换索引引擎。
