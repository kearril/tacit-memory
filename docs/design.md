# TacitMemory 设计

本文档定义系统**做什么**：记忆如何分层、如何存储、何时写入、如何检索与注入、对外暴露哪些接口。代码如何组织见 `docs/architecture.md`，术语见 `GLOSSARY.md`。

## 1. 目标

让 Agent 像一个可靠的老朋友：记得用户的偏好与习惯，记得用户最近在做什么，提起具体的事时能想起细节；不记得时直说，不编造。

| 场景 | 用户说 | 期望的反应 | 依靠 |
| :--- | :--- | :--- | :--- |
| 新开会话 | "帮我写个脚本" | 直接按用户习惯的语言和方式回应，不用重新交代 | 画像 |
| 随口聊 | "最近有点累" | 能联想到用户最近在忙的事，但不复述近况 | 近期摘要 |
| 提起一件事 | "上次数据库升级那个坑" | 先检索，再按记忆回答现象、根因和解法 | 细节页 |
| 提起没记过的事 | "上次部署那个问题" | 说没有这方面的记忆，再问细节 | 记忆规则 |
| 没提起 | 聊别的 | 不主动翻旧账 | 细节页不常驻 |

## 2. 原则

1. **只存环境里拿不到的信息**：记忆只保存 Agent 无法从代码、仓库文档、配置、客户端会话历史中获得，且会改变其行为的信息。
2. **按进入上下文的方式分层**：常驻内容在会话开始时就在上下文中，一定被看到；按需内容由 Agent 主动检索，前提是它知道去取。
3. **常驻只能依据开局信号**：会话开始时只知道工作目录、客户端和时间。只在特定话题下才相关的内容一律按需检索。
4. **文件是唯一真相源**：所有记忆都是人类可读、可直接编辑的 Markdown 文件，存放在独立的 Git 仓库中；派生索引随时可删除重建。
5. **理解与生成交给主模型，判断交给辅助模型**：写什么、怎么写、如何改写由主会话完成；常驻服务借助辅助模型做召回、排序和结构化判断，自身不调用生成式对话模型。
6. **实时写入求快，批量整理靠体检**：对话中的写入可以不完美；合并重复、精简画像、确认候选等整理工作在体检中完成。
7. **画像只是记忆**：常驻内容是可能过时的背景，优先级低于项目上下文文件与当前对话中的用户指令。

## 3. 三层记忆

| 层 | 内容 | 进入方式 |
| :--- | :--- | :--- |
| **画像** | 红线、协作规则、偏好、档案四节 | 常驻：写入常驻区块 |
| **近期活动** | 近期主线 + 按月存放的活动记录 | 近期摘要常驻：写入服务端说明；活动记录按需 |
| **细节页** | 一件事或一个主题一页，按小节组织 | 按需：被提起时检索 |

## 4. 辅助模型

| 模型 | 职责 |
| :--- | :--- |
| 嵌入模型 | 生成向量，用于检索召回与判断前的近邻筛选 |
| reranker | 对检索候选精排，并按分数阈值过滤 |
| 决策模型 | 回答结构化判断，题型为选择、打分、真伪，返回各选项概率 |

三者均为必需配置。决策模型接口与具体模型无关，只包含三种题型；首个实现为 TypeSafe Jev 的原生决策接口。发给决策模型的问题一律使用英文，被判断的内容保持原文。

### 判断

| 判断 | 题型 | 确定时 | 拿不准时 |
| :--- | :--- | :--- | :--- |
| 新画像候选与已有候选或拒绝列表中的某条是否同一偏好 | 选择 | 并入该候选；命中拒绝列表则不记录并告知 | 新建候选 |
| 新建细节页与同项目已有页是否同一件事 | 选择 | 拒绝新建，列出该页 | 允许新建，留待体检 |
| 新活动与当天已有条目是否同一主题 | 选择 | 退回已有条目，要求合并 | 单独记录 |
| 新写入的画像条目是否与已有条目冲突或取代它 | 选择 | 拒绝写入，返回冲突条目的短码，要求改用替换 | 写入，留待体检 |
| 写入内容是否含凭据 | 真伪 | 拒绝写入 | 拒绝写入 |

- 选择题的候选来自嵌入模型的近邻，最多 10 个选项（含"都不是"）。
- 服务只使用模型返回的概率，自行计算：选择题取最高概率与它和第二名的差，真伪题取为真的概率，打分题取期望与标准差。
- 每个判断在配置中设上下两个阈值，划出"确定 / 拿不准 / 否定"三档。拿不准的情况不自动处理，由体检重新发现。
- 凭据检测先用内置正则匹配常见格式（`sk-`、`ghp_`、`AKIA`、私钥块、`password=`、长 base64 等），命中即拒绝；未命中再交决策模型。被拒绝时指出可疑片段，主会话确认无凭据后可带 `confirm_no_secret` 重新提交。

### 降级

辅助模型不可用时，除凭据检测外不拒绝写入：

| 不可用 | 写入 | 检索 |
| :--- | :--- | :--- |
| 嵌入模型 | 照常写文件并提交；向量在模型恢复后按文件哈希补齐 | 只走全文 |
| reranker | 不受影响 | 按合并顺序返回，不精排 |
| 决策模型 | 所有判断按"拿不准"处理；凭据检测仅凭正则，未命中时仍须主会话确认 | 不受影响 |

降级时返回结果末尾注明；启动时连不上任一模型不阻止启动，但在服务端说明与 `tacit status` 中提示。嵌入模型不可用时，沿用索引中记录的向量维度，恢复后再校验。

## 5. 存储

```text
<记忆仓库>/
├── .gitignore              # 只含 .cache/
├── persona.md              # 画像
├── candidates.md           # 画像候选与拒绝列表
├── recent.md               # 近期主线
├── recent/YYYY-MM.md       # 活动记录（按月）
├── pages/
│   ├── <项目>/<slug>.md    # 细节页，目录名即所属项目
│   └── _topics/<slug>.md   # 专题
└── .cache/                 # 派生索引，不进 Git
```

### 通用写法

- 编码 UTF-8 无 BOM，换行 LF，文件以换行结尾；列表项以 `- ` 开头，缩进两个空格。
- 日期一律 `YYYY-MM-DD`，按常驻服务所在机器的本地日期。
- 文件不写一级标题，从 `##` 开始分节；细节页标题只在 YAML 头的 `title` 中出现。
- 来源写在条目下一行的缩进 HTML 注释里：`<!-- 2026-10-25 原话「怎么又搜不到中文了」 -->`，原话可省略。
- 结构词（节名、`归属：`、`原话` 等）按记忆语言写入；解析时所有支持语言的结构词都识别。
- 所属项目名转为小写，只允许 `[a-z0-9._-]`，下划线开头的名字保留给系统（如 `_topics`）。

### 条目与短码

| 文件 | 一条 |
| :--- | :--- |
| `persona.md` | 一个顶层列表项 |
| `recent.md` | 一个顶层列表项；近期主线整体另有一个版本短码，用于整体改写 |
| `recent/YYYY-MM.md` | 日期标题下的一个列表项 |
| `candidates.md` | 一个三级标题及其出现记录 |
| 细节页 | 一个小节，以"页面标识 + 小节名"指代 |

服务返回条目时附带短码（规范化文本哈希的前 6 位，例如 `a3f9c2`），后续调用凭短码引用；短码不写进文件。内容完全相同的条目按出现顺序加后缀（`a3f9c2-2`）。条目内容一改，旧短码即失效：拿旧短码替换或删除会被拒绝并返回最新内容。

### 画像 `persona.md`

```markdown
## 红线
- 不要自行发布版本或推送到公开仓库；改为先请用户确认（理由：影响外部，无法撤回）
  <!-- 2026-10-25 原话「发布前必须问我」 -->

## 协作规则
- 需求不清时 → 先连续追问，确认后再给出完整方案
  <!-- 2026-10-20 原话「先问清楚再动手」 -->

## 偏好
- 沟通：先要结论，再看依据；反感客套和铺垫

## 档案
- 系统：Windows 11 x64，Shell 为 PowerShell 7
```

| 节 | 句式 | 上限（可配置） |
| :--- | :--- | :--- |
| 红线 | `不要 <行为>；改为 <替代做法>`，可加一句理由 | 5 条 |
| 协作规则 | `<情境>时 → <做法>`，只用肯定句，理由可选 | 20 条 |
| 偏好 | `<维度>：<描述>`，描述句，可写"不喜欢……" | 15 条 |
| 档案 | `<字段>：<事实>`，不写行为要求 | 10 条 |

- 每条不含注释最多 100 字，一条只写一个情境和一个做法；不使用大写强调词。
- 修改逐条进行，不整篇重写；被取代的条目直接替换，历史由 Git 保留。

### 画像候选 `candidates.md`

```markdown
## 候选

### 沟通：先要结论，再看依据
归属：偏好
- 2026-10-28 原话「先说结论」
- 2026-10-30 原话「别铺垫，直接说结果」

## 拒绝列表

### 每次提交前都运行全量测试
归属：协作规则
- 2026-10-27 原话「跑一下全部测试」
- 2026-10-29 拒绝 原话「不用，只跑相关的」
```

- 三级标题即确认后写进画像的条目原文；出现天数按不同日期计数。
- 在不同日期出现满 2 天（可配置）可确认；确认后移入 `persona.md`。
- 拒绝列表永久有效；用户改主意时可直接要求写入画像。

### 近期主线 `recent.md`

```markdown
## 近期主线
- TacitMemory 设计：从 Hindsight 转向自建，确定三个辅助模型配合与定期体检
```

最多 5 条（可配置），不要求日期。

### 活动记录 `recent/YYYY-MM.md`

```markdown
## 2026-10-31
- [tacit-memory] 决策模型定为只做判断，整理交给体检
  <!-- 原话「其实可以直接把记忆库当成项目」 -->
- 想清楚了画像里缺的是人的倾向，而不只是规范
```

每天一个二级标题，按写入顺序排列；属于项目的条目以 `[项目名]` 开头；每条最多 100 字。

### 细节页

```markdown
---
title: 数据库升级后扩展丢失
aliases: [全文检索插件失效, 升级后搜索不到中文]
dates: { first: 2026-10-21, last: 2026-10-25 }
related: [my-app/backup-script, _topics/pgroonga]
---

## 现象
……

## 根因
……
```

| 字段 | 规则 | 由谁写 |
| :--- | :--- | :--- |
| `title` | 必填，最多 50 字 | 主会话 |
| `aliases` | 至少 2 个，每个最多 30 字；覆盖口语说法、中英文名与别称 | 主会话；可追加 |
| `dates` | 首次与最近一次经服务写入的日期 | 服务 |
| `related` | 其他页的页面标识；指向不存在的页时经服务写入被拒绝 | 主会话 |

- 页面标识为 `<所属项目>/<slug>`，slug 匹配 `^[a-z0-9]+(-[a-z0-9]+)*$`，在项目内唯一，创建后不可改名。
- 正文按 `##` 小节组织，小节名由主会话决定，页内不得重名。

### Git

- 首次初始化：`git init`，写入 `.gitignore`、各文件的节标题骨架与 `recent/`、`pages/` 下的 `.gitkeep`，提交 `init: create memory repo`。目录非空且不是 Git 仓库时拒绝初始化。
- 每次经服务的写入自动提交一次，只提交本次写入的文件，作者固定为 `tacit <tacit@localhost>`。提交信息为 `<区域>: <动作> <对象>`，区域为 `persona`、`candidates`、`recent`、`pages` 之一，例如 `pages: create tacit-memory/db-upgrade`。
- 要写的文件含有用户未提交的修改时，连同修改一起提交，并在提交信息末尾注明。
- 体检的提交由主会话完成，提交信息以 `checkup:` 开头；服务据此识别上次体检的时间。
- 只有配置了备份远端时才推送（见第 12 节）。

### 手动编辑与容错

服务修改文件时只定位并改动要改的那几行，其余内容原样保留。格式不符合约定时照常解析，问题列入体检报告：

| 情况 | 处理 |
| :--- | :--- |
| 细节页 YAML 头无法解析 | 照样建索引，`title` 取文件名 |
| 协作规则缺 `→`、红线缺"改为"、无法识别的节或内容 | 照样计数与渲染 |
| 某节超出上限 | 照样全部渲染；之后经服务写入该节被拒绝，直到删减到上限以内 |
| 日期格式错误 | 该条不参与基于日期的计算 |
| 文件不是 UTF-8 | 跳过该文件，在服务端说明中提示 |
| 混用不同语言的结构词 | 照常解析 |

## 6. 写入

### 入口

写入只有两个入口，不使用客户端钩子，也不做会话结束后的后台补抽：

1. **记忆规则**：写在服务端说明中，主会话在对话中当场执行；
2. **记忆指令** `remember`：用户在压缩上下文、退出前或认为重要时执行。

主会话未遵守规则、用户也未执行指令就结束会话时，该段内容不会被记住。这是明确接受的代价。

### 值得记标准

`rules.md` 分"值得记"与"不记"两节，各最多 10 条，原样写入记忆规则。初始化时生成默认模板；文件被删除时，服务启动时重新生成。

默认值得记：用户纠正或打断 Agent；方案拍板（保留用户原话）；查明根因的排错（含试过但无效的做法）；新的环境事实；用户明确要求记下。默认不记：常规的写代码、改错字、看日志；能从代码、仓库文档、配置中查到的内容。

### 通用规则

- **先检索再写**：命中已有页则更新该页，未命中才新建；一件事只对应一页。
- **读取不修改**：检索与读取不改动任何文件。
- **保留来源**：写入内容附带日期，必要时附用户原话。
- **不写凭据**：见第 4 节。

### 细节页

- 新建时提交整页；服务先用决策模型判断是否与已有页重复。
- 更新以小节为单位：新增或替换一个小节、删除一个小节、修改页头（追加别名、改标题或 `related`）。替换与删除须带原小节的短码。
- 不提供整页重写；大幅调整在体检中直接改文件。

### 近期活动

- 一条活动写"人在做什么、想通了什么"，不写"改了哪些文件"。
- 写入后，服务返回当前近期主线与上次更新主线之后过期的条目，主会话可选择改写主线。
- 与当天已有条目同一主题时，服务退回已有条目及其短码，主会话写出合并后的一句，带 `replaces` 重新提交。
- "每个会话最多一条"只写在记忆规则中，服务不强制。

### 画像

| 操作 | 允许的条件 |
| :--- | :--- |
| 新增协作规则、偏好或档案 | 用户明确要求记住 |
| 新增红线 | 只能由用户明确提出 |
| 替换、删除 | 用户明确要求修改或删除某一条 |
| 观察到的偏好或规则 | 只能提交为画像候选，并标明归属节 |

这些条件写在记忆规则中。服务对新写入的条目做冲突判断，见第 4 节。

## 7. 检索

| 参数 | 必填 | 说明 |
| :--- | :--- | :--- |
| `query` | 与 `page` 二选一 | 自然语言查询，用记忆语言书写 |
| `page` | 与 `query` 二选一 | 页面标识：读取整页 |
| `project` | 否 | 只在该项目中检索 |
| `from`、`to` | 否 | 日期范围，由主会话把"上周"之类换算成日期 |
| `kind` | 否 | `pages` 或 `activities` |

流程：

1. 按项目与日期筛选；
2. 全文检索（FTS5，BM25）与向量检索（余弦）各取前 30 条。全文检索中，中文切成相邻两字一组；英文与文件名按 `unicode61` 规则在标点处切分，查询以短语匹配，`env.ps1`、`UTF-8` 这类写法仍可命中；单字查询退回子串匹配。向量单位为：每个小节、每页的 `title + aliases`、每条活动；
3. 用倒数排名融合（RRF）合并，取前 30 条交 reranker；
4. 丢弃低于分数阈值的结果，返回前 5 条（均可配置）；一条不剩时明确返回"没有相关记忆"。

结果以小节和单条活动为单位。同一页命中的多个小节合为一条结果，每个小节返回全文及短码，并列出该页其他小节的名字；页面级命中按开头几个小节呈现。

## 8. 注入

常驻内容按变化频率分两路：

| 通道 | 内容 | 何时更新 |
| :--- | :--- | :--- |
| 常驻区块 | 画像 | 服务启动时；绑定时；画像变化时 |
| 服务端说明 | 记忆规则、语言规范、近期摘要、已有项目、体检提示 | 所依据的记忆变化后重新生成，客户端连接时下发 |

两者都在下一次会话生效，正在进行的会话不会重新加载。

### 常驻区块

- 由 `<!-- tacit:begin … -->` 与 `<!-- tacit:end -->` 界定，内部以 `<user_memory>` 包裹；起止标记不完整或不唯一时拒绝改写；结果未变不写文件；区块外的内容从不改动。
- 外壳说明（英文）表达：这是记忆，不是配置；写下时准确，但可能有缺漏或过时；项目指令与用户当前消息优先；冲突时听用户的，并用一句话询问是否更新记忆；像了解用户的同事那样自然运用，不引用来源（不说"根据你的记忆""按你的红线"），只在与任务相关时提起具体条目，不相关的条目忽略。
- 四节各有一句引导：红线分量最重，除非用户在本次对话中解除，因红线拒绝时用自己的话说明具体理由；协作规则默认照做；偏好是描述而非命令，需结合任务权衡；档案在有助于回答时使用。
- 渲染时去掉来源注释；节标题使用英文，条目保持记忆语言。
- 每次渲染都重新读取 `bindings.json`，因此运行中的服务能感知新的绑定；`connect` 在绑定时立即渲染一次。

### 服务端说明

- 总长不超过 4000 字符。记忆规则与 `rules.md` 等固定部分在启动时校验，超过 2500 字符拒绝启动；生成时若总长超限，依次截断已有项目列表与最早的活动条目，不截断记忆规则。
- 记忆规则要点：
  - **何时检索**：用户提到过去的事，或提到上下文中没有的人名、项目名、专有名词；开始处理某个项目的任务前按项目检索一次。
  - **何时写入**：按值得记标准当场写入。
  - **怎么写**：先检索再写；一件事一页；附来源；观察到的偏好提交为候选，用户明确要求才直接写画像；用户的说法与画像条目矛盾时不提交候选，先询问，同意后再替换；不写凭据；写入被拒绝时按返回的"下一步"处理。
  - **运用记忆**：检索不到就说不记得，不编造；用户聊起自己的状态时，用半句话自然联系近期摘要里的事，不罗列、不复述；不主动翻旧账；区分检索到的记忆与凭画像的推测。
- 语言规范：记忆内容与检索语句使用记忆语言；用户原话、代码、路径、命令与专有名词保持原样。
- 近期摘要：近期主线 + 活动记录中最近 7 天的条目（超过 7 条取最新 7 条），每条前补日期。
- 已有项目：供主会话填写 `project` 参数时对照。
- 体检提示：距上次体检超过 7 天（可配置）或积累了问题时，提示问题数量。

## 9. 体检

用户在记忆仓库目录中执行记忆指令 `checkup`。指令内容由服务现场生成，包含体检步骤、当前记忆语言的结构词对照表与完整的体检报告：

1. 确认当前目录是记忆仓库；
2. 逐项处理报告：机械问题直接修正，需要拍板的逐项询问用户；
3. 近期主线过期时，依据最近一个月的活动记录重写；
4. 整体审视画像：去重、合并措辞相近的条目，每处修改经用户确认；
5. 提交，提交信息以 `checkup:` 开头。

体检报告在执行时现场计算，不保存中间状态：

| 类别 | 计算方式 |
| :--- | :--- |
| 疑似重复的页 | 每页取嵌入近邻 3 页，交决策模型判断 |
| 互相冲突的画像条目 | 每条取嵌入近邻 3 条，交决策模型判断 |
| 可确认的画像候选 | 出现天数达到门槛 |
| 违反格式或规则 | 解析时记录的问题 |
| 近期主线过期 | `recent.md` 最近一次提交超过 14 天（可配置） |

## 10. MCP 接口

常驻服务以无状态方式提供三种 MCP 机制：工具、prompt 与服务端说明。不使用 resources、completions、elicitation、sampling、roots 与 logging。

### 工具

| 工具 | `op` | 必填参数 |
| :--- | :--- | :--- |
| `recall` | — | `query` 或 `page`；可选 `project`、`from`、`to`、`kind` |
| `write_page` | `create` | `page`、`title`、`aliases`、`sections`；可选 `related` |
| | `upsert_section` | `page`、`section`、`body`；替换时加 `hash` |
| | `delete_section` | `page`、`section`、`hash` |
| | `update_header` | `page`；`title`、`add_aliases`、`related` 至少一项 |
| `write_recent` | `add_activity` | `text`；可选 `project`、`source`、`replaces` |
| | `update_mainline` | `items`、`hash`（近期主线的版本短码） |
| `write_persona` | `add` | `persona_section`、`text`、`source` |
| | `replace` | `hash`、`text`、`source` |
| | `delete` | `hash` |
| | `propose` | `persona_section`、`text`、`quote` |

- `persona_section` 取值为 `red_lines`、`working_rules`、`preferences`、`profile`；`write_page` 的 `section` 为小节名。写入凭据检测未通过时，可加 `confirm_no_secret` 重新提交。
- 参数结构扁平，由服务按 `op` 校验。
- 标注：`recall` 只读、幂等、不访问外部世界，并请求客户端首轮即加载；三个写入工具非只读、有破坏性、非幂等、不访问外部世界。
- 返回 Markdown 风格的纯文本，不返回结构化数据。
- 参数缺失、短码过期、超出上限或违反规则时标记错误，按"拒绝 / 下一步 / 相关内容"三段返回，"下一步"是主会话可直接执行的动作。同主题活动被退回、候选并入已有候选属于正常分支，不标记错误。

### 记忆指令

| 指令 | 参数 | 现场附带的内容 |
| :--- | :--- | :--- |
| `remember` | 可选 `focus`：本次要记的重点 | 写入步骤；今天已有的活动；当前近期主线 |
| `checkup` | 无 | 见第 9 节 |

`remember` 写完后列出写了什么，附页面标识或短码；不预先征求确认。

## 11. 语言

| 读者 | 内容 | 语言 |
| :--- | :--- | :--- |
| 只给 Agent 看 | 工具与参数说明、服务端说明、记忆指令、工具返回与报错、体检报告、常驻区块外壳、发给决策模型的问题 | 固定英文 |
| 人要看或要改 | 记忆仓库的结构词、`config.yaml` 与 `rules.md` 模板、CLI 输出 | 随配置 `language` |
| 记忆内容 | 画像条目、细节页、活动记录、近期主线 | 按语言规范使用记忆语言 |

`language` 取 `zh` 或 `en`，缺省时系统界面语言为中文则取 `zh`，否则取 `en`。Agent 与用户交谈所用语言由画像决定，不由 TacitMemory 规定。

## 12. 客户端、备份与运行

### 客户端与绑定

| 绑定方式 | 常驻区块写入 | MCP 注册 |
| :--- | :--- | :--- |
| `--client omp` | `~/.omp/agent/AGENTS.md`（默认 profile） | 在 `~/.omp/agent/mcp.json` 中增删 `tacit` 一项，其余内容不动 |
| `--client claude-code` | `~/.claude/CLAUDE.md` | 调用 `claude mcp add --scope user`；找不到 `claude` 命令时打印该命令 |
| `--file <路径>` | 指定文件 | 不注册 |

各客户端渲染出的常驻区块完全相同。绑定记录存于 `TACIT_HOME/bindings.json`；绑定文件被删除或标记丢失时跳过该文件并在 `tacit status` 中提示，不自行恢复。

改写 `mcp.json` 时保留其余服务、字段、顺序、缩进、换行风格与 BOM；文件含注释时不改写，改为给出需要手工加入的条目。绑定会新建不存在的上下文文件与 `mcp.json`，解绑时若它们只剩空内容则一并删除。不是 UTF-8 的上下文文件一律不改动。

### 备份与恢复

- 备份为一个 zip：记忆仓库（含 `.git`，不含 `.cache`）、`config.yaml`、`rules.md`、`bindings.json` 与清单。默认存放于 `TACIT_HOME/backups/`。配置中含明文密钥时备份时提示。
- 每天第一次写入后自动备份一次，保留最近 7 份（可配置，`0` 关闭）。
- 配置了 `backup.remote` 时，每次自动备份后推送记忆仓库；也可手动推送。
- 恢复由常驻服务执行：暂停写入 → 先自动备份当前状态 → 替换记忆仓库（加 `--config` 时一并覆盖配置）→ 全量重建索引并重新渲染 → 恢复写入。未加 `--yes` 时先列出备份内容等待确认。

### 配置

配置目录为 `TACIT_HOME`（默认 `~/.tacit`），包含 `config.yaml`、`rules.md`、`bindings.json`、`backups/` 与 `logs/`。环境变量只用于指定 `TACIT_HOME` 与按 `apiKeyEnv` 读取密钥。

```yaml
server:
  port: 18888
memory:
  path: ~/.tacit/memory       # 默认为 $TACIT_HOME/memory
language: zh

models:                       # 必填，无默认值
  embedding: { endpoint: …, model: … }
  reranker:  { endpoint: …, model: … }
  decision:  { endpoint: …, model: …, apiKey: … }   # 或 apiKeyEnv: <环境变量名>，二选一

limits:
  persona: { redLines: 5, workingRules: 20, preferences: 15, profile: 10 }
  itemLength: 100
  mainline: 5
  page: { titleLength: 50, aliasLength: 30, minAliases: 2 }
candidates: { minDays: 2 }
checkup: { remindAfterDays: 7, mainlineStaleDays: 14 }
decision:                     # 各判断的上下阈值
  samePreference: { certain: …, unlikely: … }
  samePage:       { certain: …, unlikely: … }
  sameActivity:   { certain: …, unlikely: … }
  ruleConflict:   { certain: …, unlikely: … }
  credential:     { certain: …, unlikely: … }
retrieval: { candidates: 30, topK: 5, minRerankScore: … }
backup: { keep: 7, remote: … }
```

- 除 `models` 外各项均有默认值；阈值默认值以真实中文样本测定。向量维度在启动时由嵌入模型的返回确定。

### 运行

- 单一常驻 HTTP MCP 服务，只监听 `127.0.0.1`，不做鉴权：本机视为可信边界。所有写入串行执行；服务未运行时记忆工具不可用，已写入的常驻区块仍然有效。
- 启动时按文件哈希比对增量同步索引；运行时监听记忆仓库，文件变化即同步对应索引，画像变化时重新渲染常驻区块。
- 索引记录表结构版本、嵌入模型名与向量维度，任一与配置不一致即删除并全量重建。
- 日志写入 `TACIT_HOME/logs/`，按天滚动保留 14 天，只记录页面标识与短码，不记录记忆正文。

| 命令 | 作用 | 需要服务运行 |
| :--- | :--- | :--- |
| `tacit init [--language zh\|en] [--memory <路径>]` | 生成配置模板并创建记忆仓库 | 否 |
| `tacit serve` | 启动常驻服务；未初始化时报错 | — |
| `tacit connect` / `tacit disconnect` | `--client omp`、`--client claude-code` 或 `--file <路径>` | 否 |
| `tacit status` | 服务、辅助模型、绑定、上次体检与备份、待处理问题 | 是 |
| `tacit reindex` | 全量重建索引 | 是 |
| `tacit backup [--to <目录>] [--push]` | 立即备份 | 是 |
| `tacit restore <文件> [--config] [--yes]` | 从备份恢复 | 是 |

- `init` 在服务首次启动前创建记忆仓库，是唯一不经常驻服务写入记忆仓库的入口；`connect`、`disconnect` 只改客户端文件与 `bindings.json`。
- 首批适配 omp 与 Claude Code：先实现并验证 omp，Claude Code 随后。

## 13. 不做的事（v1）

| 不做 | 原因或归属 |
| :--- | :--- |
| 任务交接（上次停在哪） | 由客户端负责 |
| 保存原始会话 | 由客户端负责 |
| 客户端钩子、后台补抽 | 写入只依靠记忆规则与记忆指令 |
| 服务内调用生成式对话模型 | 生成与改写由主模型完成，整理由体检完成 |
| 人格注入 | 语气由客户端与画像中的偏好决定 |
| 主动浮现往事 | 细节只在被提起时检索 |
| 按项目的常驻内容 | 项目约定应写在项目自己的仓库文档中 |
| 统计页面命中、清理久未命中的页 | 旧页不干扰检索，统计需额外状态 |
| 永久的条目编号 | 条目引用都是短时的，用短码 |
| 自动校准判断阈值 | 尚无标注数据，阈值手动配置 |
| resources、elicitation、sampling 等 MCP 机制 | 客户端支持不足或规范已弃用 |

## 14. 扩展

扩展时遵守：

- **所有入口经常驻服务**：TUI、Web UI 等新界面只调用常驻服务，不直接读写记忆仓库或索引。
- **规则只有一份**：新能力先在核心实现，再由各入口调用。
- **文件始终可直接编辑**：界面是便利，不是必需。
- **配置向后兼容**：新增配置项必须有默认值。

已知方向：Web UI（浏览、审核候选、检索调试）、TUI、以支持 logprobs 的对话模型实现决策模型接口、更多客户端适配、按项目的常驻内容、更换索引引擎。
