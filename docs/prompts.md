# TacitMemory 提示词

本文档说明发给模型的每一段文字**负责什么**：它在哪个环节进入上下文、承担什么职责、违反时有没有兜底，以及修改时要守的约定。各环节的更新时机、服务端说明的长度上限与截断规则见 `docs/design.md` 第 8 节，提示词文档的格式与上限见 `docs/reference/configuration.md`「提示词文档」，语言划分见 `docs/design.md` 第 11 节，术语见 `GLOSSARY.md`。

本文只写每段文字要达到的效果，不抄录原文；措辞以代码为准。

## 1. 环节总览

| 环节 | 读者 | 何时进入上下文 | 生成方式 |
| :--- | :--- | :--- | :--- |
| 常驻区块 | 主会话 | 会话开始，始终可见 | 渲染进客户端的上下文文件 |
| 服务端说明 | 主会话 | 会话开始，始终可见 | 客户端连接时由常驻服务下发 |
| 工具说明 | 主会话 | 客户端可能只先显示名称与首句，用到时才读全文；`recall` 标注为首轮即加载 | 随工具列表下发 |
| 工具回复 | 主会话 | 调用之后 | 每次调用现场生成 |
| 记忆指令（`tacit-remember`、`tacit-consolidate` skill） | 主会话 | 用户触发 skill 时，正文作为用户消息送达，并附上用户写在命令后的文字；`tacit-consolidate` 的报告由 Agent 读取资源 `tacit://consolidation-report` 取得 | 正文由代码生成，写入 `TACIT_HOME/skills/`，内容不变不写文件；报告在读取时现场生成 |
| 记忆 skill | 主会话 | 会话开始只看到名称与描述，Agent 读取时才看到正文 | 服务启动、`prompts/` 变化、`connect` 与门面的 `GenerateSkills` 时生成（三个 skill 一并生成），内容不变不写文件 |
| 判断问题 | 决策模型 | 写入前；整理时 | 每次判断现场生成，不进入主会话 |

## 2. 职责分类与放置原则

每段文字属于以下一类：

| 类别 | 含义 | 例子 |
| :--- | :--- | :--- |
| 契约 | 怎样正确调用服务：工具名、参数、短码从哪里取、被拒绝后怎么办 | 工具说明、拒绝回复的"下一步" |
| 判断问题 | 发给决策模型的选择题，与阈值一起测定 | 四项判断的问题文字 |
| 策略 | 主会话何时检索、何时写、写什么、如何对待记忆 | 记忆规则、常驻区块外壳与引导语、记忆指令的步骤 |
| 由配置填入 | 内容来自 `config.yaml` 或 `prompts/rules.md` | 语言规范中的记忆语言、值得记标准 |
| 动态数据 | 来自记忆仓库或运行状态，每次现场生成 | 最近 7 天的活动、状态提示、画像条目、领域索引、主线（背景说明与近期摘要） |

判定一段文字属于契约还是策略，依次问两个问题：

1. **它讲的是不是调用格式？** 是则为契约，只写在工具说明与拒绝回复中。
2. **不是的话，Agent 不照做时后果落在哪里？** 只影响用户自己的体验（语气、是否提旧事、何时检索）是普通策略；会越权改写常驻画像的（直接 `add`、未经同意 `replace`）是权限边界，同属策略，但不宜删除。

放置原则：

- **时机与写法分开**：规定"什么时候做"的文字必须放在会话开始就可见的环节（常驻区块或服务端说明），否则 Agent 在需要时看不到它；规定"具体怎么做"的文字可以放在用到时才看到的环节（工具说明、工具回复）。
- **同一时机不重复**：同时在会话开始可见的两处不写同一条规则。不同时机的重复是有意的提醒，例如会话开始时的规则与用到工具时的说明。
- **调用格式只有一处**：参数、短码、句式要求写在工具说明中，拒绝时由"下一步"再次给出；记忆规则不复述它们。

## 3. 常驻区块

常驻区块承载画像（全局四节）、领域索引与主线，并声明自身是可能过时的记忆（理由见 `GLOSSARY.md` 的"常驻区块"）。

| 部分 | 要 Agent 做什么 | 类别 |
| :--- | :--- | :--- |
| 起止标记与 `<user_memory>` 标签 | — （服务据此定位并改写区块；服务端说明的开场引用这个标签） | 契约 |
| 外壳第一段 | 把画像当作背景而非配置；它可能有缺漏或过时；项目指令优先；用户说法不同时照用户的做，并用一句话问是否更新记忆（用户当前的话优先于记忆不必写明） | 策略：定位与优先级 |
| 外壳第二段 | 静默地运用画像，像了解用户的同事那样；只在与任务相关时提起具体条目，不引用来源 | 策略：分寸 |
| 四节引导语 | 红线分量最重，除非用户在本次对话中解除，因红线拒绝时说明理由；偏好是描述不是命令，需结合任务权衡。协作规则与档案没有引导语 | 策略：各节的权重 |
| 领域索引的引导语（`situational_rules`） | 任务命中某一行的触发描述时，先按该领域取规则再行动 | 策略：何时取规则 |
| 主线一节的引导语（`workstreams`） | 每行先读背景说明，后读近期摘要；近期摘要只在整理时更新，与活动不一致时以活动为准 | 策略：如何读主线行 |
| 节标题与数据 | — | 节标题为契约（英文）；条目、领域索引行与主线行为动态数据（记忆语言，去掉原话注释） |

来源是 `TACIT_HOME/prompts/resident.md`。用户放置该文件时，外壳两段与各节引导语整份由它替换；缺失时使用内置默认，即上表中的文字（协作规则与档案默认没有引导语；主线一节的默认引导语见内置文字）。起止标记、`<user_memory>` 标签、节标题与数据仍由服务生成，不在该文件中。

格式、上限与校验规则见 `docs/reference/configuration.md`「提示词文档」。

文件变化后，所有已绑定文件中的常驻区块在去抖后重新渲染；绑定时也使用当前文件。下一个会话生效。

这些文字都没有服务端兜底：Agent 不照做只影响画像被运用的方式，不会写坏数据。

## 4. 服务端说明

按下发顺序：开场、核心规则、通用规则、语言规范、值得记标准、最近 7 天的活动（`<recent_activity>` 标签包裹）、状态提示、整理提示。开场、核心规则、通用规则、语言规范与值得记标准是固定部分，计入固定部分的长度上限。

核心规则的来源是 `prompts/instructions.md`：用户放置该文件时整份替换核心规则，缺失时使用内置默认。内置默认即"运用记忆""何时检索""写"三段原文，代码中以 `ServerInstructionText.DefaultInstructions` 保存；下文各小节描述的是这三段的内容。其中 HTML 注释的下发规则见 `docs/reference/configuration.md`「提示词文档」。

### 开场（契约）

说明记忆分在三处：画像与主线已在 `<user_memory>` 中，最近 7 天的活动在下方的 `<recent_activity>` 标签里，细节要用 `recall` 取。它把常驻区块与服务端说明连成一体，让 Agent 知道去哪里找什么。

### 运用记忆（策略）

| 条目 | 要 Agent 做什么 | 兜底 |
| :--- | :--- | :--- |
| 区分记忆与推测 | 记得的和凭画像推测的分开说，不把猜测说成记得 | 无 |
| 关联记忆 | 把用户说的与记忆中的主线、决定、事故相连，关联改变答案时说明；与当前话题无关的记忆不提；区分记得与推测，旧事注明日期；活动比主线行新，不一致时以活动为准 | 无 |
| 联系近况 | 用户聊起自己的状况时，用半句话自然联系近期的事 | 无 |

### 何时检索（策略）

| 条目 | 要 Agent 做什么 | 兜底 |
| :--- | :--- | :--- |
| 检索时机 | 用户提到过去的事，或提到上下文中没有的人名、主线名、术语时调用 `recall` | 无；不照做时细节页这一层不会被用到 |
| 主线预取 | 话题进入 `<user_memory>` 中列出的主线时，回答前只给 `workstream` 调用一次 `recall`，读主线简报，每条主线每个会话一次 | 无 |
| 不编造 | 检索不到就说不记得 | 无 |

### 写（策略，含权限边界）

| 条目 | 要 Agent 做什么 | 兜底 |
| :--- | :--- | :--- |
| 先检索再写页面 | 有值得记的事先 `recall`；已有页面覆盖这件事就更新那一页 | 重复页判断 |
| 一件事一页 | 一件事一页 | 重复页判断 |
| 写活动 | 一件主事有了结论时写一条，带所属主线；每条主线每个会话至多一条，后续进展用 `replaces` 改写 | 同主题判断（只限同一天） |
| 问一次再 `add` | 用户纠正 Agent 或明确说出做法时，问一次是否记成长期规则（画像会进入每个会话），同意后才 `add` | `add` 的画像冲突判断 |
| 习惯用 `propose` | 贯穿会话观察到的习惯、偏好或协作规则，用 `propose` 提交为候选 | 同一偏好判断；候选留作整理的证据 |
| 红线与改写 | 红线只由用户提出；改写或删除画像条目须经用户同意 | `propose` 拒绝红线；`replace` 与 `add` 都有画像冲突判断 |

活动怎么写（写什么、属于主线时设 `workstream`）见记忆 skill。主线不在这里写，由整理负责。

"红线与改写"一行是权限边界，内置默认中以独占一行的英文 HTML 注释标明（"Permission boundary, do not remove"），注释不下发。

### 通用规则（代码提供）

| 条目 | 要 Agent 做什么 | 兜底 |
| :--- | :--- | :--- |
| 读记忆 skill 的时机 | 会话中第一次写入前、任何拒绝之后，读 `tacit-memory` skill（写法与拒绝的处理都在那里） | 无；拒绝回复本身带"下一步" |

通用规则由代码提供（`ServerInstructionText` 中的 `GeneralRules`），紧接在核心规则之后，不另起标题；用户放置 `prompts/instructions.md` 替换核心规则时它仍然存在。

### 语言规范（由配置填入）

记忆内容与 `recall` 的查询使用记忆语言；用户原话、代码、路径、命令与专有名词保持原样。查询语言与记忆语言一致，全文检索才能命中。

### 值得记标准（由配置填入）

`prompts/rules.md` 两节的条目原样写入，决定什么值得记、什么不记。它是用户直接维护的策略，缺失时按记忆语言重新生成。

### 最近 7 天的活动、状态提示、整理提示（动态数据）

内容与生成规则见 `docs/design.md` 第 8 节。最近 7 天的活动让 Agent 不检索也知道用户最近在忙什么，标签包住它，让 Agent 把它当作数据而非指令；状态提示让 Agent 知道检索与判断可能变弱。已成立的主线移到了常驻区块（第 3 节），Agent 写 `workstream` 时沿用已有的名字；对不上的话不带标签。

整理提示的职责：距上次整理已久、有待汇总的周、候选较多或主线为空时，提醒 Agent 在合适的时机建议用户运行 `tacit-consolidate` skill。它不替用户决定，也不自行开始整理；Agent 可以用其中的天数与计数说明为什么现在值得整理，而不是把这些数字当作记忆内容复述。它是下发的最后一段，整理提交后的下一个会话中消失（仍有任一触发条件时除外）。

## 5. 工具说明（契约为主）

| 工具 | 说明包含 |
| :--- | :--- |
| `recall` | 用途（检索、读整页、读整份画像与领域规则，或只给 `workstream` 取主线简报，简报含约定、未决事项、页目录与近期活动）；`query`、`page`、只给 `workstream`、只给 `kind`（`persona` 或 `rules`）四种调用各取其一；结果按页返回并附小节短码，画像与规则的条目附短码；各参数的写法（记忆语言、日期格式、`kind` 取值、`domain` 标签） |
| `write_page` | 一件事一页、按小节组织；各 `op` 的必填参数；替换与删除小节需要 `recall` 给出的短码；`type` 的四个取值；页面标识、别名、小节正文的格式；凭据的写法 |
| `write_recent` | 一条活动一行；`text` 必填及长度；`replaces` 改写当天活动；主线由整理维护；凭据的写法（写明存在哪里） |
| `write_persona` | 各 `op` 的必填参数；`scope` 与新领域的 `trigger`；四节的句式；长度与条数上限；凭据的写法；`propose` 不接受红线 |

`write_persona` 的使用条件（何时 `add`、`propose`、`replace`、`delete`）不在工具说明中，只由服务端说明"写"与 `tacit-remember` 第 4 步负责，见第 9 节。

工具说明中唯一的上限数字由 `config.yaml` 的 `limits.page.minAliases` 填入，即 `write_page` 的 `aliases` 最少个数；写入的长度与条数不设上限，说明中不出现上限数字。改配置后需重启服务。

## 6. 工具回复（契约）

- 成功时返回 Markdown 风格的纯文本，例如检索结果、写入后的短码与条数。
- 拒绝时标记为错误，分三段：`Refused`（原因，多条时逐行列出）、`Next step`（主会话可直接执行的动作）、`Related`（执行下一步所需的内容，例如当天的活动及其短码，或超限时该范围内的条目；画像短码的拒绝不附整份画像，下一步指向 `recall kind=persona`）。
- 细节页 `upsert_section`、`delete_section` 的 `section` 填了本页某小节的短码（且本页没有同名小节）时，拒绝并返回英文：`Parameter section "<短码>" is the short code of section <小节标题>, not a section name.`；下一步：`Call write_page op=upsert_section again with section set to the name <小节标题> and hash set to the short code <短码>.`（删除时为 `op=delete_section`），`Related` 附该小节的标题、短码与正文。
- 未知参数（参数名不在工具 schema 中）：每个一条 `Unknown parameter <名>.`，排在拒绝的最前。`op` 有效时下一步为 `Call write_page again with only the parameters for op <op>: page, <该 op 的参数>.`（`write_persona` 同形，不列 `page`）；`write_recent` 没有 `op`，传入已删除的 `op`、`items`、`hash` 时，下一步为 `Call write_recent again with only these parameters: text, workstream, source, replaces, confirm_no_secret. The workstream list is maintained by the tacit-consolidate skill.`；`op` 缺失或无效时为 `Call write_page again with op set to one of: <取值>; its parameters are: <全部参数>.`；`recall` 为 `Call recall again with only these parameters: query, page, workstream, from, to, kind, domain; give exactly one of query or page, unless kind is persona or rules.`
- 同主题退回、候选并入、提议命中拒绝列表或画像都是正常结果，不标记错误，同样给出下一步该怎么做。
- 辅助模型不可用而跳过某项判断时，在回复末尾以 `Note:` 注明；模型未配置时不注明，因为这不是故障，只是没有该功能。

"下一步"是纠正调用错误的主要手段：Agent 用错参数或短码过期时，按它改正即可。

## 7. 记忆指令 skill

两个记忆指令是两个 skill：`tacit-remember` 与 `tacit-consolidate`，成品写入 `TACIT_HOME/skills/`。正文为英文，由代码生成，没有 `prompts/` 下的覆盖或追加文件。frontmatter 含 `name`、一句话 `description` 与 `disable-model-invocation: true`（只由用户触发，Agent 不自行调用），正文之前是标明由 TacitMemory 生成的 HTML 注释。两个正文都写明：用户随命令附的文字是本次运行的重点或附加要求，须遵从。

`tacit-remember` 让主会话立即把本会话写进记忆：

- 开场：现在就写，不预先征求确认，除非某一步要求先问。
- 步骤：
  1. 按值得记标准回顾本会话；
  2. 页面：先 `recall`，覆盖该事的页面按小节更新，否则按类型新建；
  3. 活动：每条本会话推进了的主线各写一条（带所属主线，一个结论加原因）；本会话已写过的用 `replaces` 改写；与当天已有活动同主题而未写入时，回复给出那条活动的短码与下一步；
  4. 画像：问一次是否记成长期规则，同意后 `add`；观察到的习惯用 `propose`；与画像矛盾时先问；
  5. 列出写了什么：页面附页面标识，活动与画像条目附短码，候选附原文。

不附带当天的活动，代价是第 3 步遇到短码时多一次往返。正文只取决于代码，不读记忆仓库。

### tacit-consolidate

`tacit-consolidate` 让主会话依据整理报告整理记忆仓库。附在命令后的文字可限定本次的范围或重点，如“只做汇总”，或“只处理主线”（直接指定一条主线时带上它）。正文由四部分组成，各部分的职责如下：

| 部分 | 要主会话做什么 | 类别 |
| :--- | :--- | :--- |
| 开场 | 现在开始整理；先读取资源 `tacit://consolidation-report`，读不到则停下请用户运行 `tacit serve`；记忆仓库的绝对路径；用绝对路径改文件，并在该目录中执行 git | 契约（路径、资源名）与策略 |
| 步骤 | 六个步骤的顺序：A 部分直接处理（格式修正、删除待清理的候选、写汇总、只重写主线的近况，背景说明不动）；读取材料；起草全部提案（含主线提案）并编成一张编号清单，写明回复写法；按回复执行（确认、拒绝、改成、暂缓），主线提案确认后增删主线条目并迁移细节页；展示汇总与变更过的主线条目；以 `consolidate:` 提交 | 策略，含权限边界：画像、作用域块与页面的改动，都要在用户确认之后；A 部分只做派生内容与机械修正 |
| 结构词对照表与示例 | 按记忆语言列出结构词，并给出作用域块、候选块（含作用域行）、拒绝列表条目、主线条目（背景说明与近况两行）与汇总行的写法（日期用 `YYYY-MM-DD`、周用 `YYYY-Www`、月用 `YYYY-MM` 占位），使主会话直接改文件时服务能认出 | 契约（格式） |
| 整理报告 | 不在正文中，由资源返回：此刻的事实，即今天的日期、记忆仓库路径、上次整理的基准提交，以及 A、B 两部分的问题；每类有英文标题，每类最多列 20 项 | 动态数据（经资源读取） |

步骤引用报告的类别标题，因此标题由代码统一定义，正文与报告共用这一份定义；步骤与报告的文字都是英文，被引用的记忆内容保持原文。服务不在报告中给出做法，做法只在步骤中。

## 8. 判断问题

四项判断都是选择题：题干是新内容，每个已有项（页、活动、候选、拒绝列表项或画像条目）是一个选项，另加一个"都不是"选项；除重复页判断外，问题都要求只回答选项键（决策模型按选项键返回概率，这一要求只约束回答的写法，不改变判断结果）。被判断的内容保持原文，不翻译；每个选项超过 250 字符时截断。

| 判断 | 问题要决策模型分辨的 |
| :--- | :--- |
| 重复页 | 新页与同主线的某个已有页是否描述同一个问题、缺陷、决定或主题；只是同一产品区域或组件不算 |
| 同主题 | 新活动与当天某条已有活动是否是同一件事，包括它当天的推进、结果或后续；主线标注不作为依据，同一主线里的不同任务不算 |
| 画像冲突 | 新条目与某条已有画像条目（跨四节）是否冲突、重复或取代；相关但可以同时成立的不算 |
| 同一偏好 | 新提议与某个候选、拒绝列表项或画像条目是否是同一偏好或规则；同一话题下要求不同的、相反的偏好都不算 |

判断的三档处理与阈值见 `docs/design.md` 第 4 节。阈值是用这些问题实测出来的，问题措辞与阈值绑定。

## 10. 修改约定

- 给模型的文字一律英文（`docs/design.md` 第 11 节）。
- 措辞不由自动测试固定：自动测试只检查结构与长度上限（`docs/testing.md`）。
- 改动主会话看到的文字，以日常使用中出现的摩擦点为依据，改后在真实客户端中复现验收（`docs/testing.md` 第 4 节）。
- 改动判断问题须重新测定该判断的阈值。
- 新增文字先按第 2 节归类，再按放置原则选环节；放进服务端说明固定部分前先确认长度余量。

## 11. 记忆 skill

记忆 skill 是 `TACIT_HOME/skills/tacit-memory/SKILL.md`，承载详细写法：各类记忆怎么写、被拒绝后怎么办。会话开始时主会话只看到它的名称与 `description`，写入前读取正文。

成品由四部分拼成，前三部分由代码提供：

- frontmatter：`name` 固定为 `tacit-memory`；`description` 的前 100 字符写明读取时机（写入或修改任何记忆之前、`write_*` 被拒绝之后），omp 截断描述时仍保留触发场景。
- 生成说明：HTML 注释，写明由 TacitMemory 生成、请改 `prompts/skill.md`。
- 系统部分正文（英文）：分节为术语、检索、细节页（各类型的推荐小节，附每种类型一个真实示例）、活动（一个结论加一个原因，主线名取自 `<user_memory>`，对不上就不带标签；中英各一组好坏对照，均为虚构示例）、画像（作用域、领域与泛化检验）、拒绝处理。它讲写法，不复述调用格式与配置数值，不写读取的触发条件（触发条件只在核心规则与 `description` 中），不设长度上限。
- 用户补充（`prompts/skill.md`，可选）：接在末尾的 `## User conventions` 一节，开头由代码写明用户的写法约定优先于上文的写法建议，但不改变工具的调用格式。

`prompts/skill.md` 只能补充写法约定：它不能以 frontmatter 开头，长度上限见 `docs/reference/configuration.md`「提示词文档」，生成时机见 `docs/design.md` 第 10 节。不检查语言。

## 13. 查看方式

`tacit show <子命令>` 不读源码就能看到 Agent 收到的内容，直接在门面上生成，服务不必运行：

| 子命令 | 看到的内容 | 来源标注 |
| :--- | :--- | :--- |
| `instructions` | 服务端说明，按段标注来源，并给出固定部分与总长的长度和上限（示例：固定部分 2116/3000，总长 2365/4000） | 每段分别为代码、内置默认或 `prompts/` 中的文件 |
| `resident` | 常驻区块的外壳与四节引导语，文件格式 | 内置默认或 `prompts/resident.md` |
| `skill` | `tacit-memory` skill 的完整成品；`--default` 只输出系统部分 | 代码，以及 `prompts/skill.md` |
| `tools` | 各工具与参数的说明，由 CLI 经 `TacitMemory.Mcp` 读取，上限取自已严格加载的配置 | 代码与 `config.yaml` 的 `limits` |
| `remember` | `tacit-remember` skill 的完整成品 | 代码 |
| `consolidate` | `tacit-consolidate` skill 的完整成品（不含整理报告，报告由资源提供） | 代码与记忆语言 |

- `--default`（用于 `instructions`、`resident`、`skill`）只输出内置默认文本，可以直接保存为覆盖文件的起点，例如 `tacit show instructions --default > <TACIT_HOME>/prompts/instructions.md`。`remember`、`consolidate` 与 `tools` 没有内置默认文本，不接受 `--default`。
- 输出是此刻的内容，不含运行时状态（调用失败的辅助模型、非 UTF-8 文件）；运行中的服务还会加入这些状态提示。
- 标签随记忆语言切换，正文原样输出。
