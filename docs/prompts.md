# TacitMemory 提示词

本文档说明发给模型的每一段文字**负责什么**：它在哪个环节进入上下文、承担什么职责、违反时有没有兜底，以及修改时要守的约定。各环节的长度上限、更新时机与截断规则见 `docs/design.md` 第 8 节，语言划分见同文档第 11 节，术语见 `GLOSSARY.md`。

本文只写每段文字要达到的效果，不抄录原文；措辞以代码为准。

## 1. 环节总览

| 环节 | 读者 | 何时进入上下文 | 生成方式 |
| :--- | :--- | :--- | :--- |
| 常驻区块 | 主会话 | 会话开始，始终可见 | 渲染进客户端的上下文文件 |
| 服务端说明 | 主会话 | 会话开始，始终可见 | 客户端连接时由常驻服务下发 |
| 工具说明 | 主会话 | 客户端可能只先显示名称与首句，用到时才读全文；`recall` 标注为首轮即加载 | 随工具列表下发 |
| 工具回复 | 主会话 | 调用之后 | 每次调用现场生成 |
| 记忆指令 | 主会话 | 用户执行时，作为用户消息送达 | 调用时现场生成 |
| 判断问题 | 决策模型 | 写入前 | 每次判断现场生成，不进入主会话 |

## 2. 职责分类与放置原则

每段文字属于以下一类：

| 类别 | 含义 | 例子 |
| :--- | :--- | :--- |
| 契约 | 怎样正确调用服务：工具名、参数、短码从哪里取、被拒绝后怎么办 | 工具说明、拒绝回复的"下一步" |
| 判断问题 | 发给决策模型的选择题，与阈值一起测定 | 四项判断的问题文字 |
| 策略 | 主会话何时检索、何时写、写什么、如何对待记忆 | 记忆规则、常驻区块外壳与引导语、记忆指令的步骤 |
| 由配置填入 | 内容来自 `config.yaml` 或 `rules.md` | 语言规范中的记忆语言、值得记标准 |
| 动态数据 | 来自记忆仓库或运行状态，每次现场生成 | 近期摘要、状态提示、已有项目、画像条目 |

判定一段文字属于契约还是策略，依次问两个问题：

1. **它讲的是不是调用格式？** 是则为契约，只写在工具说明与拒绝回复中。
2. **不是的话，Agent 不照做时后果落在哪里？** 只影响用户自己的体验（语气、是否提旧事、何时检索）是普通策略；会越权改写常驻画像的（直接 `add`、未经同意 `replace`）是权限边界，同属策略，但不宜删除。

放置原则：

- **时机与写法分开**：规定"什么时候做"的文字必须放在会话开始就可见的环节（常驻区块或服务端说明），否则 Agent 在需要时看不到它；规定"具体怎么做"的文字可以放在用到时才看到的环节（工具说明、工具回复）。
- **同一时机不重复**：同时在会话开始可见的两处不写同一条规则。不同时机的重复是有意的提醒，例如会话开始时的规则与用到工具时的说明。
- **调用格式只有一处**：参数、短码、句式要求写在工具说明中，拒绝时由"下一步"再次给出；记忆规则不复述它们。

## 3. 常驻区块

常驻区块只承载画像，并声明自身是可能过时的记忆（理由见 `GLOSSARY.md` 的"常驻区块"）。

| 部分 | 要 Agent 做什么 | 类别 |
| :--- | :--- | :--- |
| 起止标记与 `<user_memory>` 标签 | — （服务据此定位并改写区块；服务端说明的开场引用这个标签） | 契约 |
| 外壳第一段 | 把画像当作背景而非配置；它可能有缺漏或过时；项目指令与用户当前的话优先；用户说法不同时照用户的做，并用一句话问是否更新记忆 | 策略：定位与优先级 |
| 外壳第二段 | 像了解用户的同事那样运用画像，不引用来源（不说"根据你的记忆""按你的红线"）；只在与任务相关时提起具体条目 | 策略：分寸 |
| 四节引导语 | 红线分量最重，除非用户在本次对话中解除，因红线拒绝时用自己的话说明理由；协作规则默认照做；偏好是描述不是命令，需结合任务权衡；档案在有用时使用 | 策略：各节的权重 |
| 节标题与画像条目 | — | 节标题为契约（英文）；条目为动态数据（记忆语言，去掉原话注释） |

这些文字都没有服务端兜底：Agent 不照做只影响画像被运用的方式，不会写坏数据。

## 4. 服务端说明

按下发顺序：开场、运用记忆、何时检索、写页面、写活动与主线、写画像、语言规范、值得记标准、近期摘要、状态提示、已有项目、体检提示。前八段是固定部分，计入固定部分的长度上限。

### 开场（契约）

说明记忆分在三处：画像已在 `<user_memory>` 中，近期活动摘要在下方的 `## Recent`，细节要用 `recall` 取。它把常驻区块与服务端说明连成一体，让 Agent 知道去哪里找什么。

### 运用记忆（策略）

| 条目 | 要 Agent 做什么 | 兜底 |
| :--- | :--- | :--- |
| 区分记忆与推测 | 记得的和凭画像推测的分开说，不把猜测说成记得 | 无 |
| 不翻旧账 | 用户没提的旧事不主动提 | 无 |

### 何时检索（策略）

| 条目 | 要 Agent 做什么 | 兜底 |
| :--- | :--- | :--- |
| 检索时机 | 用户提到过去的事，或提到上下文中没有的人名、项目名、术语时调用 `recall` | 无；不照做时细节页这一层不会被用到 |
| 项目预取 | 开始处理某个项目前，按项目名检索一次 | 无 |
| 不编造 | 检索不到就说不记得 | 无 |

### 写页面（策略为主）

| 条目 | 要 Agent 做什么 | 兜底 |
| :--- | :--- | :--- |
| 先检索再写 | 有值得记的事先 `recall`；已有页面覆盖这件事就更新那一页 | 重复页判断 |
| 粒度与写法 | 一件事一页；写日期，措辞重要时写用户原话 | "一件事一页"有重复页判断；日期与原话无 |
| 被拒绝时 | 照拒绝回复的"下一步"做 | 拒绝回复本身带"下一步" |

### 写活动与主线（策略）

| 条目 | 要 Agent 做什么 | 兜底 |
| :--- | :--- | :--- |
| 写活动的时机 | 一件主事有了结论时写一条；每个会话至多一条，后续进展用 `replaces` 改写 | 同主题判断（只限同一天） |
| 活动的写法 | 写人在做什么、想通了什么，不写改了哪些文件；属于项目时设 `project` | 无（只校验长度） |
| 改主线的时机 | 只在出现持续的新方向或旧方向明确结束时改 | 版本短码只防并发，不管语义 |
| 联系近况 | 用户聊起自己的状况时，用半句话自然联系近期的事 | 无 |

"联系近况"属于运用记忆，目前写在这一段。

### 写画像（策略，含权限边界）

| 条目 | 要 Agent 做什么 | 兜底 |
| :--- | :--- | :--- |
| 提交候选 | 用户表达的习惯、偏好或协作规则，即使是顺带说的，也用 `propose` 提交为候选 | 同一偏好判断；候选需经体检确认 |
| 直接写入的权限 | 只有用户明确要求才 `add`；红线只由用户提出 | `propose` 拒绝红线；`add` 只有画像冲突判断 |
| 矛盾时 | 用户的话与画像条目矛盾时照用户的做，不提交候选，先问是否更新，同意后才 `replace` | `add` 有画像冲突判断；`replace` 无 |

后两条是权限边界。

### 语言规范（由配置填入）

记忆内容与 `recall` 的查询使用记忆语言；用户原话、代码、路径、命令与专有名词保持原样。查询语言与记忆语言一致，全文检索才能命中。

### 值得记标准（由配置填入）

`rules.md` 两节的条目原样写入，决定什么值得记、什么不记。它是用户直接维护的策略。

### 近期摘要、状态提示、已有项目、体检提示（动态数据）

内容与生成规则见 `docs/design.md` 第 8 节。近期摘要让 Agent 不检索也知道用户最近在忙什么；状态提示让 Agent 知道检索与判断可能变弱；已有项目让 Agent 写 `project` 时沿用已有的名字。

## 5. 工具说明（契约为主）

| 工具 | 说明包含 |
| :--- | :--- |
| `recall` | 用途（检索或读整页）；`query` 与 `page` 只给一个；结果按页返回并附小节短码；各参数的写法（记忆语言、日期格式、`kind` 取值） |
| `write_page` | 一件事一页、按小节组织；各 `op` 的必填参数；替换与删除小节需要 `recall` 给出的短码；页面标识、别名、小节正文的格式；凭据检测提醒 |
| `write_recent` | 一条活动一行；各 `op` 的必填参数与长度；`replaces` 改写当天活动；`update_mainline` 需要版本短码；凭据检测提醒 |
| `write_persona` | 各 `op` 的必填参数；缺短码时会返回整份画像以取短码；四节的句式；长度与条数上限；凭据检测提醒；以及各 `op` 的使用条件（`add` 只在用户明确要求时、`propose` 用于观察到的偏好且不提议红线、`replace`/`delete` 只在用户要求时） |

`write_persona` 的使用条件属于策略，与服务端说明"写画像"一段重复；两处在不同时机出现，按第 2 节的原则保留。

## 6. 工具回复（契约）

- 成功时返回 Markdown 风格的纯文本，例如检索结果、写入后的短码与条数。
- 拒绝时标记为错误，分三段：`Refused`（原因，多条时逐行列出）、`Next step`（主会话可直接执行的动作）、`Related`（执行下一步所需的内容，例如当天的活动或整份画像及短码）。
- 同主题退回、候选并入、提议命中拒绝列表或画像都是正常结果，不标记错误，同样给出下一步该怎么做。
- 辅助模型不可用而跳过某项判断时，在回复末尾以 `Note:` 注明。

"下一步"是纠正调用错误的主要手段：Agent 用错参数或短码过期时，按它改正即可。

## 7. 记忆指令

`remember` 让主会话立即把本会话写进记忆：

- 开头：现在就写，不预先征求确认，除非某一步要求先问。
- 步骤：
  1. 按值得记标准回顾本会话；
  2. 写细节页前先检索，已有页面就按小节更新；
  3. 写一条活动，本会话已写过同一件事就用 `replaces` 改写；
  4. 只在方向变化时改主线；
  5. 画像：观察到的用 `propose`，用户明确要求的才 `add`，红线只由用户提出，与画像矛盾时先问；
  6. 写完列出写了什么：页面附页面标识，活动与画像条目附短码，候选附原文。
- 附带数据：今天的活动（附短码）与当前近期主线（附版本短码），供第 3、4 步直接使用。

步骤中混有操作名与参数名，策略与契约写在一起。`checkup` 的内容见 `docs/design.md` 第 9 节。

## 8. 判断问题

四项判断都是选择题：题干是新内容，每个已有候选是一个选项，另加一个"都不是"选项；要求只回答选项键。被判断的内容保持原文，不翻译；每个选项截至 250 字符。

| 判断 | 问题要决策模型分辨的 |
| :--- | :--- |
| 重复页 | 新页与同项目的某个已有页是否描述同一个问题、缺陷、决定或主题；只是同一产品区域或组件不算 |
| 同主题 | 新活动与当天某条已有活动是否是同一件事，包括它当天的推进、结果或后续；项目标注不作为依据，同一项目里的不同任务不算 |
| 画像冲突 | 新条目与某条已有画像条目（跨四节）是否冲突、重复或取代；相关但可以同时成立的不算 |
| 同一偏好 | 新提议与某个候选、拒绝列表项或画像条目是否是同一偏好或规则；同一话题下要求不同的、相反的偏好都不算 |

判断的三档处理与阈值见 `docs/design.md` 第 4 节。阈值是用这些问题实测出来的，问题措辞与阈值绑定。

## 9. 规则在各环节的分布

| 规则 | 会话开始可见 | 用到时可见 |
| :--- | :--- | :--- |
| 矛盾时以用户为准、先问 | 常驻区块外壳；服务端说明"写画像" | `remember` 第 5 步 |
| 只有用户明确要求才 `add`；红线只由用户提出 | 服务端说明"写画像" | `write_persona` 说明；`remember` 第 5 步 |
| 观察到的偏好用 `propose` | 服务端说明"写画像" | `write_persona` 说明；`remember` 第 5 步 |
| 先检索再写页面 | 服务端说明"写页面" | `remember` 第 2 步 |
| 照"下一步"处理拒绝 | 服务端说明"写页面" | 每一条拒绝回复 |
| 不写凭据 | — | 三个写入工具的说明；凭据检测的拒绝回复 |
| 短码从哪里取 | — | 工具说明；拒绝回复 |

"矛盾时以用户为准"在会话开始时出现在两处，按第 2 节的原则属于应当合并的重复。

## 10. 修改约定

- 给模型的文字一律英文（`docs/design.md` 第 11 节）。
- 措辞不由自动测试固定：自动测试只检查结构与长度上限（`docs/testing.md`）。
- 改动主会话看到的文字，以场景评测的前后对比为依据（`docs/testing.md` 第 4 节）。
- 改动判断问题须重新测定该判断的阈值。
- 新增文字先按第 2 节归类，再按放置原则选环节；放进服务端说明固定部分前先确认长度余量。
