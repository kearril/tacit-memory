# TacitMemory 记忆文件格式

记忆仓库里每种文件的写法。用户可以直接编辑这些文件，服务按这里的格式读写；格式不对时照常读取，问题在整理报告里列出。为什么这样存放见 `docs/design.md`「存储」。

## 1. 目录

```text
<记忆仓库>/
├── .gitignore              # 只含 .cache/
├── persona.md              # 画像
├── candidates.md           # 画像候选与拒绝列表
├── workstreams.md          # 主线：已成立的主线的背景说明与近期摘要
├── recent/YYYY-MM.md       # 活动记录（按月），末尾可有 ## Summary 节
├── pages/
│   ├── <主线>/<slug>.md    # 细节页，目录名即所属主线
│   └── _topics/<slug>.md   # 专题
└── .cache/                 # 派生索引，不进 Git
```

## 2. 通用写法

- 新建文件为 UTF-8 无 BOM、换行 LF，文件以换行结尾；修改已有文件时保留其原有的 BOM 与换行风格（含 CRLF）。列表项以 `- ` 开头，缩进两个空格。
- 日期一律 `YYYY-MM-DD`，按常驻服务所在机器的本地日期。
- 文件不写一级标题，从 `##` 开始分节；细节页标题只在 YAML 头的 `title` 中出现。
- 来源写在条目下一行的缩进 HTML 注释里：`<!-- 2026-10-25 quote「怎么又搜不到中文了」 -->`，原话可省略。活动记录的注释不写日期（由所在的日标题给出），写机器标记与原话：`<!-- on win-main quote「…」 -->`，两者可缺其一。
- 结构词（节名、`Belongs to: `、`quote`、`on` 等）一律英文，与记忆语言无关，所以不同语言的机器之间记忆格式相同；内容（条目、页面正文、自由取名的小节、原话）按记忆语言书写。结构词只认英文写法（大小写不限），写成其他语言的结构词当作普通内容。
- 所属主线名转为小写，只允许 `[a-z0-9._-]`；以下划线开头的名字保留给系统（如 `_topics`），以点开头的目录不算主线。

## 3. 条目与短码

| 文件 | 一条 |
| :--- | :--- |
| `persona.md` | 一个顶层列表项 |
| `workstreams.md` | 一个 `## Workstream` 节，每条主线一个三级标题及其背景说明、近期摘要两行；不设短码，由整理直接编辑 |
| `recent/YYYY-MM.md` | 日期标题下的一个列表项；`## Summary` 节中的一行汇总（不带短码） |
| `candidates.md` | 一个三级标题及其出现记录 |
| 细节页 | 一个小节，以"页面标识 + 小节名"指代 |

服务返回条目时附带短码（规范化文本哈希的前 6 位，例如 `a3f9c2`），后续调用凭短码引用；短码不写进文件。内容完全相同的条目按出现顺序加后缀（`a3f9c2-2`）。条目内容一改，旧短码即失效：拿旧短码替换或删除会被拒绝并返回最新内容。

## 4. 画像 `persona.md`

```markdown
## Red lines
- 不要自行发布版本或推送到公开仓库；改为先请用户确认（理由：影响外部，无法撤回）
  <!-- 2026-10-25 quote「发布前必须问我」 -->

## Working rules
- 需求不清时 → 先连续追问，确认后再给出完整方案
  <!-- 2026-10-20 quote「先问清楚再动手」 -->

## Preferences
- 沟通：先要结论，再看依据；反感客套和铺垫

## Profile
- 系统：Windows 11 x64，Shell 为 PowerShell 7
```

| 节 | 推荐句式 |
| :--- | :--- |
| `Red lines`（红线） | `不要 <行为>；改为 <替代做法>`，可加一句理由 |
| `Working rules`（协作规则） | `<情境>时 → <做法>`，只用肯定句，理由可选 |
| `Preferences`（偏好） | `<维度>：<描述>`，描述句，可写"不喜欢……" |
| `Profile`（档案） | `<字段>：<事实>`，不写行为要求 |

句式是写作建议，由记忆 skill 引导；服务不校验，写入时不拒绝，整理报告也不列出。

- 每条一行，一条只写一个情境和一个做法；不使用大写强调词。简洁靠句式与好坏对照引导，写入不设字数与条数上限，过长的条目由整理报告的篇幅提示列出，由用户决定是否精简。
- 修改逐条进行，不整篇重写；被取代的条目直接替换，历史由 Git 保留。

### 作用域

前四节只放全局条目。领域与主线条目放在其后的作用域块中，每个作用域一个二级标题，块内按四节分三级标题，句式与上限相同：

```markdown
## Domain: network-proxy
Trigger: 改代理、分流或测速时
### Working rules
- 性能/节点比较 → 不拿单次测速当日常结论
  <!-- 2026-11-06 quote「……」 -->

## Workstream: photo-sorter
### Working rules
- 发版 → 先跑全量测试
```

- 块标题与触发行为 `## Domain: <标签>`、`Trigger: <一行>`、`## Workstream: <名>`。
- 领域标签与主线名同一套命名规则（`[a-z0-9._-]`，不以 `.` 或 `_` 开头）；触发描述为一行，不设长度上限。
- 块的顺序：全局四节之后，领域块在前、主线块在后，各自按名称排序。写入新块时按此顺序放置；块缺失时补回，块内缺少的节按四节标准顺序补回块内。
- 领域的规则可以来自用户偏好，也可以来自排错教训，只要它只在该情境下成立。

## 5. 画像候选 `candidates.md`

```markdown
## Candidates

### 沟通：先要结论，再看依据
Belongs to: Preferences
- 2026-10-28 quote「先说结论」
- 2026-10-30 quote「别铺垫，直接说结果」

## Rejection list

### 每次提交前都运行全量测试
Belongs to: Working rules
- 2026-10-27 quote「跑一下全部测试」
- 2026-10-29 rejected quote「不用，只跑相关的」
```

- 三级标题即确认后写进画像的条目原文；出现天数按不同日期计数，只作整理时的参考。
- 归属行之后可有一行 `Scope: domain:<标签>` 或 `Scope: workstream:<名>`，缺省为全局；拒绝列表的条目同样。作用域行的值不合规时记为格式问题，该候选按全局处理。
- 候选全部作为整理时的证据，没有出现天数门槛；确认后移入 `persona.md`，作用域随之进入对应的作用域块。
- 拒绝列表永久有效；用户改主意时可直接要求写入画像。
- 提议写入候选时的标题补回与出现记录追加规则见 `docs/design.md`「写入」。

## 6. 主线 `workstreams.md`

```markdown
## Workstream
### home-server
Background: 家里的常驻服务器，跑自用服务。
Recent: 服务栈搭完后在收敛，砍掉不常用的。
```

每条主线一个三级标题（名字即主线名，规则同上），其后两行：背景说明（必填，写这件事是什么，基本不变）与近期摘要（可缺，写近期处在什么阶段、往哪走，不罗列做了哪些）。文件中有条目的名字才是已成立的主线；由用户确认后由整理直接编辑该文件，数量不设上限。活动比近期摘要新，两者不一致时以活动为准。

## 7. 活动记录 `recent/YYYY-MM.md`

```markdown
## 2026-10-31
- [tacit-memory] 决策模型定为只做判断，去重与修正交给整理
  <!-- on win-main quote「其实可以直接把记忆库当成主线」 -->
- 想清楚了画像里缺的是人的倾向，而不只是规范
  <!-- on win-main -->
```

每天一个二级标题，按写入顺序排列；属于主线的活动以 `[主线名]` 开头。长度与写法见 `docs/design.md`「写入」。

条目下的注释由服务写入，`on` 后是写入（或最后改写）这条活动的机器名；更早写下、没有机器标记的活动照常读取。机器标记不参与短码。`on` 后的名字不是合规的机器名时，整理报告列为格式问题。

月文件末尾可有一节 `## Summary`，由整理时的主会话直接编辑写入，每行一条汇总：

```markdown
## Summary
- 2026-W45：本周整理了画像与记忆结构
- 2026-11：十一月主要在做记忆重设计
```

- 周汇总形如 `- 2026-W45：<一行>`，周按 ISO 周计（周一至周日），写在该周周四所在月份的文件里；月汇总形如 `- 2026-11：<一行>`，按自然月计，写在该月的文件里。
- 汇总节不是活动：其中的行不在日期标题下，不取短码，不参与同主题判断与"最近 7 天"的活动列表，也不能被 `replaces` 指向。
- 新活动仍写在当天的日期标题下；当天还没有标题时，标题写在汇总节之前，汇总节保持在文件末尾。
- 无法识别的行、不存在的周号或月份、写错文件的周或月，列入整理报告的格式问题，服务照常读取其余内容。

## 8. 细节页

```markdown
---
title: 数据库升级后扩展丢失
aliases: [全文检索插件失效, 升级后搜索不到中文]
dates: { first: 2026-10-21, last: 2026-10-25 }
related: [my-app/backup-script, _topics/pgroonga]
type: incident
---

## 现象
……

## 根因
……
```

| 字段 | 规则 | 由谁写 |
| :--- | :--- | :--- |
| `title` | 必填，不限长度 | 主会话 |
| `aliases` | 至少 2 个，不限长度；覆盖口语说法、中英文名与别称 | 主会话；可追加 |
| `dates` | 首次与最近一次经服务写入的日期 | 服务 |
| `related` | 其他页的页面标识；指向不存在的页时经服务写入被拒绝 | 主会话 |
| `type` | 必填，取值 `incident`（排错）、`decision`（决定）、`entity`（实体）、`work`（工作单元）之一；经服务新建时必须给出，`update_header` 可改 | 主会话 |

- 页面标识为 `<所属主线>/<slug>`，slug 匹配 `^[a-z0-9]+(-[a-z0-9]+)*$`，在主线内唯一，创建后不可改名。
- 正文按 `##` 小节组织，小节名由主会话决定、按记忆语言书写，页内不得重名。服务只识别三个约定的小节，小节名必须是英文：`work` 页的 `Leftovers`（遗留）、`decision` 页的 `Overturned`（推翻记录）、`incident` 页的 `Lesson`（教训）。写成其他语言的同名小节只是普通小节。
- 每种类型的推荐小节与示例写在记忆 skill 中，服务不校验小节名。

## 9. Git

- 首次初始化：`git init`，写入 `.gitignore`、各文件的节标题骨架与 `recent/`、`pages/` 下的 `.gitkeep`，提交 `init: create memory repo`。目录非空且不是 Git 仓库时拒绝初始化。
- 再次执行 `init` 不覆盖任何已有文件：记忆目录已是 Git 仓库时只补缺失的骨架文件，不提交，并列出已存在的文件。传入的 `--language` 或 `--memory` 与已有 `config.yaml` 不一致时拒绝执行。
- 每次经服务的写入自动提交一次，只提交本次写入的文件，作者固定为 `tacit <tacit@localhost>`。提交信息为 `<区域>: <动作> <对象>`，区域为 `persona`、`candidates`、`recent`、`pages` 之一，例如 `pages: create tacit-memory/db-upgrade`。
- 要写的文件含有用户未提交的修改时，连同修改一起提交，并在提交信息末尾注明。
- 提交失败时文件照样写入：通知用户，工具结果标为错误并说明下次写这个文件时一并提交；索引同步、向量补齐、自动备份与常驻区块的重渲染照常进行，与提交成功时相同。
- 整理的提交由主会话完成，提交信息以 `consolidate:` 开头；服务据此识别上次整理的时间。

## 10. 格式不对时

服务修改文件时只定位并改动要改的那几行，其余内容原样保留。格式不符合约定时照常解析；问题不在写入或索引同步时记录，而是生成整理报告时把全部记忆文件重新解析一遍当场得出（见 `docs/design.md`「整理」），修正后下次生成报告即消失。下表是各类情况的解析处理，问题本身的检查项见 `docs/design.md`「整理」：

| 情况 | 处理 |
| :--- | :--- |
| 细节页 YAML 头无法解析 | 照样建索引，`title` 取文件名 |
| 无法识别的节或内容 | 照样计数与渲染 |
| 某节条目过多或过长 | 照样全部渲染与写入，不设上限；整理报告的篇幅提示列出过长的条目 |
| 细节页缺少 `type` 或取值无效 | 照样建索引、检索与读取；整理报告的格式问题中列出，不受整理基准限制 |
| 日期格式错误 | 该条不参与基于日期的计算 |
| 文件不是 UTF-8 | 跳过该文件，在服务端说明中提示 |
| 活动记录中不在日期标题下的条目、无法识别的日期标题 | 不建索引、不计入最近 7 天的活动，其余活动照常 |
| 画像、候选文件、活动记录与主线文件的格式问题 | 照常解析与渲染，问题只在整理报告中列出，写入路径与索引不使用；主线文件中有问题的条目不算已成立的主线 |
